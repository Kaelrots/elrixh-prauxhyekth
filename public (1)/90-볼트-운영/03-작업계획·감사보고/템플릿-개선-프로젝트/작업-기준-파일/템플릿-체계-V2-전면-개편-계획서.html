2. 전체 개편 원칙

2.1. 시각적 문법은 유지한다

다음 요소는 삭제 대상으로 간주하지 않는다.

<, ^, <span>, <center>, <br>, <hr class="hr-thick-*">

이들은 인간 사용자에게 필요한 문서 표현 체계다.

단, 의미 없는 중첩이나 동일 효과를 위해 불필요하게 반복된 HTML은 정리할 수 있다.

AI Agent의 해석 문제는 템플릿 구조를 훼손해서 해결하지 않고 DRAFT-AI_AGENT_INSTRUCTIONS.md의 공통 지침으로 해결한다.

3. 00-yaml 속성탭.md

판단

전면 수정 및 공통 스키마 원본으로 승격한다.

현재 여러 템플릿에 사실상 동일한 Frontmatter가 개별 복사되어 있어 향후 필드 하나를 변경할 때 전체 파일을 수정해야 한다.

V2에서는 이 파일을 공통 Frontmatter 설계의 실사용 기준으로 만든다.

주요 변경

  • 템플릿 공통 프론트매터 V2 개편 설계안 적용
  • 스키마버전 추가
  • 작성상태 추가
  • 검토상태 추가
  • 세부유형 추가
  • 별칭 추가
  • 복원여부 폐지
  • 제목 자동 태그 생성 폐지
  • 기원상태를 복원 여부의 단일 기준으로 사용
  • 버전 표기를 문자열로 통일

이 파일과 실제 템플릿들의 Frontmatter 내용이 서로 달라지는 현상을 방지해야 한다.

4. 00-복원문서주의사항.md

판단

유지하되 대폭 단순화한다.

현재 기원상태와 복원여부를 동시에 검사하는 복잡한 조건문이 들어가 있다.

V2에서는 다음 하나만 기준으로 삼는다.

보완 방향

복원 문서라는 사실과 현재 정본 여부를 혼동하지 않도록 안내문도 개정한다.

복원 문서는 반드시 구식이라는 의미가 아니다.

따라서 안내문의 의미를 다음처럼 나눈다.

  • 이 문서는 과거 자료에서 복원됨.
  • 현재 정합성 검토 여부는 검토상태 확인.
  • 현재 정본 여부는 정본상태 확인.

5. 00-편집 앵커.md

판단

유지한다.

이는 설정 데이터가 아니라 작성자의 작업 진행 위치를 시각적으로 표시하는 편집 보조 기능이다.

수정 방향

현재 기능과 미감을 가능한 한 유지한다.

단, AI Agent 공통 지침에서 다음과 같이 규정한다.

편집 앵커는 작업 상태 표시이며 세계관 설정 내용 또는 정본 데이터가 아니다.

필요하다면 추후 CSS Class를 부여하여 Publish 시 숨기는 방식도 검토할 수 있다.

6. 00-최종수정일 갱신 템플릿.md

판단

기능 유지, 구현 공통화.

현재 동일한 DataviewJS가 거의 모든 템플릿에 복사되어 있다.

이는 문서 작성에는 편리하지만 유지보수에는 불리하다.

개편 방향

가능하면 하나의 공통 컴포넌트 또는 User Script를 호출하도록 변경한다.

단, 실제 Templater/Dataview 환경에서 공통 호출이 현재 방식보다 불안정하다면 기존 복사 방식을 유지한다.

즉 코드 중복 제거는 기능 안정성보다 후순위로 둔다.

7. 01-01-국가 설정 템플릿.md

현황

현재 약 900줄 규모이며 국가 설정에 들어갈 수 있는 거의 모든 항목을 한 문서에 수용한다.

정보 누락 방지에는 강하지만 다음 문제가 있다.

  • 신규 국가 작성 시작 비용이 매우 높음.
  • 중요 설정과 선택적 세부 설정의 위계가 약함.
  • 다른 전용 문서와 역할이 중복됨.
  • 정책·기관·법제 등을 국가 템플릿이 다시 상세하게 다룸.
  • 거대한 선택표가 국가별 실데이터보다 분류표의 역할을 수행하는 경우가 있음.

판단

기존 데이터 항목은 보존하되 구조를 대규모 재설계한다.

8. 역사 템플릿 계열

02-역사 설정 템플릿.md

현재 일반 역사 템플릿은 상대적으로 단순하지만 사건의 신뢰도와 불확실성을 구조적으로 표현하기 어렵다.

02-역사 설정 템플릿 (제1기·간략).md

이 템플릿에 도입된 다음 요소는 V2 역사 템플릿에 적극 승계한다.

  • 행위자 구조
  • 사건 요약
  • 검색 키워드
  • 자료 신뢰성
  • 근거 유형
  • 확정 서술과 추정 서술 구분

이는 특히 사료 소실·전승·복원 기록이 많은 세계관에 유용하다.

최종 방향

두 설계를 통합하여 하나의 표준 역사 사건 템플릿을 만든다.

reliability 구조는 제1기에만 적용되는 특수 규칙이 아니라 모든 역사 사건에서 선택적으로 사용할 수 있도록 한다.

02-역사 설정 템플릿 (제1기·간략) 복붙용.md

독립된 전체 템플릿으로 유지할 필요는 낮다.

권고

표준 역사 템플릿의 제1기 Preset으로 축소한다.

제1기 Preset은 다음 기본값만 제공한다.

  • 복원 자료 여부
  • 권장 신뢰도 서술 방식
  • 전승/추정 기록 안내
  • 제1기 태그

본문 전체를 별도로 복제하지 않는다.

현재 존재하는 [[#본문-서술|본문 서술]] 링크와 실제 헤딩의 불일치도 이 과정에서 제거한다.

  • 차원·신비 응용
  • 특정 규제
  • 악용 시나리오

핵심 기술과 일반 기술의 문서 밀도를 다르게 가져갈 수 있게 한다.

27. 유저 스크립트/

판단

템플릿이 아니라 템플릿을 지원하는 실행 자산이다.

장기적으로는 공통 컴포넌트 또는 자동화 영역으로 분리하는 편이 구조상 자연스럽다.

다만 현재 Templater가 해당 경로를 직접 참조하고 있을 가능성이 있으므로 경로 확인 전에는 이동하지 않는다.

먼저 다음을 확인한다.

  • Templater User Script Folder 설정
  • 템플릿 내부의 tp.user.* 호출
  • BAT/JS 자동화에서 해당 경로 참조 여부

확인 후 안전할 경우 운영자산 영역으로 분리한다.

28. 신규 공통 개념: Core와 Module

V2 템플릿은 가능한 한 두 층으로 설계한다.

Core

해당 설정 문서가 성립하기 위해 반드시 필요한 내용이다.

예를 들어 인물이라면 이름·생몰·역할 정도다.

Module

필요할 때만 사용하는 상세 영역이다.

예를 들어 인물의 무장·학력·복장·연애관계 등이 이에 해당한다.

다만 실제 파일을 수십 개의 작은 템플릿으로 쪼갤 필요는 없다.

본문 내부의 선택 섹션으로 구현할 수 있으며, 반복 유지보수 필요성이 큰 경우에만 실제 파일로 분리승격한다.

29. 템플릿에서 표를 사용하는 기준

거대한 표라는 이유만으로 삭제하지 않는다.

다음 기준으로 판단한다.

유지

  • 여러 설정을 한눈에 비교할 수 있음
  • 시각적으로 구조가 명확함
  • 반복 입력이 실제 작업에 도움이 됨
  • 병합표가 의미 구조를 잘 표현함

축소 또는 재설계

  • 대부분의 셀이 항상 비어 있음
  • 단순한 분류표를 모든 설정 문서에 반복 삽입함
  • 하나의 실제 값을 입력하기 위해 지나치게 큰 표를 사용함
  • 동일 데이터가 여러 표에 중복됨

즉 <와 ^를 없애는 것이 아니라 표가 실제 문서에서 수행하는 역할을 검토한다.

30. 예시값 처리

현행 템플릿에는 ex.가 포함된 예제가 다수 존재한다.

V2에서도 예시는 유지할 수 있다.

단 AI Agent가 이를 실제 정본 데이터로 오인하지 않도록 공통 지침에 다음 규칙을 둔다.

ex., 예:, {예시}, {{placeholder}} 등은 작성 안내용 예시이며 실제 세계관 설정으로 간주하지 않는다.

가능하면 Placeholder 문법도 템플릿 전체에서 통일한다.

권장 방식은 다음 중 하나로 정한 뒤 혼용을 줄인다.

31. AI Agent README와의 연결

모든 템플릿에 AI용 설명을 반복 삽입하지 않는다.

볼트 최상위에 별도로 둘 예정인 다음 문서를 기준으로 한다.

여기에는 최소한 다음 해석 규칙을 둔다.

  • <와 ^의 표 병합 의미
  • HTML 표현 요소
  • hr-thick 구분선
  • Templater
  • Dataview 및 DataviewJS
  • Callout
  • 위키링크
  • 임베드
  • 예시값
  • 빈 값
  • 정본 상태
  • 보존 문서
  • 복원 문서
  • V1/V2 Frontmatter 차이
  • 수정 시 기존 시각 구조 보존 원칙

이를 통해 템플릿에는 실제 설정 작성에 필요한 내용만 남긴다.

32. 권장 작업 순서

Phase 0 — 기반 규격

  1. 공통 Frontmatter V2 확정
  2. AI Agent 공통 지침 확정
  3. 상태값 및 문서유형 사전 확정
  4. V1 호환 규칙 확정

Phase 1 — 공통 기반 및 현재 부실 템플릿

우선 다음을 처리한다.

  • 00-yaml 속성탭
  • 90-기타 문서 기본
  • 07-01-헌법
  • 08-국가 정책
  • 09-기관
  • 종족 설정

이들은 다른 작업에 영향을 주는 기반이거나 현재 전용 구조가 부족하다.

Phase 2 — 대형 템플릿

다음으로 작성비용이 큰 템플릿을 개편한다.

  • 국가
  • 인물
  • 지역
  • 종교
  • 자원

기존 정보 항목을 최대한 보존하면서 Core/Module 구조로 바꾼다.

Phase 3 — 역사·법제·기술

이미 좋은 구조가 상당 부분 만들어진 계열을 V2 표준에 맞춘다.

  • 역사
  • 법률
  • 황제령
  • 기술·연구

이 단계에서는 새 설계보다 기존 좋은 구조의 표준화가 중심이다.

Phase 4 — 운영자산 정리

마지막으로 다음을 정리한다.

  • 피드백 양식
  • 유저 스크립트
  • 편집 앵커
  • 수정일 버튼
  • 레거시 템플릿

경로 변경으로 기존 자동화가 깨지지 않는지를 검증한 뒤 이동한다.

33. 레거시 처리

V2 템플릿이 완성되었다고 해서 V1 파일을 즉시 삭제하지 않는다.

개편 전 원본은 일정 기간 보존한다.

권장 방식:

해당 폴더는 실제 신규 문서 생성 대상에서는 제외한다.

V2 안정화와 실제 문서 생성 테스트가 완료된 이후 최종 보존 위치를 결정한다.

34. 완료 조건

템플릿 개편은 단순히 파일을 새로 작성했다고 완료된 것으로 보지 않는다.

다음 조건을 충족해야 한다.

  • 모든 핵심 템플릿이 V2 Frontmatter를 사용
  • 동일 의미의 Frontmatter 키가 통일됨
  • 국가·인물 등 대형 템플릿의 초기 작성 부담 감소
  • 기존 정보 항목의 의미 있는 손실 없음
  • 인간용 표·HTML 시각 구조 정상 유지
  • AI Agent가 병합표와 HTML을 올바르게 해석할 지침 존재
  • 복원·정본·작성·검토 상태를 서로 구분 가능
  • 기술계열 ID·관계 구조 정상 유지
  • Dataview/Templater 기능 정상 작동
  • Quartz/웹 퍼블리시 시 깨지는 구조 없음
  • 기존 V1 문서와 V2 문서가 일정 기간 공존 가능
  • 레거시 템플릿이 신규 작성에 실수로 사용되지 않음

35. 최종 목표

이번 개편의 목표는 템플릿을 단순하게 만드는 것 자체가 아니다.

최종적으로 다음 구조를 만든다.

사람은 보기 좋고 빠르게 작성할 수 있다.

문서는 필요한 경우 매우 깊은 설정까지 확장할 수 있다.

AI Agent는 문서의 상태·종류·관계·확정도를 일관되게 파악한다.

기존 Obsidian의 시각적 표현과 세계관 문서의 미감은 보존한다.

한 번 정의한 공통 규칙을 모든 템플릿에 반복 복사하지 않는다.

즉 V2는 기존 템플릿의 정보를 버리는 작업이 아니라, 지난 수년간 누적된 템플릿의 장점을 현재의 작성 방식과 AI Agent 협업 방식에 맞게 재구조화하는 작업으로 정의한다.
