템플릿 공통 프론트매터 V2 개편 설계안

문서 목적

《엘리스 프라우셰크트》 세계관 볼트의 각종 설정 템플릿이 공통적으로 사용하는 YAML Frontmatter를 재정비한다.

본 개편의 목적은 다음 세 가지를 동시에 충족하는 것이다.

  1. 작성자가 Obsidian에서 직접 작성·관리하기 쉬울 것.
  2. Dataview·Templater 등 기존 Obsidian 자동화와 호환될 것.
  3. ChatGPT Work, Codex 및 기타 AI Agent가 문서의 종류·상태·정본성·완성도를 일관되게 해석할 수 있을 것.

1. 개편 기본 원칙

1.1. 인간 작성성을 우선한다

Frontmatter는 데이터베이스를 흉내 내기 위해 과도하게 복잡해져서는 안 된다.

설정 자체의 세부 내용은 본문에 작성하고, Frontmatter에는 다음 정보만 기록한다.

  • 문서의 식별
  • 문서의 분류
  • 문서의 상태
  • 템플릿 및 스키마 버전
  • 검색·필터링에 필요한 최소 메타데이터
  • 복원 문서의 출처 정보

정치체제, 인구, 능력, 교리, 자원량 등 개별 설정 데이터는 원칙적으로 본문에서 관리한다.

1.2. 시각 표현과 의미 구조를 분리한다

본문에서 사용하는 다음 표현은 인간의 시인성과 미감을 위한 정식 문법으로 인정하고 유지한다.

  • 표의 <
  • 표의 ^
  • <span>
  • <center>
  • <br>
  • <hr class="hr-thick-*">
  • 기타 현재 볼트에서 사용 중인 시각적 HTML

AI Agent가 이를 올바르게 해석하는 방법은 각 템플릿에 반복 기재하지 않고, 향후 볼트 최상위의 DRAFT-AI_AGENT_INSTRUCTIONS.md에서 공통적으로 정의한다.

따라서 템플릿 V2 개편은 AI를 위해 사람용 시각 구조를 제거하는 방식으로 진행하지 않는다.

1.3. 상태값을 서로 다른 축으로 분리한다

현행 정본상태만으로는 다음 상태를 구분하기 어렵다.

  • 아직 내용을 거의 작성하지 않은 문서
  • 작성은 끝났으나 검토하지 않은 문서
  • 내용은 완성되었으나 정본으로 확정되지 않은 문서
  • 정본이지만 향후 추가 작성이 가능한 문서

이에 따라 다음 세 축을 별도로 관리한다.

구분역할
`정본상태`세계관 설정으로서의 권위
`작성상태`문서 자체의 작성 완성도
`검토상태`정합성·내용 검토 진행도

2. V2 공통 Frontmatter 표준안

이 블록을 모든 V2 템플릿의 공통 기반으로 사용한다.

템플릿별 특수 속성은 이 공통부 아래에 추가한다.

3. 공통 속성 정의

3.1. 식별 관련

속성용도형식
`제목`실제 문서명자동 입력
`별칭`약칭·구칭·다른 언어 표기 등YAML List
`작성자`문서 작성자문자열
`최초작성일`현재 문서의 생성 시점ISO 계열 날짜
`최종수정일`현재 문서의 최종 수정 시점ISO 계열 날짜

별칭 신설

현재 일부 문서는 제목 자체를 태그로 자동 등록하고 있다.

V2에서는 문서명·약칭·통칭·과거 명칭 등을 태그로 처리하지 않고 별칭과 본문 명칭표에서 관리하는 것을 원칙으로 한다.

태그는 검색 분류 체계에 사용한다.

4. 버전 관련

4.1. 문서버전

해당 설정 문서 자체의 개정 버전이다.

가능한 한 Semantic Versioning 형태를 사용한다.

  • Patch: 표현 수정, 오탈자 수정 등
  • Minor: 설정 추가·보완
  • Major: 설정 구조 또는 전제의 대규모 변경

엄격한 소프트웨어식 SemVer를 강제하는 것은 아니며, 변화의 규모를 구분하기 위한 용도로 사용한다.

4.2. 스키마버전

해당 문서가 따르는 공통 메타데이터 구조의 버전이다.

이를 통해 AI Agent와 자동화 도구가 V1 문서와 V2 문서를 구분할 수 있다.

4.3. 템플릿 버전

현재 문서가 처음 생성될 때 사용한 템플릿의 버전이다.

템플릿이 나중에 V2.1로 변경되더라도 기존 문서의 값은 자동으로 변경하지 않는다.

5. 문서 분류 체계

5.1. 문서유형

볼트 전체에서 통용되는 상위 문서 구조를 나타낸다.

권장 값은 다음과 같다.

값의미
`entity`국가·인물·기관·지역·종족·자원 등 독립 개체
`concept`사상·개념·이론 등
`event`역사 사건
`period`시대·기간
`index`인덱스 및 목록
`reference`설명·참고·규칙 성격의 문서
`rule`볼트 운영 또는 세계관 규칙
`ledger`관계 원장·레지스트리 등
`template`템플릿 자체

5.2. 세부유형

기존 기술 템플릿에서 사용하는 doc_type의 장점을 볼트 전체로 확장한다.

예:

권장 세부유형 예시는 다음과 같다.

대상세부유형
국가`nation`
인물`person`
종교`religion`
사상`ideology`
지역`region`
기관`institution`
정책`policy`
헌법`constitution`
법률`law`
황제령`imperial_decree`
역사 사건`historical_event`
자원`resource`
종족`species`
기술 시대 인덱스`era_gate_index`
기술 게이트`gate_node`
기술 관계 원장`gate_edges`
상세 기술`tech_detail`

V2 전환 시 기존 doc_type은 세부유형으로 통합하는 것을 원칙으로 한다.

단, 기존 자동화가 doc_type을 실제로 참조하고 있다면 자동화 수정이 완료될 때까지 병행 유지할 수 있다.

6. 상태 체계

6.1. 정본상태

현행 체계를 유지한다.

허용값:

  • canon
  • provisional
  • draft
  • archival

의미

canon

현재 정본으로 인정되는 설정.

provisional

잠정 승인 상태. 정본 후보이나 후속 검토 또는 조정 가능성이 존재한다.

draft

작성·논의 중이며 정본으로 확정되지 않았다.

archival

현재 정본으로 사용하지 않는 역사적·보존용 문서.

6.2. 작성상태

신설한다.

허용값:

  • outline
  • partial
  • complete

의미

outline

골격 또는 일부 항목만 존재한다.

partial

실질적인 내용이 작성되어 있으나 아직 주요 부분이 비어 있다.

complete

현재 템플릿 기준으로 필요한 주요 내용을 모두 작성했다.

complete는 정본 확정을 의미하지 않는다.

6.3. 검토상태

신설한다.

허용값:

  • unreviewed
  • reviewing
  • reviewed

의미

unreviewed

정합성 검토를 거치지 않았다.

reviewing

현재 검토 중이다.

reviewed

현재 설정 및 관련 문서와의 정합성 검토를 완료했다.

7. 정본상태·작성상태·검토상태의 관계

세 속성은 독립적으로 사용한다.

예:

이는 다음을 의미한다.

현재 작성되어 있는 내용은 정본으로 확정되었고 검토도 완료했지만, 문서 자체에는 앞으로 추가 작성해야 할 영역이 남아 있다.

반대로 다음도 가능하다.

즉 문서는 완성되고 검토까지 끝났지만 설정 자체는 잠정안일 수 있다.

이 분리는 AI Agent가 문서의 실제 상태를 오판하지 않도록 하는 데 특히 중요하다.

8. 복원 문서 관련 개편

현재 다음 정보가 중복 사용되고 있다.

V2에서는 기원상태를 유일한 기준으로 사용한다.

또는

따라서 신규 V2 템플릿에서는 복원여부를 제거한다.

기존 V1 문서와의 호환성을 위하여 AI Agent 및 변환 자동화에서는 다음과 같이 해석한다.

  1. 기원상태가 존재하면 이를 우선한다.
  2. 기원상태가 없고 복원여부: true이면 restored로 취급한다.
  3. 양쪽 모두 없으면 original로 취급한다.

9. 복원 출처 정보

다음 세 필드는 유지한다.

다만 일반 문서에서는 빈 값으로 둔다.

복원 문서에만 실제 값을 기록한다.

이를 통해 모든 템플릿이 동일한 스키마를 유지하면서도 조건부 해석이 가능하다.

10. 태그 체계

현재 일부 템플릿에서는 문서 제목을 자동으로 태그에 삽입한다.

V2에서는 이를 중단한다.

기존:

개편:

문서의 명칭 자체는 제목 및 별칭에서 관리한다.

태그는 다음과 같은 분류 정보에 집중한다.

  • 문서 영역
  • 핵심 주제
  • 검색용 분류
  • 시대·지역 등 필요한 상위 카테고리

11. 분야와 적용범위

분야

문서가 어떤 설정 영역에 속하는지를 나타낸다.

복수 값 사용을 기본으로 한다.

적용범위

특정 국가, 시대, 행성, 차원 등에만 적용되는 규칙 또는 설정의 범위를 기록한다.

적용범위를 특정하기 어려운 경우 빈 목록을 유지한다.

12. 최근 변경 요약

항상 문자열로 정의한다.

내용이 존재할 경우 다음처럼 작성한다.

긴 변경 내역은 별도의 수정기록 문서를 사용하며, Frontmatter에는 1문장 요약만 둔다.

13. 유형별 확장 속성

공통 Frontmatter 이후 각 템플릿에 필요한 속성을 추가할 수 있다.

예를 들어 기술 게이트:

역사 사건:

단, 유형별 확장 속성은 다음 원칙을 따른다.

  • 다른 유형에서는 의미가 없는 필드를 공통부에 추가하지 않는다.
  • 본문에서 충분히 표현할 수 있는 장문의 설정을 YAML로 옮기지 않는다.
  • 관계·ID·검색·분류에 직접 도움이 되는 값만 우선한다.

14. 템플릿 내 Templater 처리 원칙

V1 템플릿에는 다음과 같이 복잡한 조건식이 반복된다.

V2 신규 템플릿에서는 원칙적으로 다음 하나만 사용한다.

V1 호환 처리는 개별 템플릿이 아니라 변환·점검 자동화 또는 AI Agent 지침에서 담당한다.

이를 통해 템플릿 자체의 코드량을 줄인다.

15. 작성/수정일 DataviewJS 처리

현재 여러 템플릿에 동일한 최종수정일 갱신하기 DataviewJS가 반복 삽입되어 있다.

기능 자체는 유지한다.

다만 V2에서는 가능한 경우 다음 구조로 변경한다.

공통 컴포넌트 또는 User Script 1개
→ 각 템플릿은 해당 기능을 호출
→ 동일한 JS 전체를 모든 템플릿에 반복 복사하지 않음

이는 사람용 기능을 제거하기 위한 것이 아니라 유지보수 지점을 하나로 줄이기 위한 조치다.

실제 구현 방식은 기존 Templater 및 Dataview 설정을 확인한 뒤 결정한다.

16. AI Agent 해석 규칙과의 역할 분담

Frontmatter에는 AI 전용 장문의 지시를 포함하지 않는다.

향후 볼트 최상위의 다음 문서를 AI 해석 규칙의 단일 기준으로 사용한다.

DRAFT-AI_AGENT_INSTRUCTIONS.md

해당 문서는 최소한 다음 사항을 규정한다.

  • < 및 ^ 표 병합 문법
  • <span>, <center>, <br> 등 HTML의 처리
  • <hr class="hr-thick-*">의 의미
  • Templater 코드와 실제 설정 정보의 구분
  • DataviewJS의 처리
  • 빈 셀과 없음의 차이
  • 예시값과 실제 설정값의 차이
  • 정본상태 우선순위
  • 보존·구식 문서 처리
  • 복원 문서 처리
  • 위키링크 및 임베드 처리
  • 충돌 문서 발견 시 임의 합성 금지
  • AI에 의한 시각적 마크업 임의 삭제 금지

즉,

Frontmatter는 문서 상태와 구조를 기술하고, AI Agent README는 볼트 문법을 설명한다.

두 역할을 분리한다.

17. V1 → V2 호환 정책

전체 문서를 한 번에 강제로 변환하지 않는다.

1단계

신규 V2 템플릿 확정.

2단계

앞으로 새로 생성되는 문서는 V2 적용.

3단계

기존 핵심 정본 문서부터 순차적으로 V2 전환.

4단계

구형 문서와 보존 문서는 필요할 때만 변환.

archival 문서에는 V2 변환을 강제하지 않는다.

18. V2 전환 시 자동 점검 항목

각 템플릿은 최소한 다음 사항을 검사한다.

  • 스키마버전 존재
  • 문서버전 문자열 형식
  • 템플릿 버전 존재
  • 정본상태 허용값 사용
  • 작성상태 허용값 사용
  • 검토상태 허용값 사용
  • 문서유형 존재
  • 세부유형 존재
  • 태그와 분야가 List 형식인지 확인
  • tag와 태그 등 오탈자·혼용 여부
  • 복원여부 신규 생성 금지
  • restored 문서의 복원 원문 정보 존재 여부
  • 동일 의미 필드 중복 여부

19. 최종 권장 구조

V2의 기본 철학은 다음과 같이 정리한다.

Human-first Presentation

사람이 직접 읽고 작성할 때의 가독성과 미감을 우선한다.

Structured Metadata

AI Agent와 자동화가 문서의 종류와 상태를 안정적으로 판단할 수 있는 최소 구조를 제공한다.

Shared Agent Protocol

인간용 Markdown·HTML 표현을 삭제하지 않고, AI가 그것을 올바르게 해석하도록 공통 지침을 제공한다.

이를 통해 사람용 문서와 AI용 문서를 별도로 이중 관리하지 않고, 하나의 Obsidian Markdown 문서를 양쪽이 공동으로 사용할 수 있도록 한다.
