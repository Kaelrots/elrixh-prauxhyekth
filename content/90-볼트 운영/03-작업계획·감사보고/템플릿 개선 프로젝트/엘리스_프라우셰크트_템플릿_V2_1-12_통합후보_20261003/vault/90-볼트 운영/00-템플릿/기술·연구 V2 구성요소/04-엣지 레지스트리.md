## 적용 범위와 분기

시대 내부 원장은 from_era == to_era == 대상 시대다. 교차시대는 from_era != to_era를 허용한다. 기존 `2-00(교차시대)`·10-03-2-00 등은 원장 분류 예시이며 실제 노드의 시대나 gate_id로 발급하지 않는다. 권장 분기 필드는 기존 호환 안내용이다.

edge_id는 원장에서 확정한 고정 관계 ID다. 기존 관계를 이관할 때 자동 재발급하지 않는다. from_gate·to_gate는 gate_id만 사용한다. source는 근거 문서이며 출발 ID가 아니다. valid_era는 관계가 유효한 시대·범위이며 양끝 노드의 시대와 다르다.

weight는 선택값 0.0~1.0이다. 1.0(거의 필수)·0.6(강한 권장)·0.3(느슨한 연계)은 기존 척도의 예시이며 기본값이 아니다. weight로 rel_type을 자동 변경하지 않는다.

status는 candidate·active·deprecated로 기록한다. 확인 전 active를 기본 선택하지 않는다. 폐기는 삭제 대신 deprecated와 사유를 남긴다. 교차시대 관계에는 note에 점프 이유를 한 줄 이상 적고 source로 근거를 연결한다.

## 품질 점검

- [ ] 중복·미존재 gate_id, 중복 edge_id, 자기참조가 없다.
- [ ] rel_type이 사전에 있고 alt_path와 mutex가 구별된다.
- [ ] from_era·to_era가 실제 노드 시대와 일치한다.
- [ ] 교차시대 관계에 note·근거가 있다.
- [ ] active 관계에 폐기 노드가 연결되어 있지 않다.
- [ ] prereq_hard와 prereq_soft의 의도치 않은 순환을 확인했다.
- [ ] mutex와 선행 관계가 충돌하는지 유효 시대·조건까지 검토했다.
- [ ] 허브 과집중과 대체 경로의 맥락을 검토했다.

validate_tech_graph는 전달된 데이터 범위에서만 오류·검토 사항을 반환한다. 유효 시대의 자연어 범위와 정치·교리적 예외는 사람이 확인한다. 검사를 통과했다고 세계관적 타당성이 자동 확정되지는 않는다.
