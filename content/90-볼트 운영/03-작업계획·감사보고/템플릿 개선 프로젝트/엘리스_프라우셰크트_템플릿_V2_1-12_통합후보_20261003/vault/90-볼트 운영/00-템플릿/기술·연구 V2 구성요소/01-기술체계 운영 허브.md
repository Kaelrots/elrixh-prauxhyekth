## 식별자와 호환 필드

era는 `2-01`, gate_id는 `G2-03-001` 같은 기존 형식을 사용한다. ID는 시대 인덱스에서 발급 후 불변이다. 이름·표의 No·링크 표시명이 바뀌어도 재사용·재발급하지 않는다. 기수는 신규 입력에서 문자열 `2`처럼 적고 기존 `P2` 값을 자동 변환하지 않는다.

`doc_type`은 호환 필드로 유지하며 세부유형과 같은 역할 이름을 사용한다. 둘은 기술 산출물 분류인 `sub_type`(공통 12종)과 다르다. 기존 `version`은 문서버전과 자동 병합하지 않는다.

## 성숙도와 분류

TMC는 `<ERA>-<TRL>`, 범위는 `MOD-7～9`다. ERA는 ANC·MED·EMO·IND·MOD·NFU·FUT·SPC, TRL은 1~9다. 시대 코드 era와 TMC의 ERA 축을 구별한다.

표준의 특수 코드는 `·LST`(失傳)·`·ARC`(신비)·`·TRN`(초월)다. 상위 V1 초안의 +WAR·+CIV·+ARC를 새 표준으로 채택하지 않는다. 기존 사용 기록은 삭제하지 않고 대응 검토 대상으로 남긴다. ARC와 TRN은 원칙적으로 배타적이며 필요한 코드만 쓴다.

tree_map은 실제 3단계 트랙을 1개 이상 선택하고 복수일 때 핵심·보조 또는 동시 개방 근거를 적는다. sub_type은 표준 공통 12종에서 선택한다. 없는 트랙 코드를 만들지 않는다.

## 관계와 검증

관계 우선순위는 엣지 원장 → 노드의 설명 → 인덱스 요약이다. from_gate가 출발 ID, to_gate가 도착 ID이며 source는 근거 문서 열이다. source를 출발 ID로 이름 변경하지 않는다. Hard/Soft, 대체 경로, 상호배타, 시너지, 구식화는 구별한다.

시각화는 원장의 관계를 읽어 생성한다. 그림이나 노드의 요약을 별도의 관계 원장으로 편집하지 않는다. 읽기 전용 검증기 validate_tech_graph는 명시적으로 전달받은 노드·엣지 데이터를 검사하며 실볼트를 자동 수정하지 않는다. 기존 조회식·외부 추출기의 전 범위 호환성은 승격 전에 별도 확인한다.

## 운영 체크리스트

- [ ] gate_id가 유일하며 인덱스·노드·관계의 ID가 대응한다.
- [ ] 노드마다 tree_map과 sub_type, 시대 변곡점 근거가 있다.
- [ ] 관계는 원장에 기록했고 노드의 prereq/unlocks 요약과 일치한다.
- [ ] 교차시대 엣지에 점프 이유·근거가 있다.
- [ ] 자기참조·의도치 않은 선행 순환·mutex 충돌·폐기 노드의 활성 관계를 점검했다.
- [ ] 허브 과집중과 alt_path/mutex 구별을 사람이 검토했다.
