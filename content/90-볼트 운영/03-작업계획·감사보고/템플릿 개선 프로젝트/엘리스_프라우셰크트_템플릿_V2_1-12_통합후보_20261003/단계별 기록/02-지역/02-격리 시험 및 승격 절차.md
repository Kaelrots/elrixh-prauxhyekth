# 지역 V2 격리 시험 및 승격 절차

자동검증 이후 실제 앱에서 확인할 절차다. 아래 항목은 아직 실환경에서 완료하지 않았다.

## 별도 볼트 준비

이 작업 폴더의 `sandbox-vault/`를 Obsidian의 별도 볼트로 연다. 지역 후보와 로컬 설치본에서 복사한 Templater·Dataview, 빈 시험 노트 세 개를 준비했다. 복사한 Templater 설정은 자동 생성 규칙과 시스템 명령을 끈 상태다. 사용자 테마·병합표 플러그인의 화면 확인은 이 별도 볼트에 필요한 표시 환경을 준비한 뒤 수행한다.

ZIP만 내려받았다면 `vault/`를 별도 볼트로 열고 Templater를 설치한다. 다음 경로를 <font style="font-weight:bold">격리 볼트 안에서만</font> 설정한다.

- Template folder: `90-볼트 운영/00-템플릿`
- User Script Folder: `90-볼트 운영/00-템플릿/유저 스크립트`

지역 정의·국가·기관 등 기존 설정 문서는 별도 볼트에 동봉하지 않았다. 기존 문서로 향하는 링크 해석은 원본 자료를 읽기 전용 복사해 준비하거나, 승격 시험 때 별도로 확인한다.

## 연속성과 복원 시험

격리용 시작형 복사본에서 `render_region`의 `values`로 해당 문서의 값을 지정할 수 있다. 공통 원본 기본값은 바꾸지 않는다.

```javascript
tR += await tp.user.render_region(tp, {
  preset: "continental",
  values: {
    "연속성": ["B루트"],
    "적용범위": ["신계", "라리셴베르크"],
    "기준시점": "시험용 세계관 시점"
  }
});
```

B루트 경로에서 연속성을 생략하면 거부하고, 위처럼 명시하면 생성되는지 확인한다. 복원 시험은 `기원상태: restored`와 확인된 복원 출처를 추가해 `복원여부: true`가 생성되는지 확인한다. 이 예시는 시험값이며 새 정본 설정을 확정하지 않는다.

## 실사용 승격

1. 작업 패키지 폴더가 게시용 동기화와 Quartz 출력에서 제외되는지 확인한다. 보고서·구성요소 등에는 문서별 draft 값이 없을 수 있다.
2. 별도 Quartz 사본에서 draft 문서 제외, 시험용 aliases·permalink의 연결, 기존 공개주소 충돌 여부를 검사한다.
3. 현재 실사용 공통 원본·스크립트와 지역 V1을 백업하고, 후보 매니페스트의 11개 파일을 실제 대상에 대조한다. 공통 의존성 2개가 이미 같은 내용이라면 중복 원본을 추가하지 않는다.
4. 검증 결과와 실제 교체 범위를 확인한 뒤 승격한다. 최초에는 V1 두 파일을 보존하고 V2 시작형을 별도로 추가한다. V1 폐기·이름 변경·기존 지역 문서 이관은 별도 작업이다.
5. 문제가 발생하면 추가한 지역 V2 자산을 되돌리고, 공통 의존성을 교체했다면 함께 백업으로 복구한다. 기존 생성 문서를 자동 삭제하거나 스키마 버전을 일괄 변경하지 않는다.

## 자동검사 재현

Node.js와 Python의 PyYAML을 준비해 패키지 루트에서 `node 검증/test_region.js`를 실행한다. 실제 파서는 환경변수 `TEMPLATER_BUNDLE`에 설치된 Templater 2.13.1의 `main.js`를 지정한 뒤 `node 검증/test_region.js --engine`으로 검사한다. 버전이 달라 번들 구조가 바뀌었다면 검사 어댑터를 검토한다.

JSON의 실행 환경과 파서 해시를 함께 보관한다. 이 검사는 실제 Obsidian GUI·YAML API와 Quartz 배포를 대체하지 않는다.
