# 정책 V2 격리 시험 및 승격 절차

자동검증 이후 실제 앱과 게시 환경에서 확인할 절차다. 아래 실환경 시험은 아직 완료하지 않았다.

## 별도 볼트 준비

이 작업 폴더의 `sandbox-vault/`를 Obsidian의 별도 볼트로 연다. 후보 파일, 로컬 설치본에서 복사한 Templater·Dataview, 빈 핵심형·상세형 노트를 준비했다. 자동 생성 규칙과 시스템 명령은 껐다. 실제 표·HTML 표시는 기존 테마·CSS·병합표 표시 환경을 별도 볼트에 준비한 뒤 확인한다.

ZIP만 받은 경우 `vault/`를 별도 볼트로 열고 필요한 플러그인을 준비한다. 다음 경로를 격리 볼트 안에서만 설정한다.

- Template folder: `90-볼트 운영/00-템플릿`
- User Script Folder: `90-볼트 운영/00-템플릿/유저 스크립트`

실제 국가·지역·기관·법령 문서는 동봉하지 않았다. 링크 해석은 읽기 전용 사본을 준비하거나 승격 시험에서 확인한다. 생성 예시의 제목·고정 시각은 시험값이다.

## 연속성과 복원

격리용 시작형 사본에서 문서별 값을 `values`로 전달한다. 공통 원본의 기본값은 바꾸지 않는다.

```javascript
tR += await tp.user.render_policy(tp, {
  preset: "detailed",
  values: {
    "연속성": ["B루트"],
    "적용범위": ["신계", "라리셴베르크"],
    "기준시점": "시험용 세계관 시점"
  }
});
```

B루트 경로에서 연속성 생략 시 거부하고 명시하면 생성되는지 확인한다. 복원 시험은 `기원상태: restored`와 확인된 출처를 지정해 복원 호환값·출처가 보존되는지 확인한다. 시험값을 정본 설정으로 사용하지 않는다.

## 실사용 승격

1. 작업 패키지 전체가 게시용 동기화·Quartz 출력에서 제외되는지 확인한다. 보고서·구성요소는 개별 draft 값이 없을 수 있다.
2. 별도 Quartz 사본에서 draft 제외, aliases·permalink, 기존 주소 충돌과 작성 안내·미확정 메모 노출을 확인한다.
3. 실사용 공통 원본·생성기·정책 V1을 백업하고 매니페스트의 11개 파일과 대조한다. 공통 두 파일이 같으면 중복 원본을 만들지 않는다.
4. 검증 결과와 교체 범위를 확인한 뒤 V1을 보존하면서 V2를 별도로 추가한다. V1 폐기·이름 변경·기존 정책 문서의 일괄 이관은 별도 작업이다.
5. 문제가 생기면 추가한 정책 V2 자산을 되돌리고, 공통 의존성을 교체했다면 백업으로 복구한다. 기존 생성 문서를 자동 삭제하지 않는다.

## 자동검사 재현

Node.js와 Python의 PyYAML을 준비해 패키지 루트에서 `node 검증/test_policy.js`를 실행한다. 실제 파서는 `TEMPLATER_BUNDLE` 환경변수에 설치된 Templater 2.13.1의 `main.js`를 지정하고 `node 검증/test_policy.js --engine`으로 검사한다. 번들 구조가 바뀌면 검사 어댑터를 검토한다.

검사는 모의 Vault·편집기·YAML API를 사용한다. JSON의 실행 환경·파서 해시를 결과와 함께 보관한다. 실제 앱 시험과 공개 빌드를 대체하지 않는다.
