# 10/12 자원 V2 — 검증 및 승격 준비

상태: 격리 후보본 제작·자동검증 완료. 실사용 승격 보류(HOLD).

자원 Core와 일반 물성·가공, 선택 마학·간섭·환경, 통제·보안·물류, 영혼 마모, 역사·해석 장으로 재편했다. resource_id는 평면 확장 필드로 보존하며 신규 번호를 자동 생성하지 않는다.

계획서 23절을 적용했다. tag 오기는 공통 tags 체계로 통일했다. 기존 인용 YAML의 이름·정량 값·정제 단계·기관 의미를 본문에 대응하고 임의 F·1·0·Raw 기본값을 제거했다. V1 영혼 마모·보안·정제 척도는 참고 모델로 보존했다. 특정 관점의 비판을 별도 장에 두고 기존 중복 번호를 제거했다. HTML checkbox의 고정 id 반복 대신 명시적 선택·값 표를 사용하며 병합표·HTML 시각 문법은 보존했다. 실제 기존 자원 문서의 인덱스·ID는 이관하거나 변경하지 않았다.

## 구성

- 11-자원 설정 템플릿 V2: 자원 Core를 작성한다. 일반 자원에 불필요한 마학·영혼 마모·연방 보안 장은 추가하지 않아도 된다.
- 11-자원 설정 템플릿 V2 상세형: 일반 상세와 특수 모듈을 모두 제공한다. 특수 척도·연방 기준은 실제 적용 여부를 확인하고 필요한 장만 사용한다.

## 검증

- Node 모의 검사 63건, 실제 Templater 2.13.1 WASM 파서 검사 63건, 정적·계승 검사 61건. 실패 0건.
- 실제 파서 시험도 Vault·편집기·YAML API는 모의 환경이다. Obsidian GUI 시험이나 Quartz 전체 빌드를 수행한 것으로 간주하지 않는다.
- 참조 원본 해시 전후 일치. 공통 SSOT와 render_frontmatter.js는 선행 단계와 바이트 단위로 동일하다.
- `검증/생성예시`는 고정 시각·가상 제목을 사용하는 검증 자료이며 정본 설정이 아니다.

## 승격 전 남은 확인

1. 실제 볼트의 별도 복사본에서 빈 노트에 시작형을 삽입하고 병합표·HTML·Dataview 버튼을 확인한다.
2. Quartz에서 HTML·병합표·링크 표시를 확인하고 작업계획·검증 폴더의 공개 제외를 별도로 확인한다. `draft`나 `only-local`만으로 폴더 전체가 제외되지는 않는다.
3. 원본 백업과 차이 검토 후 승격한다. 00-템플릿 원본과 법령계 파일은 이번 단계에서 변경하지 않았다.

## 기준 자료 처리

기준 폴더 계획과 계승된 공통 SSOT의 충돌은 사용자가 우선 지정한 SSOT에 맞췄다. aliases·tags·복원여부 호환값·B루트 검증을 유지했다. 구식 공통 설계의 키 이름으로 되돌리지 않았다.
