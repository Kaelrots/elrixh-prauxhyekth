# 템플릿 공통 프론트매터 V2 개편 설계안

> [!important] 2026-10-02 수정 확정 — 재배치 규격 계승·단일원본 방식
> 이번 결정은 2026-09-30 구조개편 규격을 기반으로 공통 프론트매터를 확장한다. <font style="font-weight:bold">양식·기본값·자료형·열거형·선택 필드의 편집 원본은 `00-yaml 속성탭.md` 하나뿐이다.</font>
> 이 문서는 의미·계승·운영 규칙을 설명하며 전체 YAML을 다시 복제하지 않는다. 생성기 JS에도 기본 양식을 복제하지 않는다.
> 규격 버전은 `2.0.0`이다. 규격 확정과 실사용 배포 승인은 구분한다. 이번 패키지는 별도 작업본이며 Drive 원본·실사용 템플릿·기존 설정문서·배포 설정은 변경하지 않았다.

## 1. 무엇을 확정하고 무엇을 배포하지 않았는가

확정한 것은 공통 원본의 위치, 필드의 의미·자료형·허용값, 조건부 확장, 신규 생성과 기존 이관의 분리, 재배치 규격의 계승 방식이다. 실행 코드는 모의 검증 대상이며 실제 Obsidian/Templater/Quartz 검증을 마쳤다는 뜻은 아니다.

우선순위는 이번 사용자 결정 → 기존 구조개편에서 승인된 규격의 계승 → 인물 파일럿에서 검증한 개선안 순이다. 기존 규격에 없는 새 설정 내용을 만들어내거나, 새 템플릿에 없다는 이유로 기존 속성을 삭제하지 않는다.

## 2. 유일한 양식 원본과 운영 위치

승격 후 원본 위치:

```text
90-볼트 운영/00-템플릿/00-yaml 속성탭.md
```

기존 파일의 이름과 위치를 계승한다. 최종 배포 시 `00-yaml 속성탭 V2.md` 같은 별도 활성 원본을 함께 남기지 않는다. 현재 실사용 원본을 바꾸기 전 백업은 프로젝트 보존 영역에 두고 신규 삽입 검색에서 제외한다.

<font style="font-weight:bold">‘원본 한 개’는 모든 실제 문서에서 프론트매터를 없앤다는 뜻이 아니다.</font> 생성된 문서에는 일반 YAML이 저장되고, 그 생성 양식만 한 곳에서 관리한다.

원본에는 YAML 블록 하나만 있으며 본문은 없다. `# @type`, `@enum`, `@optional` 등의 짧은 YAML 주석을 생성기가 읽어 검사한다. 이 주석은 실행 규칙이므로 Properties 화면에서 재저장하지 말고 원본 모드에서 편집한다. Obsidian은 템플릿 변수와 Properties 편집의 충돌에 대해 원본 모드 사용을 권한다.[^templates]

## 4. 공통 기본부와 선택 확장

공통 필드의 완전한 실제 목록과 기본값은 원본 MD에서만 관리한다. 목록을 읽는 규칙은 다음과 같다.

`@optional`이 없는 키는 일반 신규문서 기본부에 남긴다. `@optional`은 원본에서 삭제한다는 뜻이 아니라, 해당하지 않는 신규문서의 결과에서 생략할 수 있다는 뜻이다. 유형별 호출부가 명시한 선택 필드는 값이 null/빈 목록이어도 유지한다. 복원 출처는 restored인 경우 빈 슬롯도 남겨 확인 필요성을 드러낸다.

신규 문서에는 평면 값과 문자열 목록을 우선한다. 다만 기존 자료에 중첩 데이터가 있으면 평면형 규칙을 이유로 삭제하거나 문자열로 뭉개지 않는다. 기존 데이터의 의미 보존과 신규 작성 규격은 다르다. Obsidian Properties는 작고 원자적인 속성에 적합하며 중첩 속성 편집에는 한계가 있다.[^properties]

## 5. 문서유형과 세부유형

기존 `master / concept / entity / reference / index / report / template / archive`를 유지한다. 신규 선택지는 `event / period / rule / ledger`이다. 실제 허용값은 원본 MD의 문서유형 enum에 한 번만 적는다. 기존 reference 역사문서를 event로 바꾸는 것은 선택적 재분류이며 자동 승계의 필수조건이 아니다.

세부유형은 person, nation, institution, historical_event, gate_node, gate_edges 등의 더 좁은 역할을 나타낸다. 기존 `doc_type`은 자동 폐지하지 않는다. 동일성·조회식·추출기 호환을 확인한 뒤 별도 매핑으로 전환한다. 마스터가 특정 인물에 관한 상위 문서이면 `master + person`도 가능하다.

템플릿 원본의 YAML 또는 호출부는 <font style="font-weight:bold">앞으로 생성할 문서의 값</font>이다. 실제 인물이 아니므로 템플릿 폴더와 미처리 Templater 파일은 설정 검색·정본 수집에서 제외한다. 반대로 실제 문서에 ‘사용된 템플릿’ 속성이 있다는 이유만으로 원본 템플릿으로 오인하지 않는다.

## 6. 네 가지 상태 축

정본상태는 해당 연속성 안에서의 설정 승인 수준, 작성상태는 문서가 정한 작성 범위의 충족도, 검토상태는 현재 내용의 검토 진행도다. `draft`는 별도의 배포 제외 의도다.

`complete`는 모든 선택항목을 채우라는 뜻이 아니다. 짧은 인물도 정한 범위를 마치면 complete일 수 있다. reviewed는 canon 승격이 아니며, master/index/report라는 유형도 정본을 보장하지 않는다. 문서 내부의 명시적 미확정 구획은 문서 전체 상태와 별도로 읽는다.

`@locked`는 생성기의 호출 인자 덮어쓰기 금지 규칙이지 Obsidian의 편집 잠금이나 접근권한이 아니다. 신규 생성기는 정본·작성·검토·배포 기본값을 호출부가 덮어쓰지 못하게 한다. 승인 뒤 작성자가 바꾸는 것과 생성기가 몰래 승격하는 것을 구분하기 위해서다. 기존 문서에는 이 기본값을 적용하지 않는다.

실질적 내용 변경 후 이전 reviewed가 계속 현재 검토 완료로 보이지 않도록 다시 검토 상태로 되돌리는 운영 규칙을 둔다. 오탈자·포맷 수정과 실질적 변경의 자동 구분은 이번 생성기의 기능이 아니다.

## 7. 연속성·적용범위·기준시점

정본 해석은 문서유형 하나가 아니라 <font style="font-weight:bold">정본상태 + 연속성 + 적용범위 + 명시된 시점</font>을 종합한다. B루트 문서의 canon은 B루트 내부의 정본이며 A루트로 자동 합쳐지지 않는다. 기존 B루트의 필수 연속성 규칙을 그대로 계승한다.[^manifest]

신규 호출부에서 연속성을 지정할 때 명시적으로 전달한다. 생성기는 확인된 기존 B루트 경로에서는 B루트 누락을 거부하지만, 새로 생길 다른 분기까지 자동 판정하는 도구는 아니다. 모든 분기 감사는 추후 실제 목록과 대조한다.

적용범위 []와 연속성 []는 미지정이지 ‘전 차원·전 루트 공통’이 아니다. ‘공통’은 그 뜻이 확인될 때만 명시한다. 여러 연속성을 한 문서에 넣을 경우 각 구획의 적용 대상을 명확히 적고 자동 합성하지 않는다.

기준시점은 세계관 내부의 ‘현재’를 특정하는 선택 문자열이다. 인물·국가·기관 등에 사용하며 현실 문서 수정일과 분리한다. 세계관의 48개월·30일 체계를 현실 날짜형에 강제로 넣지 않는다. 연호 변환·나이 계산 규칙은 별도 정본을 따른다.

## 8. 기원과 복원여부의 호환

확인된 신규 작성은 original, 복원 출발은 restored다. 과거 문서의 기원이 확인되지 않으면 null 또는 미기입을 보존한다. 필드가 없다는 이유로 original을 추정하던 이전 초안의 규칙은 철회한다.

복원여부는 현재 호환 단계에서 유지한다. 신규 생성기에서는 기원상태가 original이면 false, restored이면 true, null이면 null로 파생한다. 형은 한쪽 의미만 관리하고 호환값을 따로 판단하지 않는다. 기존 자료에서 두 필드나 본문의 복원표시가 충돌하면 <font style="font-weight:bold">기존값·근거를 보존하고 HOLD</font>한다. 위 파생 규칙으로 모순을 은폐하지 않는다.

생성 뒤 문서에서 기원상태를 수동 변경하면 복원여부가 저절로 동기화되지는 않는다. 이 경우 관리 절차에서 호환값을 함께 점검해야 한다. 실시간 속성 동기화는 이번 생성기의 기능이 아니다.

호환필드를 없애는 것은 기존 조회식·Templater·JS·BAT·AI 읽기 규칙의 의존성이 사라졌다는 검사 후 별도 승인으로 진행한다. 이번에는 제거하지 않는다.

## 9. 복원 원문 기록과 미입력값

restored 문서에 원문 문서명과 원문 최초·최종 날짜를 남긴다. 하나의 원문이면 기존 세 필드를 사용한다. 여러 원문은 본문 출처표 또는 기존 구조를 보존하며 문서명/날짜의 대응관계를 잃는 임의 병합을 하지 않는다.

복원 날짜는 추정·연도만 알 수 있으므로 텍스트를 허용한다. 알려지지 않은 값은 null, 기존의 ‘미상’ 같은 표현은 의미를 확인해 계승한다. null은 부재 확정이 아니다. ‘미정’은 창작상 미결정, ‘미상’은 알려지지 않음, ‘없음’은 부재 확정, ‘해당 없음’은 비적용으로 구분하되 종전 문맥이 다르면 자동 변환하지 않는다.

## 10. 별칭·태그·분야

새 문서는 Obsidian 내장 기능 이름인 aliases와 tags를 사용한다.[^aliases][^tags] 그 외 기존 한국어 키는 읽고 쓰기 쉬운 형태로 유지한다. 분야는 의미 분류, tags는 추가 검색어다. 모든 문서에 같은 값을 양쪽에 반복하게 강제하지 않는다.

aliases에는 명칭 별칭뿐 아니라 재배치에서 보존한 옛 공개주소가 들어 있을 수 있다. 이 두 용도를 구분한 검증이 필요하며, 키가 있다고 빈 배열로 초기화하지 않는다. Quartz 배포 시 별칭 URL의 중복·충돌도 확인해야 한다.[^structure]

기존 태그에는 공백이나 오래된 표기가 있을 수 있다. 후보 합집합을 만든 뒤 원문 대응표를 남겨야 하며, 공백을 밑줄로 바꾸는 등의 정규화를 사용자 승인 없이 실행하지 않는다. 신규 생성기의 태그 검사도 자동수선 없이 오류를 알린다.

## 11. 공개주소와 배포

permalink는 공개주소이며 현재 파일시스템 경로와 다르다. 기존 고정주소와 aliases의 과거 주소를 보존한다. 초안·운영자료에 고정주소를 새로 강제하지 않는다.[^structure]

draft=true는 배포 제외 의도이고 접근권한/암호화가 아니다. Quartz의 실제 제외 필터, 변환기의 처리, 운영폴더 ignore 설정이 맞아야 작동한다. 접힌 콜아웃, DRAFT 파일명, only-local 클래스만으로 비공개를 보장하지 않는다. 기존 공개 문서의 draft=false나 미지정 상태를 신규 기본값으로 일괄 덮어쓰지 않는다.

title/created/modified 같은 기존 배포용 값은 소비자와 의미가 확인되기 전 그대로 둔다. 장기적으로 원본에서 파생할 수 있지만 이번 생성기는 배포 변환기를 교체하지 않는다. 80·98 폴더 공개정책도 기존 HOLD 결정을 임의로 해제하지 않는다.[^manifest]

## 12. 현실 날짜와 수정기록

관리 날짜는 Templater 생성 시 기록되는 현실 시간 문자열이다. 형의 한국 시간 작업환경을 전제로 기존 형식 YYYY-MM-DDTHH:mm:ss를 유지한다. 다른 시간대 환경으로 확대할 때는 별도 정규화 규칙을 정하고 기존 날짜를 추측 변환하지 않는다.

최초작성일은 문서 최초 생성의 기록이다. 이관·이름 변경·폴더 이동·템플릿 적용만으로 초기화하지 않는다. 기존 날짜가 날짜만 있거나 역전되어 있으면 원문을 유지하고 보고한다. 수정일 버튼·수정횟수 카운터는 별도 기능이며 이 생성기는 실행하지 않는다.

## 13. 문서·스키마·템플릿 버전

문서버전은 내용 개정, 스키마버전은 적용한 메타데이터 규격, 템플릿 버전은 마지막으로 적용·검증한 템플릿 구조를 기록한다. 최초 사용 템플릿은 이관/수정기록에 보존한다. 이 정의는 초기 계획서의 ‘처음 생성할 때 버전 고정’을 수정한 것이다.

새 템플릿이 생겼다는 이유로 기존 문서의 숫자만 올리지 않는다. 실제 전환과 검증을 거친 대상만 갱신한다. 이번 공통 스키마 2.0.0과 인물 본문 pilot.2는 독립적이다. 공통 규격을 확정했다고 인물 본문 전체가 최종 확정된 것은 아니다.

## 14. 유형별 호출부와 확장

인물 템플릿은 공통 원본 전체를 넣지 않고 다음 호출부만 가진다. 빠른 시작형도 같은 원본을 호출하되 자신의 템플릿 이름을 기록한다.

```javascript
<%*
tR += await tp.user.render_frontmatter(tp, {
  values: {
    "문서유형": "entity",
    "세부유형": "person",
    "분야": ["인물"],
    "사용된 템플릿": "04-인물 설정 템플릿 V2 파일럿",
    "템플릿 버전": "2.0.0-pilot.2",
    "기준시점": null
  }
});
%>
```

코드블록 표시는 설명용이다. 실제 템플릿 파일 맨 위에는 이 내용을 코드 울타리 없이 둔다. Templater의 User Script는 tp를 인자로 받고 결과 문자열을 반환하며, 포함된 템플릿은 tp.file.include로 읽는다.[^templater][^include]

유형 전용 값은 `extensions` 객체로 넘길 수 있다. 공통 키와의 충돌은 거부한다. 예컨대 gate_id는 새 번호를 자동 생성하지 않고 해당 기술 문서에서 명시한 값을 전달한다. 신규 확장은 평면형으로 제한하지만 기존 중첩 데이터 이관은 별도 검토다. `doc_type` 등 기존 전용 키는 임의 삭제하지 않는다.

선택 필드를 모든 유형에 억지로 강제하지 않는다. 상위개념/하위개념은 개념 관계용이며 가족관계나 조직의 상하관계와 동일시하지 않는다.

## 15. 신규 생성기의 안전 범위

생성기는 원본을 읽고, 원본의 @ 주석을 기준으로 값을 검사하고, 문자열을 반환한다. 파일 쓰기·이름 변경·네트워크·배포·카운터 갱신이 없다. 실제 문자열 삽입은 사용자가 실행한 Templater가 담당한다.

공통 원본 없음, 중복 키, 허용값 오류, 자료형 오류, 필수값 없음, 금지 키, 확장 충돌, 비어 있지 않은 대상, 실행 도중 원본/대상 변경이면 오류로 중단한다. 구형 하드코딩 양식으로 몰래 돌아가지 않는다. 대상은 활성 파일이 아닌 `tp.config.target_file`로 한정한다.[^config]

지원하는 시작 경로는 ‘빈 새 노트에 Templater로 삽입’이다. 기존 본문이 있는 문서, 프론트매터만 있는 기존 문서, 새 노트 만들기 명령 중 원시 템플릿이 먼저 채워지는 실행 모드는 거부될 수 있다. 이를 피해 안전검사를 해제하지 말고 실제 설치 환경에서 사용 경로를 확인한다.

## 16. 기존 문서 이관 규칙

이번 패키지에는 기존 파일을 덮어쓰는 변환기가 없다. 신규 생성기를 기존 문서 위에서 실행하여 이관하지 않는다.

이관은 원본 스냅샷 → 실제 속성 전수목록 → 유지/변환/퇴역/미분류 대응표 → 읽기 전용 변경 예고 → 승인 → 선택적 적용 → 재검증 순이다. 알려지지 않은 키는 보존한다. 기준에 없다는 이유로 삭제하지 않는다.

같은 파일의 제목, dates, 상태, URL, 연속성, 출처, gate_id 등 식별자를 보존한다. 변환 중 정보 충돌이 나면 HOLD하고 병합 이유를 남긴다. 새로운 기본값과 기존 값의 병합 우선순위는 ‘기존값 우선’이지만, 기존 모순을 사실로 인증한다는 뜻은 아니다.

## 17. 본문·AI 지침과의 경계

본문의 `<`, `^`, `<span>`, `<center>`, `<br>`, `<hr class=...>`는 인간용 표현으로 유지한다. 스키마 생성기는 본문을 변환하지 않는다. AI 지침에는 단독 병합기호의 문맥, 색상칩의 실제 HEX, 예시/입력칸, 시점·관계 방향 등을 정의한다.

기존 볼트 최상위 Agent 지침의 실제 파일부터 확인하고 거기에 통합한다. 계획서에 언급된 DRAFT-AI_AGENT_INSTRUCTIONS.md를 새로 만들어 중복 지침을 운영하지 않는다. 프론트매터에는 장문의 AI 명령문을 붙이지 않는다.

## 18. 적용 절차와 검사

먼저 프로젝트의 별도 작업 폴더에서 공통 원본과 생성기를 함께 시험한다. sourcePath 시험 인자는 원본의 위치만 바꿔 가리키며 두 번째 양식을 만드는 것이 아니다. 원본 MD와 JS를 실사용 위치에 자동 복사하지 않는다.

실환경 검증 후 기존 00-yaml 속성탭.md를 같은 경로·같은 Drive ID로 교체하고, Templater User Script Folder 설정에 맞춰 생성기를 설치한다. 실제 개별 템플릿이 공통 호출로 바뀌었는지 검사해야 단일원본 전환이 완료된다. 명시적으로 승인하기 전에는 나머지 템플릿을 일괄 변경하지 않는다.

완료 조건은 공통 양식 중복 0, 누락된 기존 유형 0, 미분류 키 자동삭제 0, 상태·날짜·공개주소 무단 초기화 0, A/B 혼입 0, 본문 변경 0, 원본 미발견 시 안전중단, 실제 Templater 삽입 성공, 실제 배포 제외·리디렉션 유지 확인이다.

이번 수행 결과는 패키지의 `검증/검증결과.md`에 기록한다. 모의 API 검증과 실제 앱 검증은 분리한다.

## 19. 이 결정으로 대체되는 이전 초안

이전의 전체 YAML 복사 운영, 기존 3종 문서유형 누락, aliases를 이름만으로 해석, 연속성·개념관계·permalink 누락, 복원여부 즉시 삭제, 기원 결측이면 original, 템플릿 버전 최초값 영구 고정, 신규 draft값의 기존문서 적용은 채택하지 않는다.

규격의 중심은 ‘가장 짧은 표’가 아니라 <font style="font-weight:bold">이미 확립된 의미의 보존과 한 곳에서의 양식 관리</font>다. 인물 본문의 구획·표 밀도는 별도 피드백으로 다듬되 이 공통 생성원본을 다시 복제하지 않는다.
