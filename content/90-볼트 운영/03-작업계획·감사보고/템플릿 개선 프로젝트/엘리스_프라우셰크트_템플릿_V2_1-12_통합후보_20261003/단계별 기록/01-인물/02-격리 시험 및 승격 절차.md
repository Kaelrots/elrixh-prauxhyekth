# 인물 V2 격리 시험 및 승격 절차

이 문서는 실제 앱에서 남은 확인을 수행하기 위한 절차다. 체크하지 않은 항목은 미검증이다. 이번 작업에서 실사용 원본을 바꾸는 명령은 실행하지 않았다.

## 격리 볼트 열기

이 채팅의 작업 폴더에는 `final/`과 나란히 `sandbox-vault/`를 준비했다. 이 별도 볼트에는 확정 후보 4개, 로컬 설치본에서 복사한 Templater·Dataview, 빈 시험 노트 두 개가 있다. 원본 볼트의 설정을 바꾸지 않았다. ZIP에는 타사 플러그인과 실제 사용자 환경 설정을 포함하지 않았다.

Obsidian에서 `sandbox-vault`를 별도 볼트로 열고 이 격리 볼트에서만 플러그인을 허용한다. 복사본의 Templater는 생성 자동실행·폴더 규칙·시스템 명령을 꺼두었다. 시험자는 두 경로가 다음과 같은지 확인한다.

- 템플릿 폴더: `90-볼트 운영/00-템플릿`
- 사용자 스크립트 폴더: `90-볼트 운영/00-템플릿/유저 스크립트`

ZIP으로 다른 컴퓨터에 옮긴 경우 `vault/`를 새 볼트로 열고 Templater를 준비한 뒤 같은 경로를 설정한다. 원본 볼트 안에서 설정을 바꾸어 시험하지 않는다.

복원·B루트 시험을 위해 공통 원본의 기본값을 바꾸지 않는다. 시험용 템플릿 복사본의 `values`에 명시한 값만 추가한다. 실제 사람의 인물 설정은 사용하지 않는다.

## 공개 제외와 승격 준비

1. 프로젝트 작업폴더가 게시용 동기화 입력과 Quartz 출력에서 제외되는지 확인한다. 필요 시 별도 승인된 게시 설정 변경으로 `90-볼트 운영/03-작업계획·감사보고/템플릿 개선 프로젝트/**`를 제외한다. 이번 패키지는 게시 설정을 자동 수정하지 않는다.
2. 별도의 Quartz 시험 사본에서 draft 인물이 출력되지 않는지, 시험용 aliases·permalink가 예상한 대상에 연결되는지 확인한다. 기존 공개주소와 충돌하지 않는 시험 경로를 쓴다.
3. 실제 환경 시험 결과, 화면 확인, 대상 파일 해시를 보고서에 추가한다. 실패가 있으면 후보를 보완하고 영향받는 검사만 다시 실행한다.
4. 실사용 승격 시점에 기존 Frontmatter·인물 V1과 현재 스크립트 상태를 백업한다. 사용자에게 실제 대상 4개와 변경 비교를 제시해 승격을 확정한다.
5. 공통 MD는 기존 `00-yaml 속성탭.md` 경로를 계승하고 생성기는 확인된 User Script Folder에 둔다. 처음에는 V1 인물 파일을 보존한 채 V2 두 파일을 추가하는 방식을 우선한다. V1을 대체할지와 표시 이름 변경은 승격 때 결정한다.
6. 승격 직후 새 인물 한 건을 시험한다. 문제가 생기면 추가한 V2 파일과 생성기를 제거하거나 이전 버전으로 돌리고, 공통 MD는 백업으로 복구한다. 이미 만들어진 인물 문서를 일괄 수정하거나 삭제하지 않는다.

## 자동검사 재현

`검증/test_renderer.js`는 Node.js와 Python의 PyYAML이 필요하다. 패키지 루트에서 `node 검증/test_renderer.js`를 실행한다. `검증/test_templater_parser.js`는 추가로 환경변수 `TEMPLATER_BUNDLE`에 검사할 Templater 2.13.1의 `main.js` 절대경로를 지정한다. 다른 버전에서 번들 구조가 다르면 어댑터를 검토해야 하며, 플러그인 원본을 수정해서 맞추지 않는다.

이 검사는 GUI와 실제 Obsidian YAML API를 대체하지 않는다. 결과 JSON의 환경 설명과 parser SHA-256을 함께 보관한다.
