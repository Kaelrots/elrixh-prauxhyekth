# 승격 전 확인 및 적용 절차

## 복사 볼트에서 확인

1. 실사용 볼트의 백업 또는 별도 복사본을 준비한다. 이 패키지의 작업·검증 자료를 공개되는 콘텐츠 경로에 함께 넣지 않는다.
2. 후보 vault의 파일을 경로별로 대조한다. `00-yaml 속성탭.md`는 실사용 V1과 이름이 같고 내용이 다를 수 있다. 공통 생성기·각 조합기·구성요소가 같은 후보 버전인지 확인한다.
3. 복사 볼트의 Templater 템플릿 폴더를 `90-볼트 운영/00-템플릿`, User Script Folder를 그 아래 `유저 스크립트`로 맞춘다. 검토 중 자동 삽입·시작 스크립트·시스템 명령을 임의로 켜지 않는다.
4. 빈 노트에서 각 시작형을 삽입한다. YAML이 하나인지, 제목·작성자·날짜·분류·draft가 올바른지, 기존 문서에 재실행하면 중단하는지 확인한다.
5. `<`·`^` 병합표, span·center·br·hr 클래스, Callout·각주·내부 링크·이미지와 Dataview 버튼을 실제 화면에서 확인한다. 생성 문서의 태그·별칭·B루트·복원 출처도 확인한다.
6. 기술 노드의 ID·doc_type·sub_type·중첩 prereq와 원장의 ID·상태·유효 시대를 확인한다. 기존 쿼리·추출기가 새 문서 분류와 추가 열을 처리하는지 확인한다.
7. Quartz 복사 환경에서 생성 문서의 표시를 빌드한다. draft·only-local·접힌 Callout을 폴더 공개 제외의 대체 수단으로 간주하지 않는다.

## 승인 뒤 수동 적용

승격대상 매니페스트의 파일만 적용 후보로 삼는다. 법령계와 기존 실제 설정 문서를 함께 변경하지 않는다. V1은 기존 링크·호출을 위해 보존한다. 레거시 폴더 이동은 이번 패키지에서 수행하지 않았으며 기존 참조 확인 후 별도 결정한다.

덮어쓰기 전 파일별 백업·해시를 남기고, 공통 파일은 한 번만 적용한다. 적용 직후 빈 문서 생성과 기존 V1 동작을 확인한다. 문제가 있으면 기록한 원본 파일·설정으로 되돌린다. 생성된 실제 문서를 후보 템플릿으로 일괄 덮어쓰는 방식은 사용하지 않는다.

## 자동검증을 다시 실행할 때

실제 사용에는 Obsidian·Templater가 필요하다. 제공된 검사 코드를 재실행하려면 Node.js와 Python·PyYAML이 필요하다. `TEMPLATER_BUNDLE`에 설치된 Templater 2.13.1 main.js 경로를 지정한 뒤 통합 검증의 test_combined.js를 실행한다. 단계별 검사 코드도 통합 vault 경로를 읽도록 조정되어 있다. 결과 파일을 새로 쓰므로 재현은 이 패키지의 복사본에서 실행한다. 자동검사 통과는 화면·웹 표시 검사를 대신하지 않는다.
