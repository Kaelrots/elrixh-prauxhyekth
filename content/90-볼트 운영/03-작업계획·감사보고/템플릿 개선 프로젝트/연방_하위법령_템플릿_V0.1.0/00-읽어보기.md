# 연방 하위법령 템플릿 V0.1.0

이 패키지는 이 대화에서 작성한 <font style="font-weight:bold">「연방 법제 템플릿 계열 V0.1」</font>을 실제로 사용할 수 있는 여섯 개의 독립형 Obsidian Markdown 파일로 옮긴 것이다. 공통 속성의 기준은 대화에서 확인한 <font style="font-weight:bold">「템플릿 공통 프론트매터 V2 개편 설계안」</font>이다.

<font style="font-weight:bold">공통 스키마 버전은 `2.0.0`, 법제 템플릿 자체의 버전은 `0.1.0`이다.</font> 기존 Drive·볼트 파일은 수정하지 않았으며, 설치·대량 적용도 수행하지 않았다.

## 2. 사용 방법

`01-템플릿`의 여섯 MD 파일은 <font style="font-weight:bold">공통 프론트매터, 서두, 공시 정보, 작성·정합화 관리 콜아웃, 유형별 본문을 각각 모두 포함</font>한다. 공통 블록을 따로 복사하거나 다른 파일을 포함시키는 작업은 필요하지 않다.

Obsidian에서 대상 노트를 먼저 만들고 제목을 정한 다음, Templater로 해당 템플릿을 삽입한다. 제목과 작성·수정시각이 생성된다. 본문의 `{작성}`, `{법률명}`, `제○조`, 예시 위키링크를 실제 내용과 대상 링크로 교체하고, 사용하지 않는 선택 항목은 제거한다. 마지막으로 Frontmatter의 분류·상태와 본문의 법령정보를 맞춘다.

이번 파일은 새 문서 생성용이다. 이미 내용이 있는 노트에 다시 적용하여 기존 Frontmatter 또는 법문을 덮어쓰는 용도로 사용하지 않는다. Templater를 사용하지 않는 경우에는 파일을 복제하고 세 곳의 `<% ... %>` 표현을 제목과 시각으로 직접 교체한다.

## 3. 공통 V2 규격

공통 키는 다음과 같다.

```text
제목 / 별칭
작성자 / 최초작성일 / 최종수정일
문서버전 / 스키마버전 / 최근 변경 요약
사용된 템플릿 / 템플릿 버전
태그 / 분야 / 문서유형 / 세부유형 / 적용범위
정본상태 / 작성상태 / 검토상태
기원상태 / 복원원문문서명 / 복원원문최초작성일 / 복원원문최종수정일
```

법제 계열의 추가 키는 `법제ID`, `규범종류`, `규범상태` 세 개뿐이다. 이관 ID와 장문의 정합화 메모는 본문 관리 블록에 둔다. `복원여부`는 다시 만들지 않았고, 제목을 태그로 자동 생성하지 않는다.

`문서유형: rule`은 <font style="font-weight:bold">이 템플릿으로 생성되는 규범 문서의 유형</font>이다. 템플릿 원본의 속성처럼 보인다고 이를 `template`으로 바꾸면 생성된 법령 문서에도 그 값이 남으므로 주의한다. 템플릿 파일 자체의 관리는 배치 폴더와 템플릿 개선 프로젝트에서 별도로 한다.

`07-04`, `07-05`, `07-07`의 `규범종류`는 특정 종류를 자동 확정하지 않도록 빈 값으로 두었다. 바로 옆 YAML 주석에 제시한 형식 가운데 실제 문서에 맞는 값을 입력한다. `법제ID`도 임의 번호를 자동 배정하지 않으며, `L-01` 등의 설계 프로젝트 번호와 실제 법령 식별자를 자동으로 동일시하지 않는다.

`규범상태`의 앞선 제안값은 `draft`, `proposed`, `enacted`, `promulgated`, `effective`, `suspended`, `repealed`이다. 각 문서의 실제 절차에 해당하는 상태만 사용한다. 이 값의 변경만으로 재가·공포·시행을 대신하지 않는다.

Frontmatter의 `최초작성일`·`최종수정일`은 현실의 노트 작성시각이다. 본문의 `제정·발령일`·`공포일`·`시행일`은 세계관 속 규범의 날짜이므로 별도로 작성한다. Templater가 최초 삽입할 때의 시각을 채우지만, 그 뒤 수정할 때마다 자동 갱신하는 기능은 이 파일에 없다.

`문서버전`은 작성 중인 문서의 버전, `템플릿 버전`은 생성에 사용한 양식의 버전, 공시 정보의 `시맨틱 버전`은 규범 공시본의 버전이다. 세 값을 자동으로 같은 값이라고 해석하지 않는다.

## 5. 원안의 파일화 과정에서 한 형식 조정

원안의 법문 골격과 유형 구분을 유지했으며, 법령의 새 기관·기간·정족수·법적 효력을 결정하지 않았다. 아래 변경은 작성 편의와 파일 형식을 위한 조정이다.

- 공통부와 유형별 특수값을 파일마다 하나의 Frontmatter에 병합했다. Frontmatter를 두 번 붙이지 않는다.
- 제목의 Templater 표현은 `<% JSON.stringify(tp.file.title) %>`로 감쌌다. 제목에 YAML 구문과 혼동될 문자가 들어가도 생성 결과가 하나의 문자열이 되게 하기 위한 처리다.
- 현실 작성시각의 Templater 표현은 작은따옴표로 감싸 원본·생성본 모두에서 문자열로 유지했다.
- `{명령 / 규칙 / ...}`처럼 선택지를 YAML 값에 그대로 넣지 않고, 빈 값과 선택 안내 주석으로 옮겼다.
- 본문 선택지는 `{... 중 작성}`으로 표시하고, 공시본 버전의 예시값은 입력용 자리표시자로 바꾸었다.
- 금융특별명령의 사후재가 서술은 확인 후 완성하는 문장이라는 안내를 추가했다. 재가 완료·시행 중 상태를 기본값으로 넣지 않았다.
- 대화 화면의 코드블록 ID와 문서 카드 표시는 제거했다. 실제 MD 전체를 다시 코드블록으로 감싸지 않았다.

## 6. 본문과 관리영역

법문, 입법·발령 정보, 공시 정보, 작성·정합화 관리정보를 구별한다. 입법 취지나 검토 메모를 자동으로 규범적 조문으로 취급하지 않는다. `제○조`가 남아 있는 것은 번호 확정 전의 자리표시자이며, 실제 초안 완성 시 조문번호와 교차참조를 따로 점검한다.

서두와 Frontmatter에 반복되는 ID·유형·상태는 <font style="font-weight:bold">현재 자동 연동되지 않는다</font>. 편집할 때 두 표기가 일치하도록 확인한다. 관계기관·상위규범의 위키링크도 입력용 자리표시자가 포함되어 있으므로 모두 존재하는 문서라고 가정하지 않는다.

작성·정합화 콜아웃은 접을 수 있지만, 접힘이 비공개를 의미하지는 않는다. 이번 파일에는 게시 제외 또는 비공개 처리를 자동 실행하는 코드가 없다. 공개본을 만들 때에는 실제 게시 규칙에 따라 관리정보를 제거하거나 게시 대상에서 분리해야 한다. CSS로 숨기는 것만으로 비밀정보를 보호하지 않는다.

## 7. 기존 템플릿 개선 프로젝트와 합칠 때

기존 `07-02-법률 설정 템플릿`·`07-03-황제령 템플릿`을 이 ZIP으로 즉시 덮어쓰지 않는다. 먼저 개선 프로젝트의 검토 폴더에 보관하고, 새 빈 노트에서 생성 결과를 확인한 뒤 채택한다. 파일명 변경에 따른 기존 링크와 템플릿 참조는 별도 확인 대상이다.

이번 패키지에는 독립 사용을 위해 공통부를 각 파일에 내장했다. 이후 V2 프로젝트에서 공통 호출 구조가 확정되면 공통부만 그 구조에 맞추어 연결한다. 검증하지 않은 `tp.user.*`, DataviewJS, CSS, 게시 스크립트는 추가하지 않았다. 공통 수정일 갱신 버튼 등은 실제 프로젝트의 구현을 확인한 뒤 별도로 연결한다.

## 8. 파일화 검증 범위

동봉한 [형식검증 결과](02-검증/형식검증%20결과.md)에 YAML 키·자료형, 제목·날짜 치환 모의검사, Markdown 기본 파싱, ZIP 무결성 점검 결과를 기록했다.

<font style="font-weight:bold">형식검증은 실제 Obsidian·Templater·Dataview·Quartz 실행시험이나 법령 내용의 최종 정합성 검토가 아니다.</font> 사용자 환경에서 템플릿 삽입과 공개 결과는 아직 확인하지 않았다. 내용은 앞서 제시한 V0.1 검토안이며, 이번 요청은 그 안의 파일화 범위로 처리했다.
