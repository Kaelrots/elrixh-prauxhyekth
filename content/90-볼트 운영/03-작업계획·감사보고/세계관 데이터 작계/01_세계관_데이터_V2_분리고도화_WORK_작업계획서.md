# 세계관 데이터 V2 — 분야별 독립 스프레드시트 분리·고도화 WORK 작업계획서

> <font style="font-weight:bold">실행 목적</font>  
> 기존 `지역 상세 목록`과 `엘리시움 신성제국 연방 국가 데이터 (신규 입력용)`을 보존하면서, 지역·국가 데이터를 <font style="font-weight:bold">분야별 독립 Google Sheets 파일</font>로 재구성한다. 기존 데이터·ID·근거·판본·필요한 조회 기능은 계승하되, 중복 입력처·호환용 구조·과도한 빈 행 수식은 정리한다.
>
> <font style="font-weight:bold">가장 중요한 구분</font>  
> 파일 안에 탭을 더 만드는 작업이 아니다. <font style="font-weight:bold">기본 운영 파일 16개</font>를 생성하고, 각 파일이 한 분야의 입력 원본을 담당하도록 만드는 작업이다. 파일 내부의 입력·참조·조회·검증 탭은 이 목적을 보조한다.
>
> <font style="font-weight:bold">이 문서의 상태</font>  
> 이 문서는 실행 지시와 검증 기준을 담은 계획서다. 현재 V2 파일 생성·원본 수정·데이터 이관·온라인 재계산은 수행하지 않았다. 아래의 모든 완료 조건은 WORK가 실제 실행하고 증거를 남겨야 충족된다.

## 1. 승인된 방향과 작업 범위

### 1.1 이번 작업에서 고정할 구조적 원칙

1. <font style="font-weight:bold">V1 보존 / V2 별도 생성.</font> V1의 데이터와 기능을 계승하지만 탭 배치·번호·호환용 좌표까지 유지할 의무는 없다.
2. <font style="font-weight:bold">분리 단위는 분야별 파일.</font> 지역별·인물별로 파일 하나씩 생성하지 않는다. 여러 지역의 인구는 하나의 지역 인구 파일에서 관리한다.
3. <font style="font-weight:bold">정보 축소가 아닌 입력 동선 단순화.</font> 복잡한 근거·기간·관계·판본은 유지하되, 일상 입력 화면에서 기술 열을 분리한다.
4. <font style="font-weight:bold">원본과 조회를 구분.</font> 값을 수정할 수 있는 입력 원본은 하나다. 참조 복사·캐시·조회·집계·연표는 원본이 아니다.
5. <font style="font-weight:bold">세계관 내용의 확정은 별개.</font> 미정인 제도·종족 정의·행성 수치·기준연도·공간계산 규칙을 이관 편의 때문에 확정하지 않는다.
6. <font style="font-weight:bold">기존 고정 ID 유지.</font> 이름·파일·탭·행 순서가 달라져도 기존 개체 ID를 다시 부여하지 않는다.
7. <font style="font-weight:bold">Google Sheets 네이티브 운영을 기본으로 한다.</font> XLSX는 백업·대조용이다. Google Sheets 전용 연결을 Excel에서도 동일하게 작동한다고 간주하지 않는다.

### 1.2 이번 범위에 포함하는 일

기존 실제 자료의 이관, 원본 책임 확정, 중복 후보 대조, 표·필드 정규화, 연결 재구성, 필요한 수식 재작성, 조회 화면·검증·입력 안내·출처·변경 이력·복구 절차를 포함한다. 내용이 없는 신규 분야도 헤더·자료형·코드북·검증·입력 안내까지 갖춘 빈 구조로 제공한다.

### 1.3 이번 범위에 포함하지 않는 일

세계관 정본의 새로운 결정, 전체 볼트의 대량 재검토, 기존 스크립트·Git·Publish 파이프라인 수정, 지도 에디터 구현, 실제 선거 결과 자동 창작, GDP·인구 장기 보간, 모든 문서의 최신 설정 강제 동기화, 신규 유료 서비스 도입은 제외한다. 군사·외교를 별도 운영 파일로 추가하는 일도 이번 기본 16개 파일 범위에는 넣지 않는다. 단, V1에 해당 내용이 실제 존재하면 삭제하지 않고 필드 대응표에 보존 목적지를 지정한다.

진행 중인 다른 세계관 개념 정합화·템플릿 개선 작업은 별도 프로젝트다. 그 결과를 읽지 않은 상태에서 이미 적용되었다고 가정하지 않는다.

### 2.2 착수 시 실행할 읽기 전용 확인

WORK는 먼저 두 원본의 실제 제목·파일 ID·수정 시각·부모 폴더·소유/접근 상태와 전체 탭 목록·`sheetId`를 읽는다. 이어 실제 사용 범위, 헤더, 입력값, 수식, 이름 지정 범위, 드롭다운·네이티브 표·조건부 서식·메모·하이퍼링크·보호 범위·숨김 상태·차트·필터를 목록화한다.

전체 빈 격자를 통째로 반복 조회하지 않는다. 메타데이터와 확인된 범위를 기준으로 분할해서 읽고, 입력행·수식행·서식만 있는 행을 구별한다. 첨부본과 원본의 탭·열·입력값 차이가 있으면 `원본변경차이표`를 만든다.

<font style="font-weight:bold">실제 원본이 첨부본보다 변경되었으면 그 차이를 먼저 보존하고 실행 명세에 추가한다.</font> 이 문서의 87개 탭 목록을 이유로 이후 추가된 자료를 무시하지 않는다. 반대로 최신 수정 시각만을 이유로 충돌하는 세계관 값 중 하나를 정본으로 채택하지 않는다.

### 3.2 권장 저장 구조

별도의 목적지가 지정되지 않은 경우, 새 Google Sheets는 다음 <font style="font-weight:bold">신규 프로젝트 폴더</font>에 모은다. 실제 폴더 ID는 실행 때 조회·생성 후 기록한다.

```text
내 드라이브/ChatGPT/세계관 데이터 V2/
├─ 00-공통·운영/                C00, H90
├─ 10-지역/                    R10~R70
├─ 20-엘리시움 연방/            N10~N70
├─ 80-시험·검증/                TEST 접두어가 있는 시험 사본·증거
├─ 90-V1 보존/                 실행 시점의 별도 원본 복사본·내보내기
└─ 99-실행기록/                레지스트리·이관명세·로그·보고서
```

V1 원본을 이 폴더로 이동하거나 원본 권한을 바꾸지 않는다. `90-V1 보존`에는 별도 복사본만 둔다. 쓰기 권한이 없는 경로를 임의로 권한 확장하거나 공개 설정으로 바꾸지 않는다.

작업계획서의 로컬 보관은 기존 운영문서 체계와 함께 둘 수 있다. 아래는 <font style="font-weight:bold">추천 경로이며 존재 확인·저장 완료를 의미하지 않는다.</font> 로컬 접근이 가능한 실행 환경에서만 처리한다.

```text
C:\구글 드라이브\세계관\90-볼트 운영\03-작업계획·감사보고\데이터 V2 분리개편 프로젝트\작업 기준 파일\
```

### 3.3 버전과 원본 표시

모든 운영 파일 첫 화면에 `file_code`, `data_version=V2`, `schema_version`, `release_id`, 실제 파일 ID, 담당 분야, 원본 입력표, 외부 참조 목록, 마지막 검증 결과를 표시한다. V1과 V2의 이름이 비슷해도 실제 파일 ID로 구별한다.

계획서 버전, 데이터 스키마 버전, 세계관 설정 판본, 배포 릴리스는 서로 다른 값이다. 계획서가 v1.0이라고 데이터가 V1이거나 설정이 초안이라는 뜻은 아니다.

### 4.2 R10 — 지역 목록·공간체계

<font style="font-weight:bold">입력 원본:</font> 지역 ID·표기·분류·기초 면적/경계 근거, 지역 상하위 관계, 시설·교통망의 기본 식별정보, 지역 특성의 부여 이력.

- `지역목록`: 기존 지역 ID, 한국어·엘룬·로마자 표기, 단계·분류, HEX, 상태, 출처. 성계권역주·항성계·행성계도 기존 데이터에 있으면 모두 유지한다.
- `지역관계`: `relation_id`, 하위/상위 지역 ID, 관계 유형, 루트·적용기간·정밀도. ‘상위 지역 1·2’처럼 개수를 고정하지 않는다.
- `공간메타`: `geometry_id` 또는 외부 자산 참조, `crs_id`, 경계/면적 판본, 단위, 근거, 적용기간. 실제 도형 데이터가 없으면 새 경계를 만들지 않는다.
- `시설목록`: 시설 ID·종류·지역·운영기간·운영자 원문·수용 능력의 정의. 성지·종교시설도 시설 기본정보는 여기서 한 번만 입력한다.
- `교통노선`: 노선 ID·종류·시종점·경로·방향·개폐·설계 속도/용량·운영 상태. 노선 설계용량과 기간별 실제 수송량을 구분한다.
- `지역특성관계`: 특성 ID·지역 ID·적용기간·활성·설명.

공간적 포함과 국가 통치관계는 다른 표다. 국가 편입만으로 지역의 불변 ID를 바꾸지 않는다. 복수 대륙에 걸친 전략지역권은 관계표에서 허용하면서 통계 집계에서는 중복 제거한다.

미해결 상위 ID나 이미 존재하던 계층 충돌은 진단에 올린다. 누락 ID를 맞추려고 새 은하·지역 설정을 창작하거나 기존 부모관계를 삭제하지 않는다. 물리값을 이용한 지도 면적 재산출은 이번 기본 범위가 아니다. 그 값이 필요해도 R70과 서로를 참조하는 계산을 만들지 않고, 승인된 외부 계산 결과와 근거를 기록한다.

### 4.3 R20 — 지역 인구

<font style="font-weight:bold">입력 원본:</font> 지역별 인구 관측과 변동, 행성 총인구의 직접 설정값. 연간 값 외의 범위·추정·불명확한 날짜도 표현할 수 있어야 한다.

`인구관측`은 `record_id`, 대상 ID, 루트·기년·시점·정밀도, 인구 정의, 종족 포함 범위, 수치/최소/최대, 값 상태, 자료 범위, 근거·출처·설정 상태를 갖춘다. `인구변동`은 기간별 출생·사망·유입·유출·기타 증감을 별도로 관리한다.

기존 `20 인구`와 `12_지역_인구`를 서로 다른 신규 입력처로 남기지 않는다. 같은 관측 원본에 대해 필요하면 ‘연간 입력 화면’을 제공하되, 한 번 입력한 값이 다른 수동 표에도 작성되어야 하는 구조는 금지한다. UI의 별도 폼을 사용할 경우 원본 테이블에 실제로 기록하는 경로가 검증되어야 하며, 그런 기능이 없으면 정규 원본 표를 유일한 입력처로 한다.

행성 총인구는 `직접값`, `지역합산값`, `채택값`, `채택근거`, `완전성`을 구별한다. 직접값의 숫자 0은 미입력이 아니다. 부분합은 전체 인구가 아니다.

### 4.4 R30 — 지역 사회·문화

<font style="font-weight:bold">입력 원본:</font> 지역별 문화·언어·민족/종족 분포 및 지역 단위 사회지표. 문화·언어·집단 자체의 정의는 C00을 참조한다.

문화·언어·집단 구성은 각자 구분된 표 또는 명확한 `distribution_type`이 있는 구조를 사용한다. 서로 다른 분류축을 한 열의 모호한 선택지로 섞지 않는다. 분포행에는 대상 지역·시점·범주 ID·인원/비율·분모·조사 기준·복수응답 여부·자료 범위가 필요하다.

‘모어 분포’와 ‘사용 가능 언어 분포’, ‘공용어의 제도적 지위’는 다르다. 마지막 항목의 국가 제도 원본은 N60이다. 국가 차원의 문화 정책도 여기로 옮기지 않는다.

사회계층·가구·교육·생활양식 등 새 항목은 빈 스키마와 지표 정의부터 제공한다. 인구 총량은 R20, 고용·산업 실적은 R60을 원본으로 하며, 필요하면 읽기 전용으로 참조한다. 상세 서술이 긴 설정은 문서 링크와 짧은 요약으로 연결하고 본문 전체를 거대한 셀에 재수록하지 않는다.

### 4.5 R40 — 지역 종교

<font style="font-weight:bold">입력 원본:</font> 지역별 신앙 인구·종교/종파 구성과 종교권역·성지/시설의 종교 연결.

`종교분포`는 지역·시점·종교 ID·값 상태·수치·단위·분모·자료범위·응답 방식·설정 상태·출처를 보존한다. `종교시설관계`는 R10의 `facility_id`와 C00의 `religion_id`를 연결한다. 시설 주소·지역·운영 시점은 R10 원본을 참조하고 별도 수동 입력하지 않는다.

상위 종교의 신자 수와 하위 종파의 신자 수를 동시에 합산하지 않는다. 공식 단일 대표 정체성 통계와 복수 응답 조사 통계를 분리한다. 국가가 인정하는 종교의 법적 지위·교무 제도는 N70의 원본이다.

### 4.6 R50 — 지역 정치·소속

<font style="font-weight:bold">입력 원본:</font> 지역과 국가 사이의 실제 통치·법적 영유·주장·보호·종속·공동관리 등 관계 및 그 적용기간·면적.

기존 지역 `10 정치 지역관계`, `15_지역_소속이력`, 국가 `03_영토_이력`을 대조해 이곳의 `지역국가관계`로 모은다. 어느 표에서 왔든 아래 필드를 보존한다.

```text
relation_id / region_id / nation_id / planet_scope_id
relation_type / route / start_era / start_year / start_month / start_day
end_era / end_year / end_month / end_day / date_precision / end_status
applied_scope / controlled_land_area / area_unit / aggregation_include
source_id / original_location / setting_status / legacy_locator / notes
```

하나의 지역에 대한 통치·영유권 주장이 병존할 수 있다. 같은 지역·같은 국가라고 모든 관계를 중복으로 보지 않는다. 중복 판정에는 관계 종류·기간·루트·범위·출처가 필요하다.

국가별 영토목록은 이 표의 조회 결과다. 국가 파일에 두 번째 영토 입력표를 만들지 않는다. 한 지역 일부만 통치하는 경우 면적 비율을 인구 비율로 자동 대체하지 않는다. 영토 변동만으로 그해 GDP·인구를 기계적으로 재배분하지 않는다.

### 4.7 R60 — 지역 경제·산업

<font style="font-weight:bold">입력 원본:</font> 지역별 경제 관측·산업활동·교역, 자원 생산 실적, 행성 경제 직접값.

`경제관측`은 대상·기간·지표·수치·단위·통화·가격 기준·자료 범위·값 상태·근거·출처를 갖춘다. GDP의 명목/실질/미분류는 별개 지표로 관리하고, 입력 편의를 위한 연간 광폭 화면은 같은 원본에서 파생한다.

`산업활동`, `지역간교역`, `자원생산`은 별도 사실 유형으로 유지한다. 자원의 매장량과 생산량을 같은 값으로 합치지 않는다. 생산량의 단위·기간이 불명확하면 원문을 보존하고 계산 대상에서 제외한다.

행성 경제의 직접 설정값은 기존 `11_행성_연간지표`의 경제 행에서 이관한다. 인구 행은 R20에 둔다. 지역 합산·채택·성장률 계산은 새 지표 정의에 따라 재구현한다. GDP, 무역 거래액, 자원 생산액을 합쳐 ‘경제력 총합’을 만드는 식은 추가하지 않는다.

### 4.8 R70 — 행성·지역 자연환경·자원

<font style="font-weight:bold">입력 원본:</font> 행성 물리·환경 기본값, 지역 환경 관측, 자원 존재·매장·품질·이용 가능성.

`행성기본값`에는 `property_id`, 원문값, 계산값, 단위, 산출법, 설정 상태, 출처, 채택 여부·근거를 둔다. 원문 반경과 지름 기준 반경, 원문 표면적과 타원체 계산면적은 서로 다른 근거를 가진 기록으로 남긴다.

역법 규칙의 원본은 C00이다. 기존 행성 시트에 있는 역법·시간값은 C00 참조 또는 원문 근거 연결로 처리하되, 세계관의 물리적 설명은 보존한다. 면적·육지율 등 미정값을 0으로 바꾸거나, 명확한 승인 없이 계산값을 정본으로 승격하지 않는다.

자원 생산 실적의 원본은 R60이다. R70에는 생산량을 별도 수동 원본으로 두지 않는다. 생산/매장 통합 비교가 필요하면 H90에서 결합해 R70↔R60 순환 import를 피한다.

### 4.9 N10 — 연방 기본정보·국가이력

<font style="font-weight:bold">입력 원본:</font> 연방 기본정보, 시점별 국호·헌정국체·수도 이력.

`국가기본`, `국호이력`, `헌정국체이력`, `수도이력`을 둔다. `nation-cog-1`과 기존 한국어·엘룬·영어 표기·HEX·출처·설정 상태를 유지한다. C00의 국가식별목록은 ID와 중립적인 목록 표시용이며, 연방의 공식 표기와 시점별 국호의 원본은 N10이다.

수도는 R10 지역 ID, 헌정체제의 제도 운영은 N20의 관련 자료와 연결한다. 실제 재임자·황실·통치영토를 이 파일의 새로운 원본으로 복제하지 않는다. 기본정보 첫 화면에 여러 분야를 모두 결합하고 싶다면 H90의 국가 상세 화면으로 이동하는 링크를 제공한다.

### 4.10 N20 — 연방 정치·행정·선거

<font style="font-weight:bold">입력 원본:</font> 기관·직위, 모든 공직 임기, 기관구조 이력, 정당·직책·계파·지도부·정당관계, 선거제도·선거·부문·결과·선거구·계보.

정치 파일은 필수 관계가 많으므로 이번에 억지로 다시 여러 독립 파일로 쪼개지 않는다. 입력 화면에서는 `기관·재임`, `정당·지도부`, `선거·결과`의 작업 단위로 접근시킨다. 자동 계산·검증 열은 접거나 분리한다.

다음 구별을 반드시 계승한다.

- 기관과 기관장 직위, 선출직 공직자와 선거권자 역할.
- 정식 재임, 권한대행·직무대행, 승계, 보궐·재선거.
- 전체 의석, 이번 선거 대상 의석, 부문별 배분 의석, 당선 의석, 선거 후 보유의석.
- 후보표·정당표 등 표종과 각각의 유효표 분모.
- 선거제도 개정판과 실제 선거의 적용 제도.
- 인물 기본정보와 공직/당직별 이력.

<font style="font-weight:bold">황제 재위도 공직 임기 원본은 N20에 둔다.</font> N30의 황실 신분·계승권은 다른 사실이다. 인물 이름은 N30의 인물 제공표를 가져온다. 선거권자·종교 대표 관련 직위가 종교와 관계된다는 이유만으로 원본을 N70으로 옮기지 않는다.

기존의 확정 의석·득표·순위 계산은 유지하되, 현실 정치 추천·예측 또는 미작성 세계관 선거의 자동 결과 생성은 추가하지 않는다. 정기 주기·임기 규칙이 존재해도 실제 기록이 없으면 일정 후보와 역사 실적을 구별한다.

### 4.11 N30 — 연방 인물·황실·계승

<font style="font-weight:bold">입력 원본:</font> 통합 인물 마스터, 친족관계, 황실 신분, 계승권·순위·지명 이력.

이 파일의 인물 마스터는 황족만을 뜻하지 않는다. 기존 공직자·후보자·정당 지도부를 연결하는 모든 `person_id`의 입력 원본을 맡는다. 같은 이름의 다른 인물은 별도 ID를 유지하고, 생몰일을 모르더라도 정밀도를 조작하지 않는다.

친생·입양·기타 법적 관계, 승계권·순위·지명·황태자녀 여부를 독립 필드로 유지한다. 신분과 권리를 자동으로 추론하지 않는다. `term_id`, `event_id`, 관련 기관 등 외부 참조는 보존한다.

<font style="font-weight:bold">순환 연결 방지 규칙:</font> N20은 N30의 인물 표를 읽지만, N30이 다시 N20의 재위 표를 실시간으로 읽지 않는다. N30의 외부 `term_id` 존재·기간 일치 검사와 황제 재위 결합 조회는 H90에서 수행한다. N30에서는 해당 검사 상태를 `통합 검증 대상`으로 표시하며, 이를 ‘정상’으로 오인하게 만들지 않는다. 외부 원본으로 이동하는 하이퍼링크는 가능하며 데이터 import와 구별한다.

### 4.12 N40 — 연방 인구·사회

<font style="font-weight:bold">입력 원본:</font> 국가 직접 인구 관측·인구구성·사회지표. 지역별 관측의 원본은 R20/R30이다.

`국가인구관측`에는 기존 국가 연간 인구를 이관한다. `국가사회지표`와 필요한 인구구성 구조는 빈 상태로 준비한다. 국가 인구 직접값과 지역 합산값은 구별하고 채택 규칙을 둔다.

국가 집계에는 R50의 해당 시점 통치범위와 R20의 동일 기준 인구를 사용한다. 영역이 일부이거나, 등록인구 귀속·기간 기준이 맞지 않거나, 지역 통계가 불완전하면 완전 국가합계로 채택하지 않는다. 교육·가구 등 사회지표는 대상 인구와 분모를 지정한다. 고용 실적의 경제적 원본은 N50에 두고 이 파일에 다시 입력하지 않는다.

### 4.13 N50 — 연방 경제·재정

<font style="font-weight:bold">입력 원본:</font> 국가 직접 GDP와 경제·재정·물가·고용·무역 등 국가 단위 관측. 기존 자료가 없는 항목은 빈 구조다.

기존 명목·실질·미분류 GDP와 통화·가격 기준·출처를 계승한다. 인구와 경제를 한 파일에서 모두 입력하던 구조를 분리하고, 1인당값에는 N40의 적합한 인구를 참조한다. 채택 근거·정의·루트·시점이 맞지 않으면 비율을 계산하지 않는다.

국가 직접 경제값과 R60 기반 지역 집계값은 같은 값으로 덮어쓰지 않는다. 재정은 세입·세출·수지·채무 등 의미와 기간이 다른 지표를 구별하고, 실적이 없는 셀은 비워 둔다. 기존 GDP를 새로 만든 재정·무역 수치의 근거로 역산하지 않는다.

### 4.14 N60 — 연방 문화·언어

<font style="font-weight:bold">입력 원본:</font> 국가 차원의 문화·언어 지위·공용어·제도·정책·문화유산 관련 이력. 문화·언어 정의는 C00, 지역별 분포는 R30이다.

`국가문화관계`, `언어지위이력`, `문화제도이력`의 최소 스키마를 마련한다. ID·범위·기간·관계/지위·법적 또는 설정 근거·상태·출처가 필요하다. 원문 문서의 실제 내용이 없으면 제도명·시행연도·비율을 만들어 넣지 않는다.

국가의 대표 문화와 주민 다수 문화, 법정 공용어와 다수 모어는 서로 다르다. 한 값을 다른 값의 자동 대리 지표로 사용하지 않는다.

### 4.15 N70 — 연방 종교·교무

<font style="font-weight:bold">입력 원본:</font> 국가와 종교의 관계·법적 지위, 교단 조직·교무 역할·적용 이력. 종교 기본 분류는 C00, 지역별 신앙 분포는 R40이다.

`국가종교관계`, `교단조직`, `교무이력`을 준비한다. 종교·종파와 교단 법인·기관은 같은 개체가 아니므로 `religion_id`와 교단/기관 식별자를 구별한다.

종교 관련 인물이 국가 공직을 맡은 사실은 N20의 공직 임기, 그 사람 자체는 N30의 인물 원본이다. N70은 관련 ID와 교무상 관계만 보존한다. 정치 파일과 종교 파일의 양방향 import가 필요해지는 조회는 H90에서 결합한다.

### 4.16 H90 — 통합 열람·검증

<font style="font-weight:bold">역할:</font> 실제 원자료를 입력하지 않는 읽기 중심의 통합 진입점이다. 사용자가 조정할 수 있는 값은 조회조건·필터·검증 실행 설정 등으로 제한한다.

필수 화면은 `전체 파일 목차`, `연방 통합연표`, `지역 상세 조회`, `국가 분야별 요약`, `행성 대비 비교`, `통합 변동연표`, `교차 참조 검증`, `미해결 충돌·결정 대기`이다. 기존 `83_연방_통합연표`의 정치·경제·황실·수도·헌정·사건 정보가 새 체계에서도 조회되는지 기능별로 대조한다.

각 결과에는 대상·루트·기년·시점·조회 상태 필터·자료 완전성·원본 파일/행 이동 링크를 표시한다. 입력 자료가 없으면 0 또는 ‘문제 없음’이 아니라 `자료 없음/미입력`으로 표시한다.

H90의 통합 검증 결과를 다시 C00이나 분야 파일에서 실시간 import하지 않는다. 필요한 곳에는 H90 검증 링크를 제공한다. 자동 변동연표를 수동사건 원본에 다시 기록하지 않는다.

## 6. 공통 데이터 규약

### 6.1 ID와 이관 추적

기존 `planet.1`, `nation-cog-1`, 지역·인물·기관·선거·임기·사건 등의 ID를 유지한다. 영문 철자·접두어·대소문자를 임의 통일하지 않는다. 코드에 이름·상위 경로를 넣거나 행 번호 수식으로 ID를 발급하지 않는다.

새로 필요한 이관행 ID는 <font style="font-weight:bold">한 번 생성해 고정 저장</font>하고, 재실행 시 같은 `legacy_locator`의 기존 대응 ID를 재사용한다. UUIDv7 등 기존 초안의 전역 ID 제안은 보존하되, 이번 이관을 이유로 모든 기존 ID를 강제 교체하지 않는다. 신규 ID 발급의 구체 방식은 C00 네임스페이스에 기록하고, 적용 환경에서 생성·고정·충돌 검사가 되는 방식을 선택한다.

`legacy_locator`는 원본 파일 ID + 탭 ID/탭명 + 원래 행/기존 레코드 ID + 스냅샷 식별자로 구성한다. 행 번호는 출처 위치일 뿐 새 개체의 영속 ID가 아니다. 분리 이관된 한 원본 행은 여러 대상 레코드와 연결될 수 있다.

기존 동일 문자열 ID가 실제로 다른 개체를 뜻하면 덮어쓰기하지 않는다. 원본 네임스페이스를 함께 보존하고 충돌 해결표를 만든다. 확인되지 않은 동일 인물·동일 사건을 자동 병합하지 않는다.

### 6.3 시간·역법

첨부 공통 기준에는 다음이 기록되어 있다. 실행 시 해당 원본의 변경 여부를 재확인하되, 확인 없이 과거 대화의 오래된 값으로 되돌리지 않는다. [S1]

- 1년은 48개월, 1개월은 30일, 날짜 수는 1,440일이며 윤년이 없다.
- 민간·행정 1일은 86,400초다.
- 매년 24월 30일 종료 후, 25월 1일 시작 전에 별도 432초 보정구간이 있다. 별도 날짜로 세지 않는다.
- 구형 제2기와 현행 제2기는 별도 기년 판본으로 보존한다. 기존 자료의 구형 3000년/현행 2000년 경계 설명을 일괄 비례축약이나 연도 자동치환으로 바꾸지 않는다.

세계관 날짜에 Excel/Sheets의 서력 `DATE` 함수를 적용하지 않는다. `era`, `year`, `month`, `day`, `precision`을 구조화하고, 필요 시 `calendar_phase`, `second_of_day`, `correction_second`를 추가한다. 일반 일 단위 작업 때문에 모든 표에 시·분·초를 강제로 노출하지 않는다.

정확한 기간은 `[시작, 종료)`로 처리한다. 연도만 아는 종료는 연간 열람에서 그 연도를 포함하되, 실제 종료일을 48월 30일로 확정해서 저장하지 않는다. 내부 필터용 상·하한을 만들면 ‘추정 경계/조회 경계’임을 별도 필드로 표시한다. 종료 미상은 무기한 지속과 구별하고, 현행 동작인 ‘기록된 시작연도만 표시’를 보존한다.

기년을 넘는 기간에는 시작 기년과 종료 기년을 각각 보관할 수 있어야 한다. 대응이 확정되지 않은 두 기년 사이의 절대 날짜 계산은 하지 않는다. `제3기 0년`을 일반적인 입력 오류나 결측 0으로 처리하지 않는다.

범위·추정·연도만 알려진 자료의 같은 해 내부 순서를 임의 확정하지 않는다. 날짜 필드 정규화는 정보의 정밀도를 높이는 창작이 아니다.

### 6.4 관계와 적용기간

다대다 관계는 연결 1건당 1행으로 표현한다. 상위 지역·전신 정당·관련 인물 ID 여러 개를 쉼표 문자열 하나에 넣는 구조를 원본으로 삼지 않는다. 기존 메모에 그렇게 저장된 값은 원문을 보존하고, 분리 가능한 경우에만 구조화한다.

지역 관계, 통치관계, 기관구조, 수도·국호·황실·친족·승계에는 적용기간과 루트가 필요하다. 기존에 기간이 없던 정적 마스터를 이관한다고 존재 시작연도를 창작하지 않는다.

집계 대상 수를 상수 `22`로 고정하지 않는다. 기존 기본값이 22개 대륙권이더라도, 대상 지역 목록·판본·적용시점을 기준으로 실제 집합을 확인한다. 단순히 행 수가 같은지뿐 아니라 <font style="font-weight:bold">대상 ID 집합이 일치하는지</font> 검사한다. 폐기·미래·다른 루트의 지역이 포함되지 않아야 한다.

기준시점·기준이 맞는 경우 `기초인구 + 출생 - 사망 + 유입 - 유출 + 기타증감`과 말기인구를 대조하는 잔차 검증은 가능하다. 잔차를 없애기 위해 미작성 출생·사망·이동값을 역산해 입력하지 않는다.

### 7.3 직접값·계산값·채택값

```text
direct_value      직접 설정/원문에서 온 값
calculated_value  명시한 산식과 적합한 원자료로 만든 값
selected_value    적용한 채택 규칙으로 선택한 값
selection_rule    직접 우선 / 완전 합계 / 미채택 등
selection_reason  근거와 결정/검증 상태
coverage_status   전체 / 부분 / 정의 불일치 / 자료 없음 등
```

동일 수치를 세 번 수동 입력하라는 뜻이 아니다. 직접값만 원본으로 입력하고 계산·채택은 재현 가능한 파생값으로 만든다. 입력값과 산출값의 차이는 보여주되 원문을 고치지 않는다.

### 7.4 경제·비율

명목 GDP 증감률, 실질 경제성장률, 미분류 GDP 증감률은 구분한다. 전년 자료가 없으면 ‘직전 관측 대비’와 ‘연간 성장률’을 혼동하지 않는다. 전기값이 0이면 0으로 나눈 결과를 감추지 말고 계산 불가 사유를 표시한다. 통화·가격 기준이 다른 관측을 자동 비교하지 않는다.

비율은 0~1 저장을 기본으로 하되 원본 표현과 환산 내역을 보존한다. `73.45%`와 `0.7345`는 같은 비율 표현이지만, 숫자 `73.45`를 근거 없이 자동 해석하지 않는다. 상호배타적이고 완전한 구성비만 합계 100%를 검사한다. 복수응답 자료에는 같은 검사를 강제하지 않는다.

인구 가중평균은 동일 정의·시점의 적합한 분모가 존재할 때만 계산한다. 표시 반올림과 저장 정밀도를 구분한다. 큰 인구·GDP의 자릿수를 임의로 잘라 저장하지 않는다. 플랫폼의 숫자 정밀도 범위를 초과하는 원문 숫자가 발견되면 원문 문자열과 계산용 근사값을 분리하고 정확도 제한을 알린다.

## 8. 파일 간 연결 설계

### 8.1 원칙

공통 기준과 분야별 제공표를 참조하고, 한 파일의 같은 외부 표를 셀마다 다시 가져오지 않는다. 외부 표는 로컬 참조 탭에 한 번 받아 내부 조회·드롭다운·집계에서 재사용한다. 중간 파일이 단순 전달만 하는 구조는 제거한다.

Google은 `IMPORTRANGE`에 처음 연결할 때 접근 허용이 필요하며, 연결 사슬과 순환 참조를 줄이도록 안내한다. 외부 파일 변경과 결과 반영 사이의 지연도 존재한다. [G1] 파일 분리는 자동적인 성능 향상을 뜻하지 않는다. 외부 참조는 인터넷 왕복을 거치며, 과도한 열린 범위와 긴 참조 사슬은 별도 관리가 필요하다. [G2]

### 8.4 연결 실패·캐시·갱신 표시

`IFERROR(외부참조,0)`나 빈 문자열로 연결 오류를 숨기지 않는다. `권한 미허용`, `원본 미접근`, `범위 없음`, `스키마 불일치`, `갱신 대기`, `정상 확인`, `오래된 스냅샷`을 구별한다. 연결 실패가 종속 계산의 실제 0으로 번지면 안 된다.

`NOW()`가 변했다고 외부 데이터가 갱신되었다고 표시하지 않는다. 마지막 성공 시각을 자동 기록하려면 실제 읽기·검증 후 기록하는 구현이 필요하다. 그런 구현이 없으면 마지막 수동 확인 시각과 `source_revision`을 보여주고 자동 갱신 검증이 아님을 명시한다.

순수 수식만으로 ‘마지막 성공한 값’을 영구 보존한다고 주장하지 않는다. 값 캐시를 쓰려면 쓰기 절차·캐시 판본·오래됨 표시를 별도로 갖추고 원본으로 오인하지 않게 한다.

### 8.5 권한과 공개 범위

새 파일은 임의로 ‘링크가 있는 모든 사용자’에게 공개하지 않는다. 숨김 탭·셀 보호·제공표는 입력 실수를 줄이기 위한 장치이며 비밀정보 접근 경계를 대신하지 않는다. 외부 편집자에게 제공할 공개본이 필요하면 원본과 별개의 값 중심 배포본을 검토한다.

연결 허용은 필요한 파일 쌍에 대해서만 실행하고 권한 상태를 기록한다. 기존 원본의 공유 범위를 바꾸는 방식으로 연결 문제를 우회하지 않는다.

### 9.2 표와 서식

입력 원본과 제공표에는 병합 셀·장식용 제목행·중복 헤더를 넣지 않는다. 사람이 보는 시작/조회 화면의 제한된 병합은 가능하다. 한국어 표시명과 영속 기술 필드 ID는 데이터 사전에서 대응시키고, 파서가 임의 `Unnamed` 열에 의존하지 않게 한다.

기존 표기 순서와 원문 문자열을 보존한다. 지역 파일의 로마자·엘룬 순서와 국가 파일의 언어 열을 통일할 때 열 위치뿐 아니라 실제 값의 의미를 대조한다. HEX는 원본 문자열을 보존하고 컬러칩을 자동 표현하되 잘못된 HEX를 임의 색상으로 대체하지 않는다.

입력/참조/계산/검증 영역은 색상뿐 아니라 열 제목·그룹·안내로 구별한다. 필수 열은 앞쪽에, 고급 근거·기술 열은 뒤쪽 접이식 그룹에 둔다. 필수 정보 누락을 막겠다고 모든 메타데이터를 매 행 수동 입력하도록 만들지 않는다. 출처 묶음·기본 단위 등은 명시된 기본값을 사용할 수 있다.

수식 영역은 의도치 않은 덮어쓰기를 막고, 외부 제공 범위는 사용자 입력처로 노출하지 않는다. 고정 행·열, 필터, 열너비·줄바꿈, 큰 숫자·비율·단위 표시를 실제 화면에서 확인한다. 임의의 샘플 데이터를 운영 원본에 넣어서 보기 좋게 만들지 않는다.

## 10. 입력 용량·계산량·확장 절차

### 10.1 용량 산정

고정된 500/1,000행 수치를 단순히 더 큰 상수로 바꾸는 것을 개선 완료로 보지 않는다. 각 표마다 `현재 실데이터 행 수`, `확보 입력행`, `계산/검증/제공표 끝행`, `예상 증가단위`, `경고 기준`, `확장 방법`을 기록한다.

예를 들어 지역 22개를 매년 하나씩 입력하면 1,000행은 완전한 45년분까지만 담는다. 정당 10개가 50회 선거에 각각 한 결과행을 가지면 500행이 된다. 이 산술 예시는 실제 입력 밀도가 정해졌다는 뜻이 아니라, 표마다 필요한 용량이 다르다는 점검 기준이다.

실제 사용할 데이터량과 조회 창을 기준으로 필요한 범위를 확보한다. 원자료 기간 전체와 현재 화면의 조회 가능 기간은 구별한다. 여러 기년을 장기 보존할 수 있더라도 조회는 페이지/기간 창으로 처리할 수 있으며, 조회 제한을 넘어선 원자료를 삭제하면 안 된다.

### 10.2 필수 확장 동작

확장 시 다음을 <font style="font-weight:bold">하나의 작업 묶음</font>으로 갱신한다.

1. 입력 표 및 필수 기본값·드롭다운.
2. 계산·조회에 쓰는 범위.
3. 중복/참조/기간/합계 검증 범위.
4. 이름 지정 범위·제공표·연결 계약·행 수 메타데이터.
5. 소비 파일에서 자료를 받는 범위 및 요약.

환경에서 자동 확장이 검증되면 사용한다. 자동 확장이 충분하지 않으면 `용량 확장`의 명시 절차나 최소 스크립트를 구현한다. 수동 방식도 가능하지만 ‘한 곳만 늘리면 다른 범위가 조용히 남는 상태’는 허용하지 않는다.

일상 운영에 예약·트리거·Apps Script를 기본으로 추가하지 않는다. 필요성이 확인된 최소 기능만 구현하고 실행 방법·권한·재실행 안정성·오류 복구를 문서화한다. 외부 서비스나 인증정보를 임의로 추가하지 않는다.

### 10.3 성능 확인

시험용 데이터로 소규모·현재 예상 규모·확장 규모를 비교한다. 첫 열기, 입력 후 해당 분야 조회, 통합연표 갱신, 외부 원본 변경 반영을 각각 확인한다. 자동 측정 수단이 없으면 수동 측정임을 적고 확인 시각·조건·결과를 남긴다.

빈 수식행을 실데이터처럼 수십만 셀 복사하지 않는다. 동일 수식을 늘어놓는 대신 실제 활성 범위·표 참조·배열 계산을 검토한다. 다만 지원 여부와 동작을 확인하지 않은 함수를 일괄 적용하지 않는다. 외부 참조의 전열 범위와 불필요한 중복 import도 줄인다. [G2]

## 11. 이관 방법과 보존 기준

### 11.1 세 층으로 보존

- <font style="font-weight:bold">V1 원본/백업:</font> 원문·기존 수식·서식·과거 구조의 보존 근거.
- <font style="font-weight:bold">이관 명세:</font> 원본 레코드/필드가 어느 V2 레코드/필드로 갔는지 설명하는 대응표.
- <font style="font-weight:bold">V2 운영:</font> 실제 입력 원본과 검증된 파생 기능.

V2 화면에서 숨기거나 정리한 정보라도 첫 두 층에서 정확히 역추적할 수 있어야 한다. `V1에 있으니 됐다`는 이유로 실제 사용해야 하는 필드를 V2에서 누락하지 않는다.

### 11.2 탭·필드·레코드 단위 대응

첨부 `02_기존87개시트_이관대응표.csv`와 부록 A를 초기 탭 대응표로 사용한다. WORK는 실행 시 실제 열을 읽어 다음 필드 대응표를 추가 작성한다.

```text
source_file_id / source_sheet_id / source_sheet_name / source_field
source_type / source_role(input|formula|display|validation)
target_file_code / target_table / target_field / transform_rule
preservation_location / change_reason / approval_or_rule / validation_result
```

새 구조에 즉시 맞지 않는 원문 필드는 `원문보존` 보조표에 원본 위치·필드명·값·형을 보존한다. 이를 영구적인 미분류 쓰레기통으로 쓰지 않고, 각 필드에 보존 이유와 향후 처리 상태를 부여한다. 자유서술 날짜를 구조화할 수 없다고 지우거나 임의의 날짜로 채우지 않는다.

### 11.3 실제 데이터와 빈 서식 구별

표 첫 열에 ID가 있는 행뿐 아니라, ID 없이 다른 입력 필드가 채워진 불완전 행도 점검한다. 이를 빈 행으로 삭제하지 않는다. 반대로 미리 채워진 `FALSE`, 수식의 빈 문자열, 기본 서식, 미선택 드롭다운, 안내행은 실제 세계관 관측으로 세지 않는다.

출처·메모·링크·텍스트도 데이터다. 값이 0인지 비어 있는지, 원문 문자열이 숫자인지, 수식 결과인지 구별해 저장한다. XLSX 호환 래퍼의 저장 결과를 원문 수치로 승격하지 않는다.

### 11.4 중복 통합

완전히 동일한 사실로 확인된 행은 하나의 원본 레코드로 묶되, 모든 `legacy_locator`와 출처를 유지한다. 충돌값·상태 차이·판본 차이·범위 차이가 있으면 후보 레코드를 각각 남기고 채택 여부를 분리한다.

이관 전후 단순 행 수는 달라질 수 있다. 따라서 `총 입력행`, `보존한 원본 레코드`, `통합된 동일 사실`, `필드 분리로 증가한 레코드`, `미분류 보존`, `누락`의 숫자를 별도로 보고한다. <font style="font-weight:bold">누락 0건</font>은 그 분해 내역으로 입증해야 한다.

### 11.5 수식·조회 재구현

원본 수식은 그대로 복사할 대상이 아니라 기능의 근거다. 원본·새 식·입력 조건·기대 결과·오류 처리의 대응을 남긴다. 시트번호/열문자 치환만으로 구조 변경을 처리하지 않는다.

기존 정당 지도부·황실·친족·승계 등 입력이 비어 있어도 기능은 이관 대상이다. ‘현재 값 없음’을 이유로 조회·검증 기능을 없애지 않는다. 기존 검증 실패를 숨기거나 과거의 통과 문구를 새 결과로 복제하지 않는다.

### PH0. 원본 확인·스냅샷·진행 기반

두 원본을 읽고 생성/수정 권한을 확인한다. 원본 복사본·XLSX 대조본·메타데이터를 보존하고 파일 ID 및 체크섬을 기록한다. `실행상태.json`, `파일레지스트리.csv`, `원본변경차이표`를 만든다. 원본에 운영상 영향을 주는 변경은 하지 않는다.

<font style="font-weight:bold">종료 조건:</font> 현재 원본 목록과 백업 위치를 제시할 수 있고, 첨부본과 실행본의 차이가 식별되어 있다. 접근 불가 시 임의 파일을 대신 원본으로 고르지 않고 그 부분을 `원본 미검증`으로 분리한다.

### PH1. 필드 대응·원본 책임·예외 확정

87개 초기 매핑에 실제 추가 탭/열을 반영한다. 모든 필드의 이관 위치와 계산/보존 구분을 정한다. 공통 ID·날짜·상태·출처·통계 규칙과 제공 계약을 작성한다. 중복 후보와 미해결 정본 문제를 `결정대기표`에 올린다.

<font style="font-weight:bold">종료 조건:</font> 미지정 필드 0개, 같은 사실의 중복 입력 원본 0개, 순환이 없는 기본 연결 설계. 미해결 설정은 값 보존·계산 제외 방식으로 명확하게 처리되어 있다.

### PH2. 16개 파일 생성·공통 기반·소형 연결 시험

네이티브 요소를 계승할 파일은 대응 원본의 별도 네이티브 복사본에서 정리·분리하는 경로를 우선한다. 원본 자체를 손대지 않고, 복사본에서만 불필요한 기존 탭·호환구조를 정리한다. 완전히 신규인 빈 분야 파일은 새 구조로 만들되, 실행 환경의 Google Sheets 생성·네이티브 표 처리 절차를 따른다. XLSX로 내보냈다가 다시 올리는 방식만으로 칩·수식·검증이 보존된다고 가정하지 않는다.

운영 폴더와 16개 파일을 생성하고 즉시 실제 ID를 레지스트리에 기록한다. 생성한 파일 ID가 V1과 다른지 쓰기 전에 검사한다. C00 코드북/출처/기준과 R10 지역 원본을 먼저 구축하고, N30 인물 마스터의 빈 구조를 준비한다.

시험 사본에서 `C00 → R10 → R20 → H90`의 작은 자료 흐름과 `N30 → N20 → H90`의 이름/임기 흐름을 시험한다. 작은 시험이 통과하기 전에 모든 분야의 수식을 대량 배포하지 않는다.

<font style="font-weight:bold">종료 조건:</font> 실제 독립 파일 16개, 식별/목차/기본 스키마 존재, 기본 import 권한·스키마·변경 반영·오류 표시 검증. 아직 내용 이관 전인 파일은 `구조 준비`로 표시한다.

### PH3. 지역 분야와 공유 사실 이관

R10 지역·관계·시설·교통망을 마무리한다. R70 물리/환경/자원, R20 인구, R30 사회문화, R40 종교, R50 소속, R60 경제를 의존 순서에 따라 이관한다. 국가 영토 원자료도 이 단계에서 R50과 대조한다. 공통 분류·출처·수동 사건은 C00에 연결한다.

<font style="font-weight:bold">종료 조건:</font> 지역 36개 탭의 실제 자료와 구조에 처리 결과가 있고, 국가 영토의 이중 원본이 제거되어 있다. 부분합·중복지역·물리 충돌·값 상태를 시험한다.

### PH4. 연방 분야 이관·기존 기능 재구현

N10 국가기본, N30 인물/황실, N20 정치, N40 인구사회, N50 경제, N60 문화언어, N70 종교교무 순으로 필요한 원본을 이관하고 참조를 연결한다. 실제 작업 순서는 데이터 의존에 따라 일부 병행할 수 있으나, 같은 파일에 동시에 서로 다른 쓰기를 하지 않는다.

<font style="font-weight:bold">종료 조건:</font> 국가 51개 탭이 처리되었고, 기존 기능 대응표에 대체 위치·시험 결과가 있다. N60/N70 미작성 분야는 빈 스키마 완료이지 정본 데이터 입력 완료가 아니다.

### PH5. 통합 열람·교차 검증·공통 오류 처리

H90에 통합연표·지역 상세·행성 대비 비교·변동연표·교차 참조 검사를 구축한다. N30 계승의 황제 임기 참조, N20의 인물 참조, C00 사건의 대상 존재, R50 통치범위와 통계의 일치 등을 검사한다. 파일별 연결 graph와 제공 계약을 검증한다.

<font style="font-weight:bold">종료 조건:</font> H90이 원본을 읽기만 하고, 모든 필수 조회가 실제 원본으로 역추적되며, 연결 실패·자료 없음·초안·부분집계가 구분된다.

### PH6. 회귀·경계·용량·재실행 시험

부록 B/검증 CSV의 시험을 전용 TEST 사본에서 실행한다. 정상 입력, 잘못된 입력, 경계일, 루트 분기, 데이터 부족, 원본 변경, 연결 끊김, 범위 확장, 재실행 중복 방지, 복구를 점검한다. 결과에는 실제 확인값과 증거 위치를 기록한다.

<font style="font-weight:bold">종료 조건:</font> 도입한 오류는 의도대로 탐지되고, 정상 자료는 오탐 없이 조회된다. 미해결 정본 충돌은 별도 경고로 남아 있으며 기술적 실패와 혼동하지 않는다.

### PH7. 최종 차분 이관·릴리스 고정·전환 준비

PH0 이후 V1이 변경되었는지 재확인한다. 변경분이 있으면 정해진 이관 규칙으로 추가 반영하고 영향받은 기능만 재시험한다. V2도 수정되었다면 양쪽 변경을 자동 덮어쓰지 않고 대조한다.

모든 제공 계약의 `release_id`를 맞추고, 다른 릴리스 자료가 섞이면 H90에 혼합 상태를 표시한다. 운영 파일의 TEST 자료를 제거·검증하고 최종 체크섬/레지스트리/보고서를 만든다.

<font style="font-weight:bold">종료 조건:</font> 기술 구축·검증 완료 상태와 미해결 설정 목록이 명시되고, 사용자가 접근할 실제 파일/폴더 링크가 제공된다. 기존 외부 링크·자동화·V1 사용을 강제로 끊지 않는다. 별도 운영 전환 승인이 없는 경우 `V2 기술 구축 완료 · 운영 전환 대기`로 보고한다.

## 13. 중단·재개·재실행 규칙

WORK는 단계마다 실제 산출물을 저장한 뒤 체크포인트를 남긴다. 한 번의 실행으로 끝나지 않아도 이미 완료한 파일을 다시 생성하거나 V1 전체를 매번 처음부터 읽지 않도록 한다.

```text
실행상태.json 필수 내용
project_id / plan_version / execution_id / phase
source_snapshot_ids / source_modified_times / source_fingerprints
created_files[file_code -> spreadsheet_id, parent_id, title]
migration_batch_ids / migrated_legacy_locators
completed_tasks / pending_tasks / blocked_tasks
test_results / dependency_graph_version / last_checkpoint
```

재개 시 이 상태와 실제 파일 ID를 확인하고, 원본 수정 시각·구조 차이를 검사한 뒤 영향 범위만 재검토한다. 같은 `legacy_locator`를 이미 이관했다면 중복 삽입하지 않고 대조한다. ‘파일이 이름상 존재한다’는 이유로 다른 프로젝트 파일을 재사용하지 않는다.

문제가 발생하면 정확한 파일·탭·범위·원인·영향·다음 처리항목을 기록한다. 접근 불가한 원본, 정본 결정이 필요한 값, 기술적 수식 실패를 각각 구별한다. 하나의 미정 설정 때문에 안전하게 수행 가능한 구조 이관까지 모두 중단하지 않는다. 다만 ID 혼동·원본 손상 위험·중복 덮어쓰기 위험은 해당 쓰기를 즉시 차단한다.

### 14.2 시험 방법

시험 자료는 운영 자료와 분리된 TEST 사본에 입력한다. 시험용 인물·정당·지역·연도는 명시된 `TEST-` ID와 `test_run_id`를 사용하며 실제 세계관 사실로 등록하지 않는다. 기대값은 시험 전에 정하고, 실제 결과·스크린샷/범위/검사 로그를 남긴다.

예시 계산 시험에서는 시험 인구 100·200의 합계 300, 시험 GDP 1,000과 인구 100의 1인당값 10처럼 사람이 검증 가능한 작은 수치를 사용한다. 기존 원본의 과거 ‘시험 통과’ 기록을 새 시험 실행으로 간주하지 않는다.

부록 B 및 `03_검증_체크리스트.csv`의 <font style="font-weight:bold">84개 시나리오</font>를 기본 시험 집합으로 사용한다. CSV의 결과 칸은 현재 모두 `미실행`이다. WORK가 실제로 확인한 항목만 통과로 변경한다.

### 14.3 최종 인수 기준

아래 조건을 모두 만족해야 `V2 기술 구축·검증 완료`로 보고할 수 있다.

1. 운영 파일 16개가 실제로 존재하고 원본 V1 파일 ID와 겹치지 않는다.
2. 기존 87개 탭 및 실행 시 발견된 추가 탭/필드에 처리 결과가 있고, 근거 없는 데이터 누락은 0건이다.
3. 기존 고정 ID와 원문값·상태·출처·시간 정밀도가 보존되며, 변경/통합은 대응표로 설명된다.
4. 같은 사실의 중복 수동 원본, 순환 import, V1에 남은 운영 의존이 없다. 보존용 링크는 별도로 허용·표시한다.
5. 조회·계산·검증의 기존 기능이 대응되고, 빈 데이터 상태와 실제 0이 구별된다.
6. 새로 도입된 기술적 P0/P1 결함이 0건이다. 기존 정본 충돌·자료 부족은 별도 목록과 안전한 처리 규칙을 갖는다.
7. 입력 범위 초과를 탐지하고 확장 후 입력·계산·검증·제공·소비 범위가 함께 작동한다.
8. TEST 자료의 운영 유입이 없고, 재실행해도 중복 생성되지 않는다.
9. 실제 네이티브 Sheets에서 수식·연결·드롭다운·색상·조회·보호 범위를 검증했다.
10. 원본 백업, 이관/필드 대응, 기능 대응, 연결 계약, 실행상태, 시험 결과, 복구 절차, 실제 파일 링크를 제공했다.

온라인 권한 허용·네이티브 재계산·표본 시험이 끝나지 않았다면 `구조 이관 완료 / 온라인 검증 미완료`처럼 상태를 분리해 보고한다. 저장된 값이 정상처럼 보이는 것을 전체 검증 완료로 대신하지 않는다.

## 15. 복구와 운영 전환

### 15.1 복구 원칙

V1은 건드리지 않았으므로 최초 회귀 대상이 된다. V2에서 장애가 나면 신규 입력을 멈추고 현재 V2 상태도 별도 보존한 뒤 영향 파일·릴리스·최근 변경을 식별한다. V2에서만 추가된 입력은 별도 차분 파일로 추출해 유실을 막는다.

정상 릴리스의 V2 복사본으로 복구하거나, 필요한 경우 사용자가 V1을 다시 기준으로 사용할 수 있도록 안내한다. V2 변경을 V1에 역방향으로 자동 덮어쓰지 않는다. 연결 주소를 이전 파일로 되돌릴 때는 레지스트리·소비 계약·릴리스를 함께 점검한다.

### 15.2 전환 시점

기술 완료 후 사용자가 V2를 운영 기준으로 선택하면 신규 입력처를 V2로 일원화한다. V1은 보존본으로 취급한다. 기존 외부 소비자·에디터·스크립트·문서 링크의 전환은 목록을 작성하고 명시적으로 요청된 범위에서만 실행한다.

원본 파일 이름에 ‘보존용’을 붙이거나, 원본 편집 권한을 바꾸거나, 원래 링크의 수식을 변경하는 일은 이 계획의 기본 권한에 포함되지 않는다. V1을 보존한다는 말과 원본에 읽기 전용 권한을 강제한다는 말은 다르다.

## 17. 최종 보고서 형식

WORK 최종 응답에는 다음을 포함한다.

- `기술 구축·검증 완료 / 일부 완료 / 온라인 검증 대기 / 운영 전환 대기` 중 실제 상태.
