# 엘리스 프라우셰크트 세계관 볼트 구조개편 마이그레이션 매니페스트

> [!important] 실행 계약
> 이 문서는 <font style="font-weight:bold">실제 Work 마이그레이션의 실행 기준표</font>다.
> 구조개편 최종설계안에서 확정된 A~H 결정을 변경하지 않는다.
> Work는 본 매니페스트에 없는 대규모 구조변경을 임의로 추가하지 않는다.
> `HOLD` 항목은 사용자의 추가 결정 또는 명시된 검증이 끝나기 전에는 이동·통합·삭제하지 않는다.
> 실제 삭제는 원칙적으로 금지하며, 구식·placeholder·사료는 우선 보존 격리한다.

# 0. v1.1 최종 감사 반영 요약

본 수정본은 구조 설계 A~H를 변경하지 않고 <font style="font-weight:bold">실행 안전성</font>을 보강한다.

주요 수정:

1. 부모 `SUBTREE` 이동 후 자식 FROM 경로가 사라지는 실행충돌 제거.
2. 제1·2·3기 역사와 역사 지도를 `연대기`/`역사지도`로 분리.
3. `신지구.md`, 라리셴베르크 마스터, 제1·2·3기 국가 트리, 시각자료 등 누락항목 추가.
4. 연방 헌법 폴더를 현행 본문과 개정·QA 자료로 세분.
5. Obsidian 코어 Templates와 Templater 설정 경로 변경을 명시적 실행항목으로 추가.
6. `카테고리 → 분야` 전환 시 폴더명 자동복제 규칙 제거.
7. `정본상태` 허용값을 `canon | provisional | draft | archival`로 통일.
8. B루트의 `연속성` 메타데이터 규칙 추가.
9. 날짜 역전·형식 오류 QA 추가.
10. Quartz `90-볼트 운영` 공개 제외, 80/98 공개정책 HOLD 추가.
11. `mirror_assets.py`/`fix_links.py`의 basename 평탄화에 대비한 미디어 충돌 사전검사 추가.
12. 활성 예약작업·자동화 프롬프트의 구 경로 갱신 절차 추가.
13. 현재 Drive 재검토 결과, 최종설계안은 이미 세계관 루트로 이동되어 있으므로 기존 `P4-004G`를 제거.
14. 최종설계안과 본 매니페스트는 마이그레이션 전체 기간 동안 루트에 고정하고, Phase 8에서만 `90-볼트 운영/03-작업계획·감사보고/볼트 구조개편/`으로 함께 이동.

# 1. 매니페스트 작성 기준

## 1.1 식별 기준

- 명시 가능한 핵심 파일은 <font style="font-weight:bold">개별 파일 단위</font>로 기재한다.
- 역사·지역·기관처럼 내부 구조가 이미 잘 잡힌 대량 폴더는 `SUBTREE` 단위로 기재한다.
- Work 실행 시 각 `SUBTREE` 하위 파일 목록을 실행 직전에 다시 스냅샷하여 누락 여부를 검증한다.
- Drive ID가 변하지 않는 <font style="font-weight:bold">move/rename</font>을 우선하며 복사→삭제 방식은 특별한 이유가 없으면 사용하지 않는다.

## 1.2 정본 판단

- `(보존용·구식 문서)` → `archival`
- 현행 A루트 + `복원여부:false` + 초안/보존 표시 없음 → 기본적으로 현행 정본 후보로 취급
- `복원여부:true` → `기원상태: restored`; <font style="font-weight:bold">정본상태와 별개</font>
- 복원 경고가 있으면서 현행성 불명확 → `HOLD`
- B루트는 `80-대체루트·비정사` 내부에서 별도 정본 체계를 가진다.

## 1.3 파일 내용 변경 제한

구조 마이그레이션 단계에서 허용되는 내용 수정은 다음뿐이다.

1. Frontmatter 스키마 변환
2. 경로형 위키링크/Markdown 링크 경로 치환
3. `permalink`, `aliases` 추가
4. MOC·index의 경로 업데이트
5. 복원정보 조건부 템플릿 반영

설정 내용 자체의 창작·재해석·정합성 봉합은 <font style="font-weight:bold">별도 정본화 작업</font>이다.

# 6. 전역 Frontmatter 변환 규칙

## 6.1 `카테고리` → `분야`

기존 `카테고리` 값을 그대로 이름만 바꾸지 않는다.

예:

```yaml
카테고리: 05-종교
```

를 단순히:

```yaml
분야: 05-종교
```

로 바꾸지 않는다.

대신 의미론적으로:

```yaml
분야:
  - 종교
```

처럼 변환한다.

## 6.2 적용범위

목표 트리를 기준으로 설정한다.

```yaml
적용범위:
  - 공통
```

또는

```yaml
적용범위:
  - 신계
  - 라리셴베르크
```

국가 전용이면:

```yaml
적용범위:
  - 신계
  - 라리셴베르크
  - 엘리시움 신성제국 연방
```

## 6.3 복원문서

```yaml
기원상태: restored
복원여부: true
복원원문문서명:
복원원문최초작성일:
복원원문최종수정일:
```

원문정보를 확인할 수 없으면 추정 날짜를 만들지 않고 `미상` 또는 빈 값으로 둔다.

## 6.4 물리경로 필드 금지

다음 Frontmatter는 새로 만들지 않는다.

```yaml
폴더:
경로:
물리위치:
```

## 6.5 정본상태 허용값

새 체계에서 `정본상태`는 다음 네 값만 사용한다.

```yaml
정본상태: canon | provisional | draft | archival
```

- `pending`은 사용하지 않는다.
- 사용자 결정 대기 자체는 매니페스트의 `HOLD` 처리상태로 표현한다.
- 정본 후보이나 아직 승인되지 않은 문서는 `provisional`을 사용한다.

## 6.6 연속성

대체루트가 존재하는 문서는 필요할 경우 다음 선택 필드를 사용한다.

```yaml
연속성:
  - A루트
```

또는

```yaml
연속성:
  - B루트
```

`80-대체루트·비정사`의 B루트 문서에는 `연속성: [B루트]`를 필수로 한다.
A루트는 기본 연속성이 명확한 경우 전 문서에 기계적으로 추가하지 않아도 된다.

# 7. 내부 링크 일괄 변환 규칙

다음 모든 형식을 스캔한다.

```markdown
[[폴더/파일]]
[[폴더/파일|표시명]]
[[폴더/파일#헤딩]]
[[폴더/파일#헤딩|표시명]]
[[폴더/파일#^블록ID]]
![[폴더/이미지.png]]
[표시명](../상대경로/파일.md)
```

## 변환 원칙

- FROM→TO 매핑에서 <font style="font-weight:bold">경로 부분만</font> 치환한다.
- `|표시명`, `#헤딩`, `#^블록ID`는 유지한다.
- 파일명이 변경되는 `RENAME` 항목에 한해서 파일명도 치환한다.
- 파일명 단독 위키링크는 동명이인 충돌이 없으면 불필요하게 경로형으로 바꾸지 않는다.
- 이동 전후 동일명 파일이 둘 이상 생기면 해당 링크를 명시 경로형으로 바꾼다.

# 8. Quartz 마이그레이션 규칙

## 8.1 permalink

고정 URL 우선 문서:

- 루트 `index.md`
- 공통설정 index
- 통합 용어집
- 신계 index
- 라리셴베르크 index

- 지역 목록

- 초월자
- 제국도교
- 엘리시움 연방 index/국가 기본설정
- 연방 헌법 대표문서

## 8.2 aliases

기존 공개 URL이 확인 가능한 경우 옛 경로를 `aliases`로 보존한다.

현재 Quartz의 `AliasRedirects`를 이용한다.

## 8.3 제국도교 URL·영문명

- `Taoism` 사용 금지.
- 제국도교의 `道`는 <font style="font-weight:bold">제국이 나아가야 할 길·질서·지향</font>을 뜻한다.
- 정식 영문명은 별도 언어 정본화 전까지 자동 확정하지 않는다.
- permalink slug에도 `taoism`을 사용하지 않는다.

# 10. Phase 공통 완료 조건

한 Phase는 다음이 모두 참이어야 완료다.

- [ ] 대상 파일/폴더가 TO에 존재
- [ ] 의도하지 않은 중복 파일 없음
- [ ] 옛 경로 참조가 해당 Phase 범위에서 0
- [ ] broken wikilink 수가 기준선보다 증가하지 않음
- [ ] 이미지 임베드 오류 증가 없음
- [ ] Dataview 오류 증가 없음
- [ ] Quartz build 성공
- [ ] 핵심 페이지 렌더 정상
- [ ] HOLD 항목이 자동 처리되지 않음
- [ ] Git diff가 해당 Phase 예상 범위 안에 있음

# 11. 롤백 원칙

각 Phase 전에 Git commit 또는 tag를 만든다.

예시:

```text
pre-vault-migration-p1
vault-migration-p1-complete
pre-vault-migration-p2
vault-migration-p2-complete
```

문제가 발견되면 <font style="font-weight:bold">해당 Phase만 롤백</font>한다.
전체 볼트를 한 번에 원복해야 하는 단일 거대 커밋 방식은 사용하지 않는다.
