# 엘리스 프라우셰크트 세계관 볼트 구조 개편 최종 설계안

> [!important] 문서의 지위
> 이 문서는 2026-09-29~30에 수행한 세계관 볼트 구조 조사와 사용자 검토·승인 결과를 통합한 <font style="font-weight:bold">볼트 구조 개편 최종 설계 기준</font>이다.
>  
> 이 문서는 <font style="font-weight:bold">어떤 구조와 원칙으로 개편할 것인지</font>를 확정한다.
> 실제 파일 이동·이름 변경·링크 치환·메타데이터 일괄 수정은 별도 <font style="font-weight:bold">마이그레이션 매니페스트</font>를 작성·검토한 뒤 Work에서 단계적으로 수행한다.
>  
> 본 문서 확정만으로 실제 파일은 이동하지 않는다.

---

# 1. 개편 목적

현재 《엘리스 프라우셰크트》 세계관 볼트는 초기 구축기의 분류 체계 위에서 장기간 확장되면서 다음 문제가 누적되었다.

1. `00-1-용어 및 설정집`이 단순 용어집을 넘어 세계관 본체 저장소처럼 사용되고 있다.
2. `01-신계 차원` 등 <font style="font-weight:bold">세계·차원 기준 분류</font>와 `마법·종교·정부·언어` 등 <font style="font-weight:bold">주제 기준 분류</font>가 같은 레벨에서 혼재한다.
3. 실제 실체 폴더와 핵심 정본 문서의 위치가 서로 어긋나는 사례가 있다.
4. 엘리시움 신성제국 연방은 이미 하나의 독립 서브트리를 필요로 할 정도로 설정량이 커졌다.
5. `복원여부` 하나만으로 문서의 기원과 현재 정본 지위를 동시에 표현하기 어렵다.
6. `카테고리`가 의미 분류와 물리적 폴더 위치를 혼용한다.
7. 경로가 포함된 인링크와 Quartz 공개 URL을 폴더 이동과 분리해 관리할 필요가 있다.
8. 구식·비정사·복원·현행 정본의 물리적 위치와 메타데이터 관계를 명확히 할 필요가 있다.

개편의 최종 목표는 다음과 같다.

> **물리적 위치는 설정의 실제 소속을 나타내고,  
> 메타데이터는 설정의 의미와 정본 지위를 나타내며,  
> 통합 용어집과 MOC는 탐색을 담당하고,  
> 공개 URL은 파일 경로와 독립적으로 유지한다.**

# 2. 사용자 승인 결정 A~H

## A. 공통설정의 적용범위

<font style="font-weight:bold">확정: 전 차원 공통설정으로 운용한다.</font>

`00-세계관 공통설정`은 신계·구계·혼돈계를 가로질러 적용되는 개념과 규칙을 저장한다.

대표 후보:

- 차원 구분과 우주론
- 대전이
- 차원류
- 차원 장막
- 차원안전·차원재난
- 전 차원에 공통 적용되는 존재론
- 공통 능력·에너지 개념
- 세계관 공통 정치·사회 분류체계
- 기술·역사 작성 표준 및 메타 분류

개별 세계 또는 특정 지역에만 적용되는 설정은 해당 세계·지역 트리로 내려간다.

---

## B. `00-1-용어 및 설정집` 개편

<font style="font-weight:bold">확정: 기존 `00-1-용어 및 설정집`은 해체·재정의한다.</font>

기존처럼 세계관 본체를 저장하는 공간으로 사용하지 않는다.

신규:

```text
00-세계관 공통설정/
├─ index.md
├─ 00-세계관 통합 용어집.md
└─ 분야별 공통설정/
```

`00-세계관 통합 용어집.md`는 <font style="font-weight:bold">집중형 용어 허브</font>로 사용한다.

용어집에는:

- 표준 용어
- 1~3문장 간단 설명
- 분야
- 정본상태
- 상위·하위개념
- 상세 정본문서 링크

만을 둔다.

상세한 설정 자체는 독립 정본문서에서 관리한다.

---

## C. 엘리시움 신성제국 연방의 위치

<font style="font-weight:bold">확정: 당분간 라리셴베르크의 국가·정치 트리 아래에 둔다.</font>

기본 위치:

```text
01-신계 차원/
└─ 02-라리셴베르크/
   └─ 03-국가·정치/
      └─ 엘리시움 신성제국 연방/
```

향후 설정량과 세계관 확장에 따라 신계 직속의 별도 중심국가 계층이 필요해질 경우 그때 재분할한다.

현재 단계에서는 별도의 추가 계층을 미리 만들지 않는다.

---

## D. 보존·구식 문서의 물리적 격리

<font style="font-weight:bold">확정: `98-보존·구식 문서`로 물리적 격리한다.</font>

예:

```text
98-보존·구식 문서/
├─ 00-세계관 공통/
├─ 01-신계/
├─ 02-구계/
├─ 03-혼돈계/
├─ 10-라리셴베르크/
├─ 20-엘리시움 연방/
└─ 90-기타 사료/
```

원칙:

- 삭제하지 않는다.
- 현행 정본과 같은 위치에 두지 않는다.
- 사료·계승 관계 추적에 계속 사용한다.
- 현행 문서가 구식 문서를 규범적·정본적으로 참조하는 경우 감사 대상이 된다.
- 필요한 경우 원래 위치의 MOC에서 보존본으로 링크할 수 있다.

## E. 복원 문서 메타데이터 체계 개편

<font style="font-weight:bold">확정: 문서의 ‘기원’과 ‘현재 정본 지위’를 분리한다.</font>

### 1. 정본상태

```yaml
정본상태: canon | provisional | draft | archival
```

- `canon`: 현행 정본
- `provisional`: 잠정 정본·검토 중 현행안
- `draft`: 초안
- `archival`: 사료·보존용

### 2. 기원상태

```yaml
기원상태: original | restored
```

- `original`: 현 체계에서 새로 작성
- `restored`: 과거 원문·구문서를 복원하여 출발

### 3. 기존 `복원여부`

마이그레이션 기간에는 기존 자동화·템플릿 호환을 위해 유지할 수 있다.

```yaml
복원여부: true | false
```

그러나 장기적으로 <font style="font-weight:bold">정본 판정 근거로 사용하지 않는다.</font>

따라서 다음 조합도 정상이다.

```yaml
정본상태: canon
기원상태: restored
복원여부: true
```

즉 과거 문서를 복원해 시작했더라도 현재 지속적으로 갱신되고 검토되어 현행 정본이 된 문서를 정확하게 표현할 수 있다.

### 4. 복원 원문 메타데이터

복원 문서는 가능한 경우 다음을 기록한다.

```yaml
복원원문문서명: "원문 문서명"
복원원문최초작성일: YYYY-MM-DD
복원원문최종수정일: YYYY-MM-DD
```

원문 날짜가 정확하지 않을 경우 허위 정밀도를 만들지 않고 알려진 범위를 기록한다.

### 5. 템플릿 조건부 본문

`기원상태: restored` 또는 호환기간 중 `복원여부: true`인 경우에만 본문 시작부에 다음 섹션을 출력한다.

```markdown
### 과거 문서 계승 및 복원 정보

- 복원 원문 문서명: ...
- 원문 최초 작성일: ...
- 원문 최종 수정일: ...
```

복원 문서가 아니면 해당 섹션 자체를 출력하지 않는다.

구현 단계에서 Templater 조건문을 사용한다.

개념 예시:

```templater
<%* if (
  tp.frontmatter["기원상태"] === "restored" ||
  tp.frontmatter["복원여부"] === true
) { %>
### 과거 문서 계승 및 복원 정보

- 복원 원문 문서명: <% tp.frontmatter["복원원문문서명"] ?? "미기입" %>
- 원문 최초 작성일: <% tp.frontmatter["복원원문최초작성일"] ?? "미상" %>
- 원문 최종 수정일: <% tp.frontmatter["복원원문최종수정일"] ?? "미상" %>
<%* } %>
```

> [!note]
> 위 코드는 설계 예시이다. 실제 Work 적용 시 현재 설치된 Templater 버전과 템플릿 실행방식을 기준으로 문법을 검증한 뒤 반영한다.

## F. B루트·대체루트·비정사

<font style="font-weight:bold">확정: 현행 정본 A루트와 물리적으로 분리한다.</font>

신규:

```text
80-대체루트·비정사/
├─ index.md
└─ 01-신계 B루트/
```

향후 다른 분기·IF·폐기되지 않은 대체연속성이 생기면 같은 계층에 추가한다.

원칙:

- A루트 정본과 동일한 충돌 대상으로 취급하지 않는다.
- B루트의 설정이 A루트로 유입되는 경우 명시적 승격 절차가 필요하다.
- B루트 문서에는 적용루트 또는 연속성 메타데이터를 명시한다.

예:

```yaml
적용범위:
  - 신계
연속성:
  - B루트
정본상태: canon
```

여기서 `canon`은 <font style="font-weight:bold">B루트 내부의 정본</font>을 의미한다.

## G. Quartz 공개 URL 정책

<font style="font-weight:bold">확정: 물리적 파일 경로와 공개 URL을 분리한다.</font>

현재 Quartz 구조에서 다음 기능을 활용한다.

- `permalink`
- `aliases`
- `AliasRedirects`

### 주요 정본·마스터·MOC

공개 가치가 높고 장기간 참조될 문서는 `permalink`를 부여할 수 있다.

```yaml
permalink: /stable/public/path
```

물리적 폴더가 이후 다시 바뀌더라도 공개 URL은 유지한다.

### 기존 공개주소

파일 이동으로 기존 URL이 바뀌는 문서는 필요에 따라 옛 URL을 `aliases`에 등록한다.

```yaml
aliases:
  - /old/public/path
```

Quartz의 AliasRedirects를 이용하여 옛 URL에서 새 URL로 리디렉션한다.

### 적용 우선

- 세계관 메인 index
- 주요 세계·행성 MOC
- 대전이·신인류·초월자 등 핵심 정본
- 라리셴베르크 핵심 마스터
- 엘리시움 연방 국가 마스터
- 연방 헌법
- 제국도교 등 주요 설정

초안·감사자료·작업계획·마이그레이션 자료에는 고정 permalink를 강제하지 않는다.

### 원칙

> 물리적 경로 = 볼트 내부 구조  
> 의미적 위치 = YAML 메타데이터  
> 공개주소 = Quartz permalink/aliases

세 계층을 서로 독립시킨다.

## H. `카테고리` 폐지·`분야` 전환

<font style="font-weight:bold">확정: 기존 `카테고리`는 새 체계에서 `분야`로 대체한다.</font>

현재처럼 폴더명을 그대로 복제하는 `카테고리` 사용을 중단한다.

신규:

```yaml
분야:
  - 종교
  - 신학
  - 정치
```

`분야`는 의미론적 분류이며 실제 폴더 경로를 표현하지 않는다.

물리적 폴더 경로는 Frontmatter에 별도 기록하지 않는다.

필요한 경우 Obsidian/Dataview의 파일 메타정보로 실제 경로를 동적으로 취득한다.

마이그레이션 중 기존 `카테고리`는 즉시 삭제하지 않고:

1. 값 분석
2. `분야`로 변환
3. 참조 Dataview·템플릿 수정
4. 사용처가 사라진 것을 확인
5. `카테고리` 제거

순으로 단계적으로 퇴역한다.

# 3. 최종 정보구조 원칙

## 3.1 물리적 위치는 실제 소속을 따른다

파일의 위치는 다음 우선순위로 결정한다.

1. 전 차원 공통인가
2. 특정 차원인가
3. 특정 천체·지역인가
4. 특정 국가·기관·종교 등 실체인가
5. 그 실체 내부의 어느 기능·분야인가

“용어이기 때문에 용어집에 둔다”는 기준은 사용하지 않는다.

---

## 3.2 문서 역할과 폴더 역할을 구분한다

권장 문서유형:

```yaml
문서유형: master | concept | entity | reference | index | report | template | archive
```

### master
분야 전체 또는 실체 전체의 상위 정본.

### concept
하나의 개념·원리·현상을 설명하는 문서.

### entity
국가·기관·종교·천체·인물처럼 특정 실체를 설명하는 문서.

### reference
용어집·목록·표·색인·표준 사전.

### index
MOC·탐색 허브.

### report
분석·평가·전략·감사·검토 보고서.

### template
작성 템플릿.

### archive
사료·구식 문서.

---

## 3.3 Index/MOC는 탐색장치이며 자동으로 정본이 아니다

주요 대분류에는 `index.md`를 둔다.

역할:

- 분야 설명
- 핵심 정본 링크
- 하위 구조 안내
- 미작성·검토 필요 상태 표시
- 관련 MOC 교차링크

`index.md`에 설정 내용을 과도하게 중복하지 않는다.

# 4. 최종 최상위 폴더 구조

```text
세계관/
│
├─ index.md
│
├─ 00-세계관 공통설정/
│  ├─ index.md
│  ├─ 00-세계관 통합 용어집.md
│  ├─ 01-우주론·차원/
│  ├─ 02-대전이·차원재난/
│  ├─ 03-존재·종족/
│  ├─ 04-능력·마법·에너지/
```

# 8. 제국도교 명칭·개념 원칙

## 8.1 정본 의미

`루벨리니온 제국도교`의 <font style="font-weight:bold">도교</font>는 현실 중국의 도교(Taoism)를 의미하지 않는다.

구성 의미는 다음과 같다.

- <font style="font-weight:bold">제국(帝國)</font>: 제국
- <font style="font-weight:bold">도(道)</font>: 제국이 나아가야 할 길·질서·지향
- <font style="font-weight:bold">교(敎)</font>: 그 길을 가르치고 신앙·규범으로 구성하는 종교

따라서 세계관 문서·용어집·번역·URL에서 `제국도교 = Taoism`으로 등치하지 않는다.

## 8.2 영문명

최종 영문 정식명은 별도 언어·용어 정본화에서 결정할 수 있다.

그 전까지 다음 원칙만 확정한다.

> <font style="font-weight:bold">영문 번역에 `Taoism`을 사용하지 않는다.</font>

임시 설명이 필요한 경우 의미를 풀어쓴 번역을 사용할 수 있으나 이를 정식 영문명으로 자동 확정하지 않는다.

# 11. 내부 링크 마이그레이션 원칙

파일 이동은 <font style="font-weight:bold">마이그레이션 매핑표</font>를 단일 기준으로 수행한다.

다음 형식을 전수 검사한다.

```markdown
[[폴더/파일]]
[[폴더/파일|표시명]]
[[폴더/파일#헤딩]]
[[폴더/파일#헤딩|표시명]]
[[폴더/파일#^블록ID]]
![[폴더/이미지.png]]
[표시명](../상대경로/파일.md)
```

## 11.1 경로형 위키링크

기존 경로 부분만 새 경로로 치환한다.

헤딩·블록ID·표시명은 변경하지 않는다.

## 11.2 파일명 단독 위키링크

파일명이 변경되지 않고 충돌이 없다면 불필요하게 수정하지 않는다.

## 11.3 파일명 변경

파일명 자체를 변경하는 경우에만 전역 참조를 함께 수정한다.

## 11.4 이미지·첨부파일

임베드 경로가 포함되어 있으면 동일 매핑 원칙을 적용한다.

## 11.5 이동 후 검증

반드시 검사:

- 옛 경로 잔존
- 존재하지 않는 링크
- 동명이인 파일 링크 모호성
- 헤딩 참조
- 블록 ID
- 이미지 임베드
- Markdown 상대링크
- Dataview 경로 쿼리
- Quartz 렌더 결과

# 12. 문서 이동 처리유형

마이그레이션 매니페스트에서는 각 항목을 다음 중 하나로 분류한다.

## MOVE
내용 변경 없이 새 위치로 이동.

## MOVE+META
이동과 함께 Frontmatter를 새 표준으로 갱신.

## RENAME+MOVE
파일명 정리와 이동을 동시에 수행.

## CONSOLIDATE
복수 파일의 역할이 중복되어 통합이 필요한 경우.

## NEW-MASTER
현재 대표문서가 비어 있거나 역할을 수행하지 못해 새 마스터를 만드는 경우.

## ARCHIVE
`98-보존·구식 문서`로 격리.

## HOLD
정본 충돌·정의 불명확 등 사용자 결정 후 처리.

## KEEP
현 위치 유지.

# 13. 현재 확인된 주요 예외 처리 원칙

## 13.1 `마법 기본설정.md`

- 내용은 풍부함.
- 기원은 복원문서.
- 새 구조에서는 공통설정의 마법·에너지 계층 후보.
- 단순 이동과 정본승격을 동일한 작업으로 처리하지 않는다.
- `기원상태: restored`를 유지하면서 현재 정본 여부를 별도로 판정한다.

## 13.2 `류아블론츠 성계 정보 설정.md`

- 복원 기원이지만 최근까지 수치가 갱신됨.
- `기원상태: restored`와 `정본상태`를 분리해야 하는 대표 사례.
- 천체 실체 폴더로 이동하는 방향은 확정하되 canon 여부는 내용 검증 결과로 기록한다.

## 13.3 `엘리시움 신성제국 연방.md`

- 현재 대표문서 역할을 수행하지 못하는 placeholder 상태.
- 새 국가 트리에 `index.md`와 `00-국가 기본설정.md`를 새로 구축한다.
- 기존 placeholder는 즉시 삭제하지 않고 대체 완료 후 처리한다.

## 13.4 `현대 엘루닉어 기본설정.md`

- 현재 내용이 비어 있거나 불충분한 상태.
- 언어 폴더 재배치 후 정식 마스터 구축 대상으로 표시한다.

## 13.5 구 엘루닉어 단어집

- 복원·임시 상태.
- 현행 표기법을 자동 대표하지 않는다.
- 사료 보존 후 별도의 정본 단어집을 생성한다.

# 14. 운영·출판 구조

## 14.1 볼트 운영자료

```text
90-볼트 운영/
├─ 00-템플릿/
├─ 01-수정기록/
├─ 02-일지·브레인스토밍/
├─ 03-작업계획·감사보고/
├─ 04-자동화·스크립트/
└─ 05-출판·폰트·운영자산/
```

세계관 설정과 편집·관리 메타자료를 물리적으로 분리한다.

## 14.2 Quartz 프로젝트

Quartz 퍼블리시 프로젝트는 세계관 정본 트리와 별도 프로젝트로 유지한다.

볼트 개편 시 Quartz 쪽에서 수정해야 하는 것은:

- content 미러링 경로
- 링크 보정 스크립트
- Asset 미러링
- permalink/aliases
- Explorer/Breadcrumb 동작
- draft·비공개 처리
- 배포 스크립트의 경로 의존성

이다.

Quartz 소스 자체를 세계관 설정 폴더 안으로 이동하지 않는다.

# 18. 각 Phase 완료조건

각 Phase는 다음 조건을 충족해야 다음 단계로 넘어간다.

1. 대상 파일이 매니페스트 위치에 존재한다.
2. 원래 파일이 중복 잔존하지 않는다. 단, 의도적 보존본 제외.
3. 경로형 내부링크가 갱신되었다.
4. 깨진 위키링크가 증가하지 않았다.
5. 이미지 임베드가 유지된다.
6. Dataview 오류가 새로 발생하지 않는다.
7. Quartz build가 성공한다.
8. 공개 핵심페이지가 정상 접근된다.
9. 예상 밖 정본 충돌이 발견되면 자동 해결하지 않고 HOLD 처리한다.

# 19. 최종 설계 원칙 요약

## 저장 위치

> <font style="font-weight:bold">공통 → 차원 → 천체·지역 → 실체 → 기능·분야</font>

## 의미분류

> `카테고리`가 아니라 <font style="font-weight:bold">`분야`</font>

## 정본관리

> <font style="font-weight:bold">현재 지위 = `정본상태`</font>  
> <font style="font-weight:bold">문서의 기원 = `기원상태`</font>

## 복원문서

> restored라고 해서 archival인 것은 아니다.

## 용어집

> 상세 설정 저장소가 아니라 <font style="font-weight:bold">집중형 색인 허브</font>

## 대체루트

> A루트 정본과 물리적으로 분리.

## 보존자료

> 삭제하지 않고 `98-보존·구식 문서`로 격리.

## 링크

> 이동 매핑표를 기준으로 경로형 인링크를 일괄 갱신.

## Quartz

> 파일 위치와 공개 URL을 `permalink`·`aliases`로 분리.

## 제국도교

> 현실의 Taoism과 무관하다.  
> ‘제국이 나아가야 할 길(道)의 가르침·종교(敎)’라는 고유 개념으로 취급하며 영문명에 `Taoism`을 사용하지 않는다.
