## 1. 출발점과 전환 범위

### 1.1 현재 원격에서 확인한 출발점

조회한 main HEAD는 `943db96dda3fda0ee9f62e08b7909d89a91bd501`다. README는 T06의 합성 지도 선택까지 완료했다고 설명한다. 실제 PNG는 표시용이고, 실제 전체 식별 마스크 인수는 입력 대기다. 가져온 초안은 현재 세션에서만 유지되며 영구 저장·복원과 속성 편집은 후속 범위다. <font style="font-weight:bold">현재 상태를 완성된 웹 편집기로 가정하고 파일 저장 API만 바꾸면 안 된다.</font> [P1, P3]

T07 검색·라벨·패널 보완 → T08 기본 속성 편집·명령·Undo → T09 저장·복원이 기존 티켓의 선행 관계다. T10은 기본 지도 모드·집계이며 별도 완료 범위다. 로컬에 이후 구현이 있으면 실제 코드·검사와 대조해 해당 부분을 재사용하되, 원격만 보고 다시 만들지 않는다. [P4]

README의 ‘기존 작업 브랜치·Draft PR 유지/미병합’ 안내와 실제 PR #1의 병합 완료 상태가 다르다. 착수 시 로컬·원격·PR 상태를 대조하고 사용할 작업 기준을 기록한다. 과거 문구만 보고 오래된 브랜치로 강제 전환하거나 작업 트리를 초기화하지 않는다. [P6]

## 3. 보존할 데이터 계약

### 3.1 core와 데스크톱 관리 정보

현재 strict core에는 프로젝트·세계·데이터셋 ID, revision, 합성/세계 데이터 구분, 지역, 포함 관계, 대륙 소속, 전략지역권 관련 대륙, 팔레트, 인구 facts, 가져오기 문제, coverage가 있다. 저장 왕복은 이 전체를 비교해야 한다. 화면에 보이는 이름과 인구만 같다고 통과시키지 않는다. [P5]

현재 facts는 population만 허용한다. 값은 null 또는 0 이상 안전한 정수이며 null과 unknown은 함께 지정된다. 데스크톱 경로, 최근 파일, 창 크기, 요청 토큰, 캐시 키를 core에 덧붙여 strict 검증을 우회하지 않는다. [P5]

T08에 명시된 메모 등 현행 core가 담지 못하는 편집 항목은 <font style="font-weight:bold">저장 계약 결정이 필요한 차이</font>다. T08 구현 전에 다음 중 기존 승인 계약과 맞는 방법을 ADR로 정한다.

- 도메인 필드라면 버전이 있는 스키마 확장·이관과 이전 버전 읽기 검사를 마련한다.
- 별도 주석 문서라면 프로젝트 ID/지역 ID로 연결되는 버전 있는 부속 데이터로 관리하며 저장·복구·전달 범위에 포함한다.

메모를 화면에만 두거나 unknown 필드로 흘려보내고 T08 완료라고 보고하지 않는다. 기존 `0.1.0` 입력을 읽는 경로를 유지하며, 새 포맷의 구버전 앱 역호환 여부는 실제 지원 범위를 안내한다. 외피 버전 증가가 core 이관을 자동 해결하는 것은 아니다.

### 3.3 좌표와 선택

픽셀 좌표와 현행 타일 좌표 계약을 보존한다. 가로세로 비율로 위경도·행성 반지름·km²를 추정하지 않는다. `wrapX`가 미확인이면 끝점 사이를 자동 인접으로 연결하지 않는다. 표시 배율·DPR·패널 접기·줌 변화에도 같은 원본 지점의 ID는 같아야 한다. [P7]

클릭은 합성된 화면색이 아니라 검증된 원본 ID 데이터를 사용한다. 원본 타일 로딩 중에는 판정 중/실패/재시도를 표시하고 이웃의 지역을 대신 선택하지 않는다. source·mask revision·palette가 바뀌면 오래된 Worker 응답을 폐기한다. 한 픽셀 섬, 타일 경계, 마지막 부분 타일, 물/미할당/범위 밖을 별도 검사한다.

## 4. 타일·자산·저장 설계

### 4.1 자산의 종류를 분리한다

원본 마스터, 검증된 식별 타일·사전, 표시 타일, 썸네일, 파생 캐시는 같은 데이터가 아니다. 원본과 의미 데이터는 보존하고 파생 캐시는 다시 만들 수 있는 조건을 문서화한다. 식별 사전이나 재생성 불가능한 사용자 자산을 임시 캐시처럼 지우지 않는다.

각 필수 자산은 논리 ID, 버전, 해시, 크기, 역할, 상대 위치 또는 재연결 정보를 가진다. <font style="font-weight:bold">데이터셋·마스크 revision·팔레트·ID 사전의 호환성까지 검사</font>한다. 파일 해시가 맞아도 다른 마스크의 사전을 연결하면 정상 프로젝트가 아니다.

### 4.2 저장과 복구본의 자산 일관성

전체 자산을 매번 복사·재압축하는 대신, 바뀌지 않은 검증 자산을 참조하는 구조를 우선 검토한다. 이는 새 설계 후보이므로 부분 실패·보존 예산·정리 검사를 통과해야 채택한다.

저장 절차는 `변경 데이터와 필요 자산 준비 → 자산 검증 → 완성 manifest 기록 → 세대 게시 → 최신 포인터 변경`으로 한다. 실행 중 프로젝트와 보존된 모든 복구 세대가 참조하는 자산은 삭제 대상에서 제외한다. 자산 정리는 보존 세대 계산 후 수행하고, 실패한 정리가 마지막 정상 저장본을 망가뜨리지 않아야 한다.

저장 도중 자산 복사가 실패하거나 큰 출력 취소가 발생하면 이전 정상 세대를 유지한다. 최신 데이터 파일만 있고 타일이 없는 상태를 ‘저장 완료’로 게시하지 않는다. 오래된 복구본이 구형 마스크 버전을 참조하면 그 버전의 자산을 함께 복원하거나 명시적으로 차단한다.

### E. 필요한 성능 개선만 수행

PL-E1에서 동일 타일/뷰포트/조작 순서로 기존 웹·변경 웹·EXE를 비교한다. PL-E2는 병목이 입증된 부분만 타일 요청 중복 제거, 캐시 상한, 복사 감소, 표시 무효화, 대형 저장 분리로 보완한다. PL-E3에서 원래 ID·참조·마스크 정확성과 전후 자원을 재검사한다.

작은 표본 3회는 중앙값·범위·개별값을 제시하며 p95나 장시간 안정성으로 부르지 않는다. 기존 계획의 p95 클릭 100ms, 지도 전환 500ms 등은 <font style="font-weight:bold">과거 제안 목표</font>다. 이를 인수 기준으로 채택하려면 실제 기능·환경·충분한 반복 표본의 측정법을 먼저 명시한다. T10 지도 모드가 미구현이면 그 기능의 성능 PASS를 만들지 않는다. [P7]

전체 원본을 통째로 디코딩해 ‘EXE니까 처리된다’고 접근하지 않는다. 타일 캐시·Worker 전달 복사·GPU/CPU 메모리는 별개로 기록한다. GPU 수치를 얻지 못하면 추정/미측정으로 표기한다.

### F. 최종 회귀와 패키지

PL-F1은 소스·lockfile·설정·타일 생성 입력을 고정하고 전체 필요한 회귀를 실행한다. PL-F2는 새 경로의 무설치 폴더에서 실제 EXE·자산·Worker·편집·저장·재열기를 확인한다. PL-F3은 그 빌드와 패키지의 바이트/manifest 연결을 확인한 뒤 설치본·해시·실행 안내를 만든다.

배포물에는 허용된 데모만 포함하며 `reference/` 원문·사용자 세계관 마스터를 무단 번들하지 않는다. 원본·대형 자산은 사용자 프로젝트 또는 별도 승인 자산팩으로 전달한다. Python 전처리 결과물과 도구가 필요하다면 생성 출처·포함 범위·라이선스를 기록한다. 설치·제거·서명은 생성 성공과 별도 상태다.

### G. 실제 사용자 인수

PL-G1은 가능할 때 PL-R의 실제 일부 지역 편집 왕복을 검사한다. 전체 식별 마스크가 없으면 전체 세계 지도 인수는 BLOCKED_INPUT으로 남긴다. PL-G2는 완전 패키지 A→Drive→B→편집→Drive→A와 경량 패키지의 자산 재연결을 실제 검사한다. 양쪽 PC에 필수 자산이 우연히 남아 있는 상태만으로 완전 패키지 독립성을 증명하지 않는다.
