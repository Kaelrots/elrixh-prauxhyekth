# 행성 지도 에디터 — 실행 중인 Cloud Codex에 전달할 추가 지시문

작성일: 2026-10-02 · 패키지 버전: 2.0-draft.1  
대상: `Kaelrots/planet-map-editor`  
문서 상태: <font style="font-weight:bold">추가 지시·신규 개발계획 작성 완료. 이 문서를 작성한 Chat에서 코드 수정·커밋·빌드·배포는 수행하지 않았다.</font>

## 1. 전달 방법과 이번 실행 범위

이 파일과 같은 묶음의 `01_행성지도에디터_V2_개발계획서.md`, `02_V2_인수검증_추적표.md`, `03_근거와_기존계획_대조.md`를 <font style="font-weight:bold">현재 실행 중인 행성 지도 에디터 작업</font>에 함께 전달한다. 아래 지시문은 기존 EXE 전환을 취소하거나 새로운 프로젝트를 초기화하는 명령이 아니다.

- <font style="font-weight:bold">지금:</font> 기존에 승인된 EXE 전환을 계속하면서, 안전한 체크포인트에서 V2-00 현황 대조·계획 통합을 수행한다. 완료된 코드를 새 설계에 맞춘다는 이유로 갈아엎지 않는다.
- <font style="font-weight:bold">본격적인 후속 개발:</font> 사용자가 세 에디터 EXE 전환을 정리하고 행성 에디터 집중 개발을 시작하라고 지시하면, V2-01~V2-04의 첫 실사용 묶음부터 진행한다. 현재 작업에서 이미 후속 개발까지 명시적으로 승인되었다면 그 승인 범위 안에서 이어간다.
- <font style="font-weight:bold">전체 로드맵:</font> V2-05 이후는 계획에 등록하되 이번 문서 수신만으로 전부 동시 구현하지 않는다. 정본 변경·고위험 공간 편집·다른 저장소 수정은 별도 범위다.

사용자가 후속 착수를 승인했다면 정상적인 하위 티켓 전환마다 다시 질문하지 않는다. 필수 정보가 없거나 권한·정본·파괴적 변경 경계를 넘을 때만 해당 항목을 보류한다.

## 2. 그대로 전달할 명령 지시문

```text
현재 진행 중인 Kaelrots/planet-map-editor의 EXE 전환 작업에 아래 후속 요구사항과 첨부 V2 계획을 접수해라.

[목표]
행성 지도 에디터를 단순 지도 조회기가 아니라, 지도·목록·Inspector에서 지역 설정을 편집하고 승인된 JSON/Markdown 데이터에 안전하게 반영하는 세계관 저작 도구로 발전시킨다.
HOI4·Victoria 3·Europa Universalis V에서 참고할 지도 기반 선택·속성 편집·지도 모드·일괄 수정·객체 배치·연결망·검증 흐름을 요구사항으로 분해한다. 모든 게임의 최신 내장 에디터 기능을 검증 없이 완전 복제했다고 주장하지 마라.

[즉시 지킬 원칙]
1. 현재 진행 중인 수정·검사·저장을 강제로 중단하지 말고, 일관된 상태를 남길 수 있는 체크포인트에서 이 지시를 반영해라.
2. 현재 작업 디렉터리, 저장소 remote, 브랜치, HEAD, 미커밋 변경, 실제 실행 명령과 작업 소유자를 확인해라. 대상이 다른 에디터 저장소라면 그곳에는 적용하지 마라.
3. 실제 AGENTS.md, 현재 작업 상태·인계 기록, DESKTOP_MIGRATION_STATE.md가 존재하면 읽고, DEVELOPMENT_PLAN.md, TASKS.md/TASKS.json, docs/PROGRESS.md, docs/UI_UX_PLAN.md, docs/DATA_CONTRACTS.md와 현재 스키마·저장·렌더링 코드를 대조해라.
4. 제공된 경로나 상태 파일명이 실제 존재한다고 가정하지 마라. 없으면 대응 파일을 찾고 차이를 기록해라. 없는 계획 파일은 첨부본에서 확인하고, 첨부 접근도 안 되면 읽었다고 보고하지 마라.
5. 943db96dda3fda0ee9f62e08b7909d89a91bd501는 2026-10-02 Chat에서 확인한 원격 참고점이지 강제 복원 지점이 아니다. 실행 중 Cloud 작업의 후속 구현·미커밋 변경을 우선 보존해라.
6. git reset --hard, git clean -fd, 강제 푸시, 임의 브랜치 전환, 다른 작업자 변경 덮어쓰기, 무관한 의존성 일괄 교체를 하지 마라.

[EXE 전환과의 관계]
7. 기존 행성 EXE 계획에는 T07 검색·라벨·패널, T08 기본 편집·명령·Undo/Redo, T09 저장·복원이 포함되어 있다. 현재 이미 구현됐거나 구현 중인 부분을 V2라는 이유로 다시 만들지 마라.
8. 실행 외피와 렌더러를 재선정하지 마라. 확인된 원격 렌더러는 Canvas 2D + Worker OffscreenCanvas다. 실제 현재 코드와 ADR이 더 최신이면 이를 기록하고 존중해라. Electron/Tauri/WebGL/Rust 전환은 이 지시의 자동 작업이 아니다.
9. SHELL_READY, EDITOR_READY, RELEASE_READY_LOCAL, HANDOFF_VERIFIED를 분리해라. 창이 뜨거나 EXE 파일이 생성된 것만으로 편집·저장·Windows 실행·두 PC 인수를 통과 처리하지 마라.
10. Cloud 환경에서 Windows EXE 실행을 못 하면 해당 검사는 BLOCKED_ENVIRONMENT로 남겨라. 가능한 도메인·웹·codec 검사는 진행하되 Windows 검증을 대체했다고 하지 마라.

[이번에 수행할 V2-00]
11. 첨부 01·02·03을 읽고 현재 코드→기존 T 티켓→신규 V2 티켓→검사 근거 대응표를 작성해라. 코드 존재, 연결된 UI, 실행 검사, 실자료 인수의 상태를 따로 기록해라.
12. 기존 계획·TASKS·데이터 계약에 V2 링크와 추가 요구를 반영하되 기존 완료 기록·원래 인수 기준은 보존해라. V2-xx는 별도 ID로 추가하고 기존 T00~T23 번호를 바꾸지 마라. TASKS.json의 실제 형식부터 확인하고 형식을 임의 교체하지 마라.
13. 현재 작업자가 수정 중인 공통 상태 파일에는 병렬 작성자를 추가하지 마라. 하나의 담당자가 계획과 상태를 통합해라. 같은 내용의 진행 문서를 여러 개 유지하지 말고 정본 상태 파일을 명시해라.
14. 추가 계획을 접수했다는 짧은 보고와, 현재 EXE 관문·중복 방지 결과·다음 한 작업을 남긴 뒤 기존 승인 범위를 계속 수행해라.

[후속 첫 구현 묶음: 착수 승인 후 V2-01~V2-04]
15. 현행 strict 스키마·codec 위에 최소 Field Registry와 Inspector 어댑터를 연결해라. 기존 폼·명령·저장 서비스를 재사용하고 범용 엔진부터 새로 만들지 마라.
16. 이름·기존 별칭·인구·메모 중 실제 지원되는 필드로 시작하고, 새 필드는 버전 있는 스키마 이관 또는 검증된 부속 데이터 계약을 먼저 마련해라. 0, null, 빈 문자열, 필드 부재, 지원하지 않는 값의 의미를 섞지 마라.
17. 프로젝트 저장과 원본 문서 반영은 다른 상태로 표시해라. JSON/MD 연결은 필드별 단일 권위 원본과 Binding 계약을 정하고, 지도 선택→Inspector 수정→diff→승인→파일 기록→재열기를 연결해라.
18. 첫 문서 쓰기 대상은 합성 fixture와 격리한 샘플 폴더다. 실제 세계관 볼트 전체를 검색·변환·덮어쓰지 마라. 실자료 쓰기는 사용자가 지정·승인한 파일/폴더 범위에만 적용해라.
19. Markdown은 승인한 키/관리 구획만 수정한다. 자유서술·콜아웃·HTML·위키링크·DataviewJS·Templater·주석·기존 주소·수정횟수 관리 필드를 임의 재작성하거나 실행하지 마라.
20. 템플릿 개편 작업과 별도의 공통 YAML을 만들지 마라. 제공된 계획은 90-볼트 운영/00-템플릿/00-yaml 속성탭.md를 공통 양식 원본으로 지정한다. 실제 승인된 최신 원본과 필드 매핑을 확인하고, 미접근이면 합성 계약만 검증해라. 문서 ID와 Region ID를 임의로 동일시하거나 기존 ID를 교체하지 마라.
21. 문서를 읽을 때의 내용 해시를 저장하고, 기록 직전 다시 비교해라. 외부 변경은 충돌로 보존한다. 앱 내부의 Undo가 외부 사용자의 변경까지 덮어쓰지 않게 해라. 초기 단계는 한 문서 단위의 안전한 저장부터 완성해라.
22. MD 경로와 JSON 경로를 각각 독립적인 authoritative fixture로 검증한다. 같은 값의 MD·JSON 사본 둘을 동시에 독립 정본으로 두지 마라.
23. V2-01~V2-04와 기존 T07~T09의 필수 인수 기준을 검사한 뒤 첫 실사용 묶음을 보고하고 멈춰라. 전역 경제·역사·시설·교통·경계 브러시는 후속 티켓으로 남겨라.

[검증·보고]
24. 검사는 NOT_RUN/PASS/FAIL/BLOCKED_INPUT/BLOCKED_ENVIRONMENT/NOT_APPLICABLE을 구분한다. 합성 자료, 실제 일부, 전체 실자료, 웹, Windows native를 나눠라.
25. 변경 영향에 맞는 검사를 먼저 실행하고 통합 체크포인트에서 전체 필수 회귀를 수행해라. 문서만 바뀐 단계에서 전체 앱을 반복 빌드하지 마라. 실패를 숨기기 위해 검사 삭제·단언 완화·보안 해제를 하지 마라.
26. 파일·검사 명령·종료 코드·소스 및 입력 해시·남은 문제를 근거로 남겨라. 과거 통과 수치를 오늘 실행한 결과처럼 복사하지 마라.
27. 현재 Cloud 작업의 기존 commit/push/PR 권한을 넘지 마라. 이 지시만으로 main 병합·공개 배포·실사용 볼트 일괄 수정이 허용되는 것은 아니다.
28. 최종 보고는 현행 EXE 상태 / 반영된 계획 / 이번 구현 / 실행 검사 / 미검증·차단 / 실제 변경 파일 / 다음 한 작업으로 정리해라.
```
