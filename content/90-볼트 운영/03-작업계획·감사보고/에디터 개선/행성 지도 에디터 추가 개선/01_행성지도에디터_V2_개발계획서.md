## 0. 요약과 첫 인도물

### 0.1 최종 제품 목표

<font style="font-weight:bold">지도에서 대상 선택 → 관련 사실·문서 조회 → 구조화 편집 → 변경 영향과 diff 확인 → 승인한 원본에 저장 → 재열기·외부 변경 조정.</font>

기존 세계관의 지명·지역 계층·색상 식별·문서 체계를 유지하면서, 반복적인 설정 입력과 검증을 지도 중심 화면으로 모은다. HOI4·Victoria 3·EU5의 지도 저작 경험은 기능 분해의 참고 대상이며, 특정 게임의 규칙·지리 단계·자산·전용 파일 형식을 세계관 표준으로 강제하지 않는다.

### 0.2 첫 실사용 인도물: REGION_AUTHORING_ALPHA

전체 세계관 데이터베이스를 먼저 구축하지 않는다. 작은 검증 지도에서 다음 동작을 연결한다.

1. 지도·검색·목록이 동일한 지속 Region ID를 선택한다.
2. 현재 지원되는 이름·별칭·인구·메모를 Inspector에서 검증하고 편집한다.
3. 기존 프로젝트 저장·Undo/Redo·복구를 유지한다.
4. 별도 합성 MD 표본과 JSON 표본에 대해 필드 바인딩, diff, 승인 저장, 새 세션 재열기를 각각 검증한다.
5. 기존 자유서술과 관리되지 않는 필드는 보존한다. 외부 수정이 있으면 덮어쓰지 않고 충돌로 남긴다.

<font style="font-weight:bold">합성 표본 성공, 실제 일부 사용 가능, 전체 실자료 인수 완료는 서로 다른 결과다.</font> 첫 인도물이 INFO STANDARD 전체의 확정이나 모든 Paradox 편집기와의 동등성을 의미하지 않는다.

### 1.2 반드시 보존할 기존 설계

- `regionId`, 원본 식별색 `mapHex`, 주제도 표시색을 분리한다. 개명·정치 소속 변경·파일 이동으로 Region ID를 바꾸지 않는다.
- <font style="font-weight:bold">대륙권 → 전략지역권 → 광역권 → 권역권 → 지역권</font> 명칭을 유지한다. 전략지역권의 복수 대륙 관계와 광역권 이하의 단일 대륙 소속을 구분한다.
- 표시용 PNG와 검증된 식별 마스크는 다른 자산이다. 화면에 보이는 색으로 지역을 추측하지 않는다.
- 화면 상태, 선택, 카메라, 편집 초안, 의미 데이터, 저장 상태를 분리한다.
- null/0, 부분 자료/완전 자료, 형식 검증/정본 승인을 구별한다.
- 기존 명령·revision·codec·타일·Worker·자산 세대·복구 경로를 재사용한다. `reference/`와 실제 마스터를 임의 덮어쓰지 않는다.
- 외부 그림 도구와 Obsidian을 폐기하지 않는다. 수정 결과는 사람이 읽고 다른 도구에서도 사용할 수 있어야 한다. [R2–R7]

### 1.3 EXE 완료 후에도 같은 기능을 다시 만들지 않는다

기존 EXE 계획의 PL-C1은 T07 검색, T08 기본 편집, T09 저장을 이미 포함한다. 따라서 V2-00에서 각 기능을 `재사용 / 연결 보완 / 결함 수정 / 신규 필요 / 확인 불가`로 분류한다. 원격 README의 ‘미착수’를 실행 중인 작업의 현재 상태로 복사하지 않는다. [R7]

## 4. 제품 구조 — 재설계보다 연결

### 4.1 계층

```text
지도 / 검색 / 목록 / 표 / Inspector / 오류 목록
                         ↓
       편집 초안 + 명령 + 도메인 검증 + revision
                         ↓
        Field Registry / 엔터티·관계 / 조회 서비스
                  ↙                      ↘
       기존 프로젝트 codec           문서 Binding / Patch
       웹·native 저장 어댑터          관리 필드·출처·충돌
                  ↘                      ↙
           제한된 파일 서비스 / 사용자 승인 저장
                         ↓
        저장 세대·원본 해시·복구·자산·변경 추적
```

기존 폴더·API 명칭은 실제 코드와 일치시키며 위 개념을 그대로 새 디렉터리로 모두 만들 필요는 없다. 렌더링·도메인·저장 각각을 프레임워크 교체 작업으로 확대하지 않는다.

### 4.3 ‘스키마만 추가하면 모든 기능이 생긴다’고 가정하지 않는다

단순 필드는 레지스트리로 폼을 만들 수 있다. 구성비, 기간 중첩, 관계, 네트워크, 경계 분할은 전용 도메인 로직과 위젯이 필요하다. 초기 목표는 <font style="font-weight:bold">이름·인구·메모의 공통 검증과 표시/편집 경로 재사용</font>이다. 마법·정치체제·법령·인물 전체를 지원하는 범용 IDE는 이번 목표가 아니다.

### 4.4 스키마 이관

현재 확인된 원격 core `0.1.0`은 strict이고 facts는 population만 허용한다. 메모나 새 속성을 UI에만 저장하거나 strict 검증을 해제해서 숨기지 않는다. 실제 Cloud 코드가 더 새 버전이면 그 버전을 기준으로 한다. [R4]

새 필드가 필요하면 버전 있는 core 확장 또는 버전 있는 부속 모듈 중 기존 계약에 맞는 방식을 선택한다. 이전 입력 읽기, 이관 전후 의미 비교, 실패 시 원본 보존, 구버전 앱의 새 데이터 처리 정책을 함께 검증한다. 미래 버전/알 수 없는 모듈은 명시적으로 거부하거나 검증 가능한 읽기 전용 범위로 열며, 알 수 없는 내용을 버린 상태로 저장하지 않는다.

### 5.2 Document Binding 계약

최소한 `entityRef`, `documentRef`, `fieldKey`, 문서 형식/locator, read/write 권한, 권위 원본, 기준 내용 해시, 스키마 버전, 관리 구획을 추적한다. Region ID와 문서 ID는 별개일 수 있으며, 한 문서가 여러 지역을 설명하거나 한 지역이 여러 문서에 연결될 수 있다.

단, <font style="font-weight:bold">동일 필드·동일 판본·동일 적용 시점에 서로 다른 두 권위 원본이 생기면 쓰기를 차단</font>한다. 단순한 파일명·행 번호만으로 연결하지 않는다. 개명·이동은 안정 ID와 명시적 재연결로 처리한다.

### 5.3 템플릿 개편과의 연결

확인한 템플릿 V2 작업본은 `90-볼트 운영/00-템플릿/00-yaml 속성탭.md`를 공통 양식 원본으로 지정한다. 이 경로는 확인할 대상이며 현재 Cloud에서 접근 가능하다는 뜻은 아니다. 현행 승인본이 다른 경로로 이동했다면 실제 연결을 갱신한다. [R8]

에디터 저장소에 독립적인 ‘공통 프론트매터 V2 원본’을 새로 만들지 않는다. 기계 판독용 산출물이 필요하면 승인 원본·관련 타입 정의로부터 생성된 아티팩트로 관리하고 source hash/version을 기록한다. 양식 자체만으로 타입·집계법을 알 수 없으면 별도의 승인된 <font style="font-weight:bold">의미 필드 매핑 계약</font>을 두되 전체 YAML 사본을 복제하지 않는다.

`연속성`, `상위개념·하위개념`, `permalink`, 기존 URL용 `aliases`, 정본/작성/검토 상태, 호환 필드는 기존 의미를 보존한다. 문서 별칭을 지역 개체의 이름 별칭과 자동 합치지 않는다. JS/BAT가 관리하는 수정횟수·수정일 등은 담당 체계를 확인하기 전 읽기 전용이다. 새 파일 ID를 자동 발급하거나 기존 ID를 일괄 갈아끼우지 않는다.

### 5.4 안전한 Markdown 편집

첫 버전은 <font style="font-weight:bold">지원이 명시된 frontmatter 키 또는 고유한 관리 구획</font>만 편집한다. 임의 Markdown의 모든 문법을 무손실로 쓸 수 있다고 주장하지 않는다.

- 입력 바이트와 파싱 결과를 함께 보존한다. 중복 키, 모호한 구획, 별칭/앵커 등 미지원 YAML 구문은 오류 또는 읽기 전용으로 남긴다.
- 가능하면 소스 범위 기반 패치 또는 문서 노드 기반 처리를 사용한다. 단순 정규식으로 본문 전체를 교체하지 않는다.
- 본문·관리 밖 필드·주석·개행·BOM·HTML·위키링크·표현 블록을 보존하는 golden fixture를 둔다. 무수정 저장은 no-op이다.
- 노드 기반 YAML 라이브러리도 모든 서식을 완전 보존한다고 가정하지 않는다. 실제 변경 구간을 비교하고, 지원할 수 없는 형식은 사용자가 승인할 사본 출력으로 돌린다. [W2]
- 미리보기에서 DataviewJS·Templater·사용자 스크립트를 실행하지 않는다. 미리보기의 HTML 보안과 원문 바이트 보존은 별도 문제로 처리한다.

JSON도 같은 원칙을 적용한다. 중복 키·안전 범위 밖 숫자·미지원 구조는 조용히 변환하지 않는다. 기존 대형 정수나 고정 소수점 표기 정책을 먼저 정한다. 관리하지 않는 필드의 의미를 삭제하지 않고, 형식 변경이 불가피하면 diff로 드러낸다.

## 6. 편집·파일 기록·충돌·Undo 계약

### 6.1 두 저장 경로

<font style="font-weight:bold">프로젝트 저장:</font> 기존 manifest·codec·자산·세대 복구 서비스를 사용한다.  
<font style="font-weight:bold">문서 반영:</font> Binding으로 연결된 원본 파일의 관리 필드에 한정해 별도로 승인·기록한다.

앱 상태는 적어도 `편집 초안 / 적용된 미저장 변경 / 프로젝트에 저장됨 / 문서 미반영 / 문서 반영됨 / 충돌 / 실패`를 구분한다. 파일 한 개가 저장됐다는 이유로 프로젝트 전체·Drive 업로드·다른 PC 동기화까지 완료 처리하지 않는다.

### 6.2 한 문서 기록 절차

`원본 읽기·해시 → 편집 초안 → 도메인 검증 → 패치 생성 → diff 승인 → 대상 재읽기·기준 비교 → 백업·임시 기록 → 재검증 → 교체 → 결과 재읽기·해시 확인 → 상태 갱신` 순서로 구현한다.

파일 서비스는 앱 내부 요청을 직렬화하고 request ID·project ID·revision·문서 해시·세션 세대를 연결한다. 늦은 저장 완료는 당시 저장한 snapshot만 완료 처리하며 그 후의 편집을 미저장으로 유지한다. 파일 잠금·권한·용량·취소·과거 응답 오류는 기존 EXE 저장 계약을 재사용한다.

### 6.3 동시 편집의 한계와 안전 정책

저장 전 해시 비교와 임시 파일 교체만으로 비협력 외부 프로그램의 동시 기록까지 완전히 방지하는 원자적 compare-and-swap이 되는 것은 아니다. 앱 내부 쓰기 잠금은 Obsidian이나 Drive의 전역 잠금이 아니다.

첫 실사용 버전은 한 파일에 한 편집자 운영을 기본으로 하고, 외부 수정 감지·재읽기·백업·교체 후 검사를 제공한다. 교체 직전/직후 경쟁이 감지되면 각 버전을 보존하고 사용자 조정을 요청한다. 무손실 동시 병합을 보장하지 않는다.

### 6.4 Undo는 외부 이력을 지우지 않는다

메모리 내 명령 취소와 디스크 반영 취소를 구분한다. 파일에 이미 기록한 값을 되돌릴 때도 새로운 역패치의 기준 해시를 검사한다. 그 사이 타인이 수정한 파일을 예전 백업으로 무조건 덮어쓰지 않는다. Undo 이력과 세계관 속 역사 연표는 다른 데이터다.

### 6.5 다중 파일 반영은 후속 단계

첫 묶음의 단위는 한 권위 문서다. 여러 파일에 걸친 일괄 반영은 변경 집합·대상별 기준 해시·journal·복구 상태를 갖춘 후 제공한다. 일반 파일시스템의 여러 독립 경로를 완전 원자적으로 갱신한다고 설명하지 않는다. 일부 반영 후 실패하면 성공/미반영/충돌 목록을 유지한다. 롤백도 최신 해시가 방금 기록한 버전과 일치하는 대상에만 적용한다.

## 7. 분야별 확장 계약

### 7.1 지도 모드·환경·사회·일괄 편집

주제도는 보기만 바꾸며 원본 ID 타일을 수정하지 않는다. 범례에는 단위·시점·집계 범위·미상과 데이터 충족률을 표시한다. 상위 합계는 실제 포함된 고유 최하위 지역 집합으로 계산한다.

문화·종교·언어·종족·민족은 별도 차원이다. 서로 겹칠 수 있는 범주는 ‘상호배타 구성’과 다른 검증 규칙을 가진다. 비율 80%만 알면 나머지는 미상이며 자동 100% 정규화하지 않는다. 개별 차원 비율로 교차 집단 인구를 임의 계산하지 않는다.

일괄 편집은 `유지 / 값 지정 / 명시적으로 비우기`를 구분한다. 혼합값은 빈값이 아니다. 상위 인구를 하위 지역마다 복제하지 않는다. <font style="font-weight:bold">속성 브러시</font>는 이미 존재하는 Region ID 집합을 선택·수정하는 도구이며 경계 픽셀을 칠하는 도구가 아니다. 명령 적용 전 대상 수·영향·전후를 미리 본다.

### 7.2 시간과 국가·영토 관계

현재 문자열 `periodLabel`을 연도 범위로 추측 변환하지 않는다. 세계관 날짜, 현실 편집 시각, 자료 판본/연속성을 분리한다.

- `CalendarDefinition`: 월·일·윤년·시대 순서를 정의하는 사용자 달력 어댑터. 48개월·월 30일·윤년 없음 같은 사용자 정의 달력도 표현할 수 있어야 한다. 실자료 달력은 현행 기준문서와 연결한다.
- `WorldTime`: 원문 표기, 달력·시대 ID, 정확도, 정렬 가능한 값/범위. 모르는 월·일을 1월 1일로 채우지 않는다.
- `TemporalFact`: 특정 시점 관측 또는 유효기간. 종료 미상·현재까지 지속·확정 종료를 구별한다.
- `TerritorialRelation`: 법적 소속, 실제 지배, 점령, 주장, 자치·공동관할 등 승인된 관계 종류와 적용 범위.
- `Edition/Continuity`: A/B 루트나 설정 개정을 세계관 역사 연도와 혼합하지 않는다. 표준의 실제 필드와 매핑한다.

첫 시간 지도는 <font style="font-weight:bold">고정된 지리 경계 위에 시점별 소속·사실이 바뀌는 표현</font>이다. 역사적 지역 분할로 경계 자체가 바뀌는 기능은 V2-11과 연결한 후에만 지원한다. 국가 색을 바꾸는 것과 식별 마스크 변경은 별개다. 공백·중첩을 임의 보간/단일 국가로 축약하지 않는다.

### 7.3 경제·산업·자원·시장

경제 수치는 값뿐 아니라 지표의 의미·단위·기준 연도·명목/실질·기간·범위·집계법이 필요하다. GDP, 세수, 자산, 생활수준, 상대 지수를 한 필드로 섞지 않는다. 자원 존재·매장량·채굴량·재고·수출량을 구별한다.

시장권·산업·상품·생산 시설·교역 관계는 승인된 카탈로그와 ID로 연결한다. 초기에는 입력·조회·필터·집계·지도 표시만 제공한다. 가격 형성, 인구 이동, 생산 증가, 전쟁 피해를 자동 발생시키는 시뮬레이션은 별도 규칙 승인 없이는 구현하지 않는다.

### 7.4 지도 객체·Locator·시설

실체와 표시 위치를 구분한다. 도시는 하나의 엔터티이며, 도시 아이콘 위치·라벨 앵커·항구 위치·도시 상세 지도 링크는 별도 참조가 될 수 있다. 수도는 도시의 종류가 아니라 특정 국가·기간과의 역할 관계일 수 있다.

범용 지도 객체는 안정 ID, 종류, 위치/기하 참조, 관련 지역·시설·문서, 자산, 유효기간을 가진다. NetworkNode는 교통 접속점으로서 객체와 연결할 수 있지만 객체와 항상 1:1이라고 가정하지 않는다. 여러 지역에 걸친 도시도 허용 가능한 관계로 설계하며 기존 5단계에 여섯 번째 층위를 만들지 않는다.

도시 에디터와 은하 에디터의 실제 소스는 수정하지 않는다. `externalRefs` 등 연결 계약만 정의하고, 다른 앱 연동은 해당 앱의 승인·검사 후 구현한다.

### 7.5 기하·곡선·교통

점·폴리라인을 우선 구현하고 필요한 곳에 곡선 제어점을 추가한다. 스냅 후보와 실제 접속 확정을 분리한다. 같은 화면 좌표여도 지상/고가/지하·서로 다른 교통 모드가 자동으로 연결되지 않는다.

강 자연 지물과 항행 수로, 경계선과 도로를 같은 선 자료로 합치지 않는다. 곡선의 렌더링용 단순화는 원본 제어점과 연결 그래프를 변경하지 않는다. 실제 거리·시간은 검증된 좌표/축척/속도와 조건이 있어야 계산한다.

### 7.6 외부 파일 감시

저장 전 내용 비교는 V2-04부터 필수다. 자동 감시는 V2-10에서 추가하되 파일 시스템 이벤트를 변경 사실의 최종 증거로 사용하지 않는다. 재읽기·파싱·해시 검증을 거친다. 감시 기능의 동작은 운영체제·파일시스템별로 다르므로 대상 환경에서 확인한다. [W3]

이벤트 병합·자기 기록 중복 억제·파일 교체/이동·일시적 불완전 파일·삭제·재연결·주기적/수동 재검사를 처리한다. 미저장 폼이 있으면 자동 덮어쓰기하지 않는다. 감시 범위는 승인한 프로젝트/문서 폴더로 제한하고 `.git`, 앱 캐시·복구·빌드·대형 자산은 기본 제외한다. 감시 기능을 Drive 동기화 엔진이라고 부르지 않는다.

### 7.7 경계 편집·분할·병합

V2-11A는 기존 자산을 안전하게 재가져오는 경로이며, V2-11B는 실제 경계 저작이다. B를 구현하려면 경계 정책·ID 계보·재배분 방법 승인이 선행되어야 한다.

새 지역 ID와 이전 지역의 계보, 인구·구성·특성·시설·노선·문서·역사 관계의 영향을 미리 제시한다. 분할 시 인구를 양쪽에 전액 복제하지 않는다. 임의 면적 비례 배분을 정본으로 확정하지 않는다. 이전 마스크/자산 세대를 유지하고 실패·취소 시 기존 의미 데이터와 타일 판정을 복구한다.

## 9. 대형 지도·LOD·응답성 계획

### 9.1 유지할 원칙

EXE라는 확장자만으로 성능 향상을 가정하지 않는다. 현행 렌더러/Worker/타일 구조에서 병목을 측정하고 필요한 부분만 바꾼다. 초기 PixiJS 제안과 달리 확인된 원격은 Canvas 2D + Worker OffscreenCanvas다. 실제 최신 ADR이 다르면 그 근거를 기록한다. [R2–R3]

화면용 LOD, 원본 식별 데이터, 객체 가시성, 데이터 조회 범위는 서로 다르다. 확대율에 따라 아이콘/라벨/선의 표시 밀도를 낮춰도 대상은 목록·검색에서 접근할 수 있어야 한다. 작은 섬이나 경계가 축소되어 보이지 않아도 ID 판정은 검증된 원본을 사용한다.

### 9.3 부하 확장과 통과 기준

작은 기존 합성 표본 → 고정된 중간 합성 표본 → 승인된 실제 일부 → 실제 대상 규모 순으로 확장한다. 4096×2048/10,000개 지역 등 기존 제안 표본도 실제 fixture 존재와 명세를 확인한 후 사용한다. 사용자의 원본 해상도라고 추정하지 않는다.

초기 기준 측정은 3회 개별값·중앙값·범위로 기록한다. p95 등 꼬리 지연은 충분한 반복 표본과 측정 정의를 별도로 마련한다. 기존 승인된 성능 목표가 있으면 보존하고, 없으면 기준 측정 뒤 목표를 제안한다. 목표 미확정을 성능 PASS로 처리하지 않는다.

취소 가능 처리, 화면 밖 객체 제외, 가상 목록, 부분 무효화, 캐시 상한·해제, 중복 타일 요청 합치기, 큰 작업 Worker 분리가 우선 후보다. 성능 때문에 다른 엔진을 선택해야 한다면 별도 ADR·작은 비교 실험·정확성 회귀 후 결정한다.

## 10. 보안·권한·협업 경계

파일 서비스는 선택한 승인 루트/대상만 다룬다. 경로 탈출·심볼릭 링크/Windows 재분석 지점·잘못된 외부 URL·압축 해제 용량·중복 파일 경로를 검사한다. 화면에 임의 fs나 shell을 노출하지 않는다. Electron을 사용하는 경우 context isolation·sandbox·IPC 발신자 검사 등 기존 보안 경계를 유지한다. [W4]

문서·이미지·카탈로그·스키마 안의 코드를 실행하지 않는다. Templater 원문은 보존할 콘텐츠이지 자동 실행 지시가 아니다. 사용자 지도·볼트 원문을 앱 기본 번들에 넣지 않는다.

하나의 브랜치/작업 트리에서 같은 코어 파일을 여러 작업자가 동시에 재설계하지 않는다. 계획·코어 스키마·저장·공통 상태 파일에는 단일 통합 담당자를 둔다. 독립 검사·읽기 전용 조사만 병렬화할 수 있다. 별도 worktree를 쓸 경우 실제 승인된 브랜치와 기준·병합 책임을 기록한다.

문서 변경은 문서 검사부터, 도메인 변경은 단위·codec부터, 파일 서비스 변경은 실제 디스크/장애 검사부터 실행한다. 동일 실패를 조건 변경 없이 반복하거나 정상 로그 전체를 계속 읽지 않는다. 재사용 검사 결과에는 동일 입력·소스·환경 여부를 남긴다.

### 11.2 INFO STANDARD 승격

에디터 구현이 표준의 자동 확정 권한을 갖지 않는다. 표준 후보는 대표 문서 입력에서 발견한 중복·필드 공백·모호한 관계와 근거를 모아 제안한다. 사용자가 승인하면 표준 원본에 반영하고 에디터의 매핑/검증 산출물을 갱신한다.

지역 분야에서 검증된 공통 타입·참조·문서 바인딩을 다른 분야에서 실제로 재사용할 수 있을 때만 공통 모듈 추출을 제안한다. 국가·인물·법령·마법의 고유한 규칙을 지역 스키마에 억지로 넣지 않는다.

## 14. 완료 보고 형식

```text
대상 / 브랜치 / HEAD / 미커밋 변경:
현재 EXE 관문 및 환경:
이번 승인된 실행 범위:
기존 구현에서 재사용한 항목:
계획에 반영한 V2 요구:
이번에 실제 구현한 기능:
실행 검사: 명령, 종료 코드, 입력/소스 해시, 결과 경로:
합성 / 실제 일부 / 전체 실자료 상태:
프로젝트 저장 / 외부 문서 반영 / Windows 실행 상태:
보존 확인: 원본, ID, HEX, 자유서술, 기존 메타, 다른 저장소:
FAIL / NOT_RUN / BLOCKED 및 사유:
실제 산출물 경로 / 패키지·Git·Drive 상태:
다음 한 작업:
```
