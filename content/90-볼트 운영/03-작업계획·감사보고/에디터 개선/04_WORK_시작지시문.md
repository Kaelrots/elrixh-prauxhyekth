# EXE 전환 — WORK 시작·재개 지시문

작성일: 2026-10-02 · 용도: 사용자가 구현 작업을 맡길 때 전달

이 파일을 작성한 것만으로 앱 수정·커밋·푸시·설치·배포가 실행되거나 승인된 것은 아니다. 아래 지시문을 해당 작업공간에 전달할 때 사용자가 정한 실행 권한을 따른다. 로컬 절대경로는 이번 계획에서 확인하지 않았으므로 실제 선택된 작업 폴더와 Git remote를 대조한다. 이미 존재하는 개발 상태를 먼저 확인하며 자료를 다시 만들라고 요구하지 않는다.

실제 구현 권한과 제품별 시작 지시를 함께 받았다면 해당 계획의 다음 단계를 진행하라.

## 3. 행성 지도 편집기 구현 시작

```text
Kaelrots/planet-map-editor의 실제 현재 작업공간에서 행성 평면 지도 편집기의 Windows EXE 전환을 수행하라.

AGENTS·현재 Git/PR·미커밋 변경·현행 개발 규칙을 먼저 확인하라.
이 묶음에서 05_사전조사_근거와미확인사항.md → 00_공통_EXE전환_실행기준.md →
02_행성지도에디터_EXE전환_세부계획서.md를 읽고 03_인수검증_추적표.md의 C/P/R을 사용하라.
원격 참고 SHA 943db96dda3fda0ee9f62e08b7909d89a91bd501는 강제 복원 지점이 아니다.
README의 옛 Draft PR/미병합 문구를 그대로 따라가지 말고 현재 실제 상태를 대조하라.

현재 원격은 T06 합성 선택 단계이고 T07–T09 편집·저장 선행 작업이 남아 있다.
로컬에 후속 구현이 있으면 먼저 확인해 재사용하라. 소스에 없는 기능을 구현 완료로 가정하지 말라.

진행 방식:
1. PL-A/B에서 실제 구조·타일/Worker·Python·기존 검사·원본 보존을 확인한다.
2. PL-C0로 현재 조회 기능을 EXE에 담아 자산/Worker/경로/종료를 확인할 수 있다.
   이것은 SHELL_READY이며 편집·저장 가능한 EXE 완료가 아니다.
3. 기존 의존성 T07 → T08 → T09를 보존한다. 검색·라벨·기본 편집·명령·Undo·저장 계약을 구현한다.
   작은 인구 편집 하나의 성공으로 T08 전체를 완료 처리하거나 T07 의존성을 삭제하지 않는다.
4. PL-C1에서 작은 프로젝트의 편집·실제 저장·새 세션 재열기·필수 자산 전체 왕복을 통과한다.
5. PL-D로 저장/종료 실패와 자산·복구 세대의 일관성을 검사한 뒤 E/F/G로 진행한다.

보존·설계 조건:
- regionId/mapHex/displayColor를 분리하고, 복수 대륙 전략지역권의 전체/부분 관계를 유지한다.
- 실제 표시용 PNG는 presentation으로 남긴다. 검증된 식별 마스크 없이 지역 클릭 판정을 만들지 않는다.
- 현재 strict planet-map-core/0.1.0에 파일 경로·창 상태·미정 기후 등 임의 필드를 주입하지 않는다.
- 현행 population null↔unknown·정수 범위, coverage·importIssues·dataPurpose를 보존한다.
- T08 메모 등 core가 담지 못하는 요구는 승인된 스키마 이관/버전 있는 부속 데이터 계약으로 해결한다.
- .pmap는 과거 제안이다. 실제 확장자·포맷은 T09 계약으로 확정하며 구형 입력 읽기를 지킨다.
- 필수 타일/사전/팔레트/마스크 revision의 호환성과 해시를 모두 검증한다.
- 보존된 복구본이 참조하는 자산을 캐시 청소로 삭제하지 않는다.
- 완전 패키지와 경량 패키지를 구분하고, 경량의 누락 자산은 재연결을 요구한다.
- Python prebuild와 사용자 실행 의존성을 분리한다. 외부 Python/Node 없는 실행을 검사한다.
  사용자 원본 전처리는 검증된 동봉 도구 또는 명시적 지원 경로로 제공하고 지원하지 않는 기능을 숨기지 않는다.
- 기존 웹 실행·T09 어댑터를 유지하고, 렌더러를 과거 계획만 보고 PixiJS라고 가정하지 않는다.

T10 이후 전체 기능·3D 행성·새 투영/지형 엔진·정본 재작성은 별도 승인 없이 추가하지 말라.
실제 전체 마스크가 없으면 BLOCKED_INPUT이다. 합성/실제 일부/전체 실자료 인수를 분리하라.
측정 슬롯 하나를 쓰고, 작은 실행 실패를 대형 부하 반복으로 덮지 말라.

DESKTOP_MIGRATION_STATE.md에 T07/T08/T09 상태와 EXE 완료 등급을 각각 기록하라.
검증은 현재 소스·입력·환경·명령·결과 경로와 연결하고 마지막 빌드/패키지 출처를 대조하라.
실행 위치·사용자 데이터 위치·두 PC 전달 방법을 남기되 미실시 설치·Drive·반환을 완료로 표시하지 말라.
저장소·사용자 원본·정상 배포물은 보존하고, 사용자 권한 범위 밖의 변경·push·공개 배포는 하지 말라.
```

## 4. 중단 후 이어가기

```text
현재 작업공간의 DESKTOP_MIGRATION_STATE.md와 Git 변경 목록부터 읽어라.
상태 파일의 기준 SHA·실제 HEAD·lockfile·실행 환경이 일치하는지 확인하라.
마지막 PASS의 근거 파일과 미완료 조건을 확인한 뒤 바로 다음 작업 하나부터 이어라.
이미 확인한 실패를 같은 조건으로 반복하지 말고 실패 원인/가설/판별 검사를 구별하라.
코드·환경·입력 변경의 영향에 맞춰 재검사하고, 최종 패키지가 마지막 코드에서 나왔는지 다시 연결하라.
권한이나 실제 입력이 없는 항목은 명시적으로 남기되 다른 독립 작업까지 완료했다고 과장하지 말라.
```
